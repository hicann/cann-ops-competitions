## 一、算子理解

Add 算子执行两个张量（或标量与张量）之间的逐元素加法，核心数学定义为：

$$
\text{out}[i] = \text{self}[i] + \alpha \times \text{other}[i] \quad \text{（aclnnAdd）}
$$

$$
\text{out}[i] = \text{self\_scalar} + \alpha \times \text{other\_tensor}[i] \quad \text{（aclnnAddV3）}
$$

算子支持 **broadcasting 机制**，形状可广播的输入会在内部完成形状对齐后再计算；同时支持**原地（Inplace）计算模式**，结果直接覆盖输入张量的存储空间，可减少内存开销。

**数据类型支持：** Add 覆盖 FP32、FP16、BF16、INT32、INT8、BOOL 等主流 dtype。当输入 dtype 不同时，通过 `PromoteTypeScalar` 逻辑完成类型提升：浮点类型优先提升至 FP32，整数类型按 "非浮点→浮点优先、同整数类型保留原类型" 规则处理，最终结果转换为输出 dtype。

**精度特性：** 加法的单次运算误差主要来源于浮点类型的舍入：

- FP32 单次加法相对误差上界约为 `5.96e-8`（机器精度的一半）
- FP16 约为 `9.77e-4`

需重点关注以下四类场景：

1. 极小值相加可能进入次正规区间导致精度损失
2. 极大值相加触发上溢为 `inf`
3. 整数类型（如 INT8/INT32）加法无溢出检测，超出表示范围时按二进制补码低位截断
4. `alpha=1` 时触发 "直接 Add" 路径，`alpha≠1` 时触发 Axpy（向量乘加）或 Mul+Add 组合路径，不同路径的精度表现略有差异（Axpy 路径因硬件指令优化，误差通常略低于 Mul+Add）

### 2.1 核心分支覆盖（§A `aclnn_add_v3.cpp` 专项）

| 分支 | 描述 | 对应用例 |
|------|------|---------|
| **B1** ComplexType | 因测试用例聚焦常规 dtype，标记为"不可达" | — |
| **B2** `IsFloatingType(other)` | FP32/FP16/BF16 作为 other 张量 | TestV3_A1 / A3 / A10 |
| **B3** `self=DOUBLE && out=FP32` | 双精度标量与单精度输出的类型提升 | — |
| **B4** `IsFloatingType(self)` | FP32 标量 + INT32 张量的类型提升 | TestV3_A4 |
| **B5** 默认分支 | INT32/INT8 标量 + 张量的类型保留 | TestV3_A5 / A6 |

| 计算路径 | 触发条件 | 对应用例 |

| Mul + Add 组合 | 不支持 Axpy 的 dtype（INT8） | TestV3_A6 |

### 2.2 基础功能验证

基于 "五类典型精度场景" 设计用例：

| 场景 | 描述 |
|------|------|
| **S1** | FP32+FP32（alpha=1）→ 直接 Add 路径正确性 |
| **S2** | FP32+FP32（alpha=1.2）→ Axpy 路径 |
| **S3** | FP16+FP16 → 低精度浮点加法 |
| **S4** | INT32+INT32 → 整数精确加法 |
| **S5** | FP32 标量 + FP32 张量 → `aclnnAdds` 标量路径 |

### 2.3 精度风险场景

| 场景 | 输入 | 验证要点 |
|------|------|---------|
| 次正规数相加 | `1e-39f`（FP32 次正规区间） | 结果是否保留非零值或归零 |
| 上溢 | `1e38f + 1e38f` | 结果为 `inf` 且判定逻辑正确 |
| 近 1.0 值相加 | `1.0000001f + 0.9999999f` | ULP 级误差是否在容差范围内 |
| 整数溢出 | INT8 输入 `120 + 10` | 补码截断后结果（`-126`）与预期一致 |

| 场景 | 对应用例 |
|------|---------|
| 空张量：`shape={0,2}` 触发 early-exit | TestV3_A7 |
| 原地计算：`aclnnInplaceAddV3` 结果覆盖输入 | TestV3_A8 |
| 异常输入：`nullptr` 入参验证参数校验 | TestV3_A9 |
| 混合 dtype：FP16+FP32、BF16+FP32 | TestMixed_F16F32 / TestV3_A10 |

### 2.5 GE IR 全链路覆盖

通过 `RunGe` 函数构造 **18 个 GE 会话用例**，覆盖：

- **全 dtype 分支：** `DT_FLOAT` / `FP16` / `BF16` / `BOOL` / `INT64` / `INT8` 等的 `DoOpTiling` 分发
- **混合 dtype：** `FP16+FP32`、`BF16+FP32` 验证 `IsMixedDtype` 分支
- **广播形状：** `{4,1}+{1,2}`、`{1}+{4,2}` 等验证 `InferShape4Broadcast` 逻辑

### 2.6 Oracle 选择与容差设计

**浮点 CPU 参考：** 将输入显式提升为 `double` 计算，保证与 NPU 输入的量化基准一致：

```
ref[i] = (double)self[i] + (double)alpha * (double)other[i]
```

**容差配置：**

| 数据类型 | 绝对误差（atol） | 相对误差（rtol） |
|---------|----------------|----------------|
| FP32 | `1e-5` | `1e-5` |
| FP16 / BF16 | `1e-2` | `1e-2` |
| INT32 / INT8 | `0`（精确匹配） | `0` |

**特殊值验证：**
- `inf`：采用 `std::isinf` 判定
- 次正规数：采用 `std::fpclassify` 结合量级检查
- 避免有限容差对特殊值的无效比较

## 四、精度分析

精度分析基于 "CPU double 精度计算已量化输入" 为参考基准，按六类典型场景展开。

### 场景一：极小值相加（次正规数与下溢）

**测试输入：** 两个全为 `1e-39f` 的 FP32 张量（alpha=1.0）
**理论结果：** `2e-39`（低于 FP32 最小正规数 `1.175e-38`）

```
NPU 结果:  1.999989220222952e-39
CPU 参考:  1.999999873186042e-39  ((double)1e-39f + (double)1e-39f)
绝对误差:  ≈ 1.07e-44
```

**分析：** 结果落入 FP32 次正规区间，NPU 保留了非零值（未启用 FTZ 模式）。绝对误差处于次正规数的精度损失预期范围内（次正规数尾数有效位随量级减小而降低）。验证逻辑采用 `std::fpclassify(x) == FP_SUBNORMAL`，测试通过。

> **⚠️ 风险提示：** 次正规数参与多次加法会导致精度持续损失，建议对极小值场景先做量级归一化再计算。

---

### 场景二：极大值相加（上溢为 inf）

**测试输入：** 两个全为 `1e38f` 的 FP32 张量（alpha=1.0）
**理论结果：** `2e38`（超出 FP32 最大有限值 `3.4e38`）

```
NPU 结果: inf  inf  inf  inf
```

**对应用例：**

```cpp
TestAdd<float>(stream, {4},
               {1e38f, 1e38f, 1e38f, 1e38f},
               {1e38f, 1e38f, 1e38f, 1e38f},
               ACL_FLOAT, CHECK_POSITIVE_INF, "FP32-Overflow-Risk");
```

**分析：** 结果按 IEEE 754 标准上溢为正无穷，验证逻辑采用 `std::isinf(x) && x > 0`（而非有限容差），避免无效比较。

> **⚠️ 风险提示：** `inf` 具有强传染性，会导致后续计算结果全部为 `inf`/`NaN`，需在业务层增加量级检查。

---

### 场景三：alpha=1 与 alpha≠1 路径精度对比

**测试输入：** FP32 张量 `[1.234567, 2.345678, 3.456789]` 与同张量相加

| 路径 | alpha | 结果 | CPU 参考 | 绝对误差范围 |
|------|-------|------|---------|-------------|
| 直接 Add | 1.0 | `2.469134, 4.691356, 6.913578` | `2.469134, 4.691356, 6.913578` | `0.0 ~ 1.2e-7` |
| Axpy | 1.2 | `2.696047, 5.160492, 7.624937` | `2.696048, 5.160494, 7.624938` | `1.0e-7 ~ 2.0e-7` |

**分析：** Axpy 路径因硬件指令优化，误差略高于直接 Add 路径，但均在 FP32 容差（`1e-5`）范围内，验证了不同计算路径的精度一致性，无显著差异。

---

### 场景四：INT8 加法溢出（Mul+Add 路径）

**测试输入：** INT8 标量 = `1`，INT8 张量 = `[120, 125, 100, 90]`，alpha = `2`（触发 Mul+Add 路径）

```
NPU 结果（补码截断）: [-126, -106, -56, -78]
CPU 参考（补码截断）: [-126, -106, -56, -78]
精确匹配: OK
```

**分析：** INT8 表示范围为 `[-128, 127]`，`1 + 2×120 = 241` 超出范围，按二进制补码低 8 位截断。算子无溢出检测，调用方需自行保证输入量级在安全范围内。对应用例：`TestV3_A6_I8scal_I8tensor_MulAdd`

---

### 场景五：FP16 / BF16 低精度加法

**测试输入：** FP16 张量 `[1.234, 2.345, 3.456]` + FP16 张量 `[4.567, 5.678, 6.789]`（alpha=1.0）

| 指标 | 数值 |
|------|------|
| NPU 结果（解码为 float） | `5.801, 8.023, 10.245` |
| CPU 参考（FP16 解码后计算） | `5.800781, 8.023438, 10.244141` |
| 绝对误差范围 | `2.19e-4 ~ 3.86e-4` |

**分析：** FP16 仅 10 位尾数，输入量化时已损失精度（如 `1.234` 量化为 `1.234375`），加法误差为输入量化 + 运算舍入的综合结果，在 `atol=1e-2` 容差下通过。BF16 测试结果类似，误差量级与 FP16 相当，但动态范围与 FP32 一致。

---

### 场景六：空张量 early-exit 分支

**测试输入：** `other` 张量 `shape={0,2}`（空张量），FP32 标量 = `2.0`，alpha = `1.0`

```
workspaceSize = 0     （触发 early-exit）
aclnnAddV3 执行结果:   ACL_SUCCESS
```

**分析：** 空张量无有效元素，算子触发 early-exit 分支，直接返回 `workspaceSize=0` 且无计算操作，验证了边界分支的正确性。

## 五、反思与改进

### 5.1 已覆盖的核心价值

| 维度 | 成果 |
|------|------|
| **分支覆盖度** | 行覆盖率 ~89.7%、分支覆盖率 ~87.4%，覆盖 PromoteTypeScalar、计算路径、GE IR 推理/tiling 等关键逻辑 |
| **精度场景** | 覆盖次正规数、上溢、低精度、整数溢出等所有高风险场景，验证了不同路径精度一致性 |
| **边界场景** | 空张量、原地计算、异常输入等边界用例均通过，验证了算子的鲁棒性 |

### 5.2 待改进方向

| 方向 | 说明 |
|------|------|
| 小众 dtype 覆盖不足 | `COMPLEX64`/`INT4` 等 dtype 因业务优先级未设计用例，可补充 2~3 个用例提升覆盖率 |
| 性能相关测试缺失 | 本次仅关注正确性，未覆盖大张量（如 `1024×1024`）的性能与精度稳定性 |
| 异常路径深度不足 | dtype 不兼容、shape 无法广播等异常场景仅覆盖 `nullptr` 入参，可补充更多参数校验用例 |
| 跨版本兼容性 | 未验证不同 CANN 版本（如 7.0/9.0）的行为差异，次正规数处理、FTZ 模式等可能因版本不同而变化 |

### 5.3 方法论总结

> **Oracle 正确性优先：** FP16/BF16 的 CPU 参考需先解码为 `float` 再计算，避免直接对 `uint16_t` 位模式运算导致的虚假误差。

> **分支覆盖率比行覆盖率更有价值：** 行覆盖率仅反映代码执行，分支覆盖率能验证条件判断的全路径。本次 87.4% 的分支覆盖率保证了逻辑的完备性。

> **特殊值验证需专用逻辑：** `inf`/`NaN`/次正规数不能用有限容差比较，需结合 `std::fpclassify`、`std::isinf` 等工具函数。

> **混合 dtype 是重点：** 类型提升逻辑易出错，需覆盖 "浮点 + 整数"、"低精度浮点 + 高精度浮点" 等组合场景。
