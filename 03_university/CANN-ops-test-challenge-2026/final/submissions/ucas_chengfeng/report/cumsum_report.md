# 算子测试报告

------

## 一、算子理解

**数学定义**  
Cumsum（累加和）算子沿给定维度 `dim` 计算张量的前缀和。对于一维序列 \( x_0, x_1, ..., x_{n-1} \)，输出 \( y_i = \sum_{j=0}^{i} x_j \)。  
算子包含两个版本：  
- `aclnnCumsum`（V1）：仅支持标准前缀和模式。  
- `aclnnCumsumV2`（V2）：额外支持 `exclusive`（是否排除当前元素）和 `reverse`（从尾部向头部累加）标志。

**输入输出规格**  
- **输入**：`self`（张量），`dim`（整数，指定累加轴）。V2 还接受 `exclusive`（bool）和 `reverse`（bool）。  
- **输出**：与输入 `self` 形状相同的张量。  
- **数据类型支持**：FLOAT32、FLOAT16、BF16、INT32、INT64、INT8、UINT8、DOUBLE、COMPLEX64、COMPLEX128。BOOL 类型不被支持。  
- **Broadcasting**：Cumsum 不支持 broadcasting，输入与输出形状必须严格一致。  
- **定义域约束**：`dim` 必须在 `[-rank, rank-1]` 范围内；空张量（含 0 维度）返回空张量；0 维标量返回自身。

**值得关注的数学性质**  
- **边界行为**：`exclusive=True` 时首个输出元素为 0（或加法单位元），`reverse=True` 时累加方向反转。  
- **单调性**：对于全非负序列，前缀和单调不降；全非正则单调不增。  
- **数值稳定性**：浮点累加可能产生舍入误差，尤其当数值跨度极大（如大数吃小数）或重复分数累加（如 0.1*1000）时。  
- **整数溢出**：累加和可能超出整数类型的表示范围（本测试未专门构造溢出场景，但属于潜在风险）。

## 二、测试策略与用例设计

**总体思路**  
采用端到端黑盒测试，对比 NPU 输出与 CPU 高精度（`double`）参考实现。根据数据类型采用绝对/相对容差或精确匹配。  
测试覆盖算子功能正确性、异常处理、数据类型兼容性以及边界条件。

**参照实现（Oracle）**  
CPU 端使用 `double` 精度实现前缀和逻辑（针对 V1/V2 的不同标志位），得到期望结果。对于整数类型，保证精确匹配；对于浮点类型，设定绝对/相对容差（FLOAT16、BF16 允许 \(10^{-2}\) 至 \(10^{-3}\) 级误差，FLOAT32 允许 \(10^{-5}\)，DOUBLE 允许 \(10^{-10}\)）。

**用例分类与分布**  
| 类别 | 数量 | 主要覆盖点 |
|------|------|-------------|
| `aclnnCumsum`（V1）基本功能 | 22 | 1D~3D、各种 dtype、空/0维张量、长序列、大小数混合、重复小数 |
| `aclnnCumsum`（V1）错误处理 | 6 | nullptr、dim 超界、形状不匹配、dtype 不一致、不支持 BOOL |
| `aclnnCumsumV2`（V2）基本功能 | 8 | exclusive/reverse 四种组合、负 dim、0 维、空张量 |
| `aclnnCumsumV2` 数据类型覆盖 | 12 | FLOAT16/BF16/INT8/INT16/UINT8/COMPLEX64/COMPLEX128 等 |
| `aclnnCumsumV2` 错误处理 | 8 | nullptr、dim 超界（正负）、形状/类型不匹配、9D 超维、BOOL |
| **总计** | **56** | 所有测试用例均已在 NPU（Ascend 910B）上执行 |


**精度阈值设定依据**  
- 整数类型：`rtol=0, atol=0`。  
- 浮点类型：`rtol=1e-5, atol=1e-5` for FLOAT32；`rtol=1e-2, atol=1e-2` for FLOAT16/BF16。  
- 复数类型：实部与虚部分别按同等浮点阈值判定。

## 四、精度分析

**误差度量方式**  
使用相对误差 `|a-b| / max(1, |b|)` 与绝对误差 `|a-b|`，取两者较小者作为判断依据。对于整数和复数累加，采用精确匹配。

**CPU 参考实现依据**  
采用 `double` 精度累加，避免浮点误差对“Ground Truth”的污染。对于低精度输入（FLOAT16/BF16），参考值仍基于 `double` 计算，若 NPU 输出与 `double` 参考相差超过给定阈值则视为精度不达标。


## 五、反思与改进

**测试盲区与局限性**  
1. **未测试整数溢出**：未构造使 INT8/UINT8/INT16 累加溢出的用例，虽然规范未强制要求检出溢出，但作为完整性测试可补充。  
2. **高维张量**：当前最大测试维度为 3D（以及一个 9D 的错误触发用例），未验证 4D~8D 正常功能。  
3. **随机/模糊测试**：所有输入均为人工构造或简单规律序列，未使用模糊测试（Fuzzing）发现隐蔽的边界崩溃。  
4. **性能与内存占用**：未测试极长序列（>10⁶ 元素）时的内存分配与 kernel 调度稳定性。  
5. **混合 dtype 的更多组合**：仅测试了 BF16→FLOAT32 输出，未测试 INT8→FLOAT16 等。

**若有更多时间会如何扩展**  
- 实现自动化随机测试生成器，在不同形状（含非对齐维度）、随机数值上对比 CPU/NPU 结果。  
- 增加溢出检测测试（如 INT8 累加至 200 观察是否 wraparound 或报错）。  
- 对特殊浮点值（INF、NaN、-0.0）进行测试，当前未覆盖。  
- 添加性能基准测试，确保优化未引入性能退化。

**方法论经验教训**  
- **Oracle 的选择至关重要**：使用 `double` 作为参考有效避免了“相同浮点误差”导致的误判。  
- **精度阈值需结合 dtype 动态调整**：FLOAT16 和 BF16 必须放宽阈值，否则误报为错误。  
- **测试异常路径往往比功能路径更容易遗漏**：例如 nullptr 和 dim 超界，本测试已覆盖，但其他算子开发时建议优先设计此类用例。  
- **代码覆盖率是必要但不充分指标**：分支覆盖率即使达到 100% 也无法保证没有数值精度问题或并发 bug。

**对 CANN 测试工具链的建议**  
1. 提供更细粒度的分支覆盖率可视化（如哪些分支因 dtype 组合未命中）。  
2. 内置随机张量生成器与差分测试框架，减少手工构造用例的负担。  
3. 对于浮点累加类算子，建议文档中明确标注不同 dtype 下可预期的最大误差上界。
