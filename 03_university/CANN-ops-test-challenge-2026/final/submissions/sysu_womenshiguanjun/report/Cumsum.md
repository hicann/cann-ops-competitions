> 测试环境：Ascend 910B，CANN 工具链版本 8.0.RC1

## 一、算子理解

Cumsum 定义为前缀和：`y[i] = sum_{j=0..i}(x[j])`，支持沿给定维度 `dim` 累加。该算子提供两类 API：

- `aclnnCumsum(self, dim, dtype, out)`：标准累加
- `aclnnCumsumV2(self, dim, dtype, exclusive, reverse, out)`：扩展参数

其中 `exclusive=true` 表示当前位置不包含当前元素，`reverse=true` 表示反向累加。该算子的核心数值特性是误差随累加长度增长（尤其浮点类型）。

**支持 dtype**：FP32、INT32、INT64、INT8、UINT8

**数值特性**：浮点类型存在误差累积，整数类型精确计算但可能溢出。

## 四、精度分析

### 场景一：基础功能验证（dim0 与 dim1）

**测试输入**：FP32 二维张量 `{1, 2, 3, 4}`，形状 `{2, 2}`

**dim=0 测试**（沿第一维累加）：

```
输入：[[1, 2], [3, 4]]
期望输出：[[1, 2], [4, 6]]
```

**dim=1 测试**（沿第二维累加）：

```
输入：[[1, 2], [3, 4]]
期望输出：[[1, 3], [3, 7]]
```

**分析**：基础功能验证通过，dim0 和 dim1 的累加结果与 CPU 参考完全一致。

### 场景二：3D 张量测试

**测试输入**：FP32 三维张量，形状 `{2, 3, 4}`，24 个元素

**测试用例**：

- `Cumsum-fp32-3d-dim0`：沿第一维累加
- `Cumsum-fp32-3d-dim2`：沿第三维累加
- `Cumsum-fp32-3d-negdim`：负向索引 dim=-1

**分析**：3D 张量测试触达更多代码路径，验证了高维张量的累加逻辑正确性。

### 场景三：长序列误差累积

**测试输入**：FP32 一维张量，4096 个全 1.0 元素

**数学期望**：输出应为 `[1, 2, 3, ..., 4096]`

**分析**：浮点数累加的误差随长度增长，容差设为 `atol=2e-2, rtol=1e-5`。

### 场景四：大小数混合（精度吞没）

**测试输入**：FP32 一维张量，交替 `1e8` 和 `1e-6`

**分析**：小数 `1e-6` 可能被大数 `1e8` 吞没，容差设为 `atol=2e-2, rtol=1e-5`。

### 场景五：大张量测试（新增）

**测试用例**：

- `Cumsum-int32-large-right-axis`：INT32，形状 `{64, 64, 16}`，元素数 65536，dim=1
- `Cumsum-int32-large-left-axis`：INT32，形状 `{2048, 17}`，元素数 34816，dim=1
- `Cumsum-fp32-large-last-axis`：FP32，形状 `{12800, 512}`，元素数 6553600，dim=1

**分析目的**：

- 验证大规模数据的累加正确性

**预期结果**：整数类型精确匹配，FP32 类型允许一定的累积误差。

### 场景六：V2 参数组合测试

**测试用例**：

- `CumsumV2-fp32-exclusive`：exclusive=true
- `CumsumV2-fp32-reverse`：reverse=true

**分析**：V2 API 的参数组合验证了扩展功能的正确性。

### 场景七：整数类型测试

### 场景八：异常路径测试（扩展）

**测试用例**：

- `Cumsum-invalid-dim`：非法 dim（shape.size() + 3）
- `CumsumV2-invalid-dim`：V2 非法 dim

**shape 不匹配设计**：self 形状 `{2, 2}`，out 形状 `{4}`，输出张量形状与输入不一致，触发 shape 校验分支。

**超维度设计**：9D 张量 `{1, 1, 1, 1, 1, 1, 1, 1, 1}`，触发最大维度限制检查分支。
