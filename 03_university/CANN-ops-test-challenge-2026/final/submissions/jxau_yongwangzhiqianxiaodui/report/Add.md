# 算子测试报告

## 一、算子理解

**数学定义**  
Add 算子执行逐元素加法：  
\[
out = self + \alpha \times other
\]
\(\alpha\) 为标量缩放因子（`aclScalar*` 类型），默认可为 1。支持广播（broadcasting），当两个输入 shape 不一致时，按广播规则对齐后计算。

**输入输出规格**  
- `self`、`other`：`aclTensor*` 类型，支持 ND 格式，dtype 需满足支持列表。  
- `alpha`：`aclScalar*` 类型，数据类型需可转换为 promote type。  
- `out`：`aclTensor*` 类型，shape 应为 `self` 与 `other` 广播后的 shape。

**支持的 dtype（Ascend 910_93）**  
依据 `aclnn_add.cpp` 中的 `ASCEND910_DTYPE_SUPPORT_LIST`：  
`DT_FLOAT`, `DT_FLOAT16`, `DT_INT32`, `DT_INT64`, `DT_INT16`, `DT_INT8`, `DT_UINT8`, `DT_DOUBLE`, `DT_BOOL`, `DT_COMPLEX64`, `DT_COMPLEX128`。  
混合类型（如 `FLOAT16 + FLOAT`）也在支持之列，但需依赖具体硬件路径。

**广播规则**  
遵循 numpy 风格广播：从尾部维度开始对齐，维度为 1 的轴会被复制以匹配另一输入。支持 0 维（标量）到 8 维的张量。

**值得关注的数学性质**  
- 加法满足交换律、结合律（浮点下可能因舍入顺序不严格成立）。  
- \(\alpha = 0\) 时输出等于 `self`；\(\alpha = 1\) 时为标准加法。  
- 边界行为：极大值相加可能上溢为 `inf`，极小值相加可能下溢为 0 或次正规数；整数加法可能回绕（wrap-around）。  
- NaN/Inf 具有传播性：任一输入为 NaN 则结果为 NaN；`inf + (-inf)` 结果为 NaN。

## 二、测试策略与用例设计

**参照实现（Oracle）**  
CPU 端使用 `double` 精度计算期望值：  
```cpp
double expected = (double)x1[i] + alpha * (double)x2[i];
```
对于整数类型，使用对应整型直接计算（注意溢出行为由实现定义，本次测试仅验证一致性）。

**精度阈值**  
- FLOAT32：`atol=1e-6, rtol=1e-6`  
- FLOAT16：`atol=1e-3, rtol=1e-3`（但因硬件问题未完整测试）  
- BF16：`atol=1e-2, rtol=1e-2`（硬件不支持，测试跳过）  
- 整数类型：精确匹配（`==`）

**用例设计分类**  
1. **合法数据类型**：覆盖 FLOAT32, INT32, INT8, UINT8, INT64, DOUBLE, BOOL 等（基于硬件支持列表）。  
2. **Alpha 参数**：测试 \(\alpha = 1.000001\)（绕过已知 alpha=1 分支 bug）、\(\alpha = -2.5\)、\(\alpha = 0\)。  
3. **Shape 广播**：2D+1D 尾部广播、高维广播 `[2,1,4] + [2,3,4]`。  
4. **数值边界**：下溢（`1e-20 + 1e-20`）、上溢（`1e20 + 1e20`）、NaN 传播、整数溢出（`INT32_MAX + 1`）。  
5. **API 变体**：`aclnnAdd`, `aclnnAdds`, `aclnnInplaceAdd`, `aclnnAddV3`, `aclnnInplaceAddV3`。  
6. **异常输入**：`nullptr` 输入、不支持的数据类型（如 `UINT32`）。

## 四、精度分析

**误差度量**  
采用组合容差：  
\[
|actual - expected| \le atol + rtol \times |expected|
\]
CPU 参考使用 `double`，输入以 `float` 量化后计算。

**典型精度场景**

### 1. 下溢（极小值相加）
- **输入**：`1e-20f + 1e-20f`，`α=1.000001`  
- **NPU 输出**：`2.000000905883325e-20`  
- **CPU 参考**：`2.000000890205331e-20`  
- **绝对误差**：`~1.56e-29`，**相对误差**：`~7.8e-10`  
- **分析**：乘积进入次正规区间，精度仍保持在合理范围，未发生 FTZ（flush-to-zero）。硬件支持次正规数。

### 2. 上溢
- **输入**：`1e20f + 1e20f`，`α=1.000001`  
- **NPU 输出**：`2.000001095612917e20`  
- **CPU 参考**：`2.000001e20`（理论值）  
- **分析**：结果未达到 `inf`（`FLT_MAX ≈ 3.4e38`），仍在可表示范围内，因此上溢未发生。该测试实际验证了大数加法精度，误差在预期内（相对误差 ~5e-7）。测试中未覆盖真正的上溢（`FLT_MAX + FLT_MAX`），因硬件可能饱和为 `inf`，但本环境输入较小。

### 3. 大数+小数（精度丢失）
- **输入**：`1e10 + 1e-5`  
- **NPU 输出**：`10000000000.000000`（实际值如预期）  
- **CPU 参考**：`10000000000.000010`  
- **误差**：`1.0e-5`（小数被大数吞没）  
- **分析**：Float32 有效数字约 7 位，`1e10` 的 ULP 约为 `1e3`，`1e-5` 在加法中被舍去。此行为符合 IEEE 754 规范。

### 4. 十进制小数精度
- **输入**：`0.1f + 0.2f`  
- **NPU 输出**：`0.30000001192092896`  
- **CPU 参考**：`0.30000000000000004`  
- **绝对误差**：`~1.19e-8`  
- **分析**：`0.1` 和 `0.2` 在二进制浮点中无法精确表示，误差源于输入量化及加法舍入。误差量级符合 Float32 精度（约 `2e-8`）。

### 5. Alpha 非1分支
- **输入**：`self=[1,2,3]`，`other=[1,1,1]`，`α=1.000001`  
- **NPU 输出**：`[2.000001, 3.000001, 4.000001]`  
- **CPU 参考**：相同  
- **分析**：绕过 alpha=1 分支后，算子计算正确，说明非1路径正常。alpha=1 分支存在 bug 导致输出全 0，已在报告中说明，建议厂商修复。

## 五、反思与改进

**测试盲区与局限性**  
- 未测试非连续内存张量（`strides` 不连续）的性能和正确性。  
- 高维广播（dim > 4）未覆盖。  
- 整数溢出行为（如 `INT32_MAX + 1`）未全面验证（依赖于实现定义）。  
- 未测试 `aclnnAdds` 与 `aclnnInplaceAdds` 的多种标量类型组合。  
- V3 API 的 `AxpyV2` 路径未触发（因 `promoteType` 未满足条件）。

**扩展计划**  
- 若更多时间，将增加：  
  - 非连续张量测试（通过 `aclCreateTensor` 自定义 `strides`）。  
  - 随机数据模糊测试（fuzzing）以发现潜在边界错误。  
  - 压力测试（大张量，如 `[1000,1000,1000]`）评估性能与稳定性。  
  - 异常输入（不合法的 shape 广播）全覆盖。

**经验教训**  
- **Alpha 参数陷阱**：在 Ascend 910 环境下 `alpha=1` 分支存在 bug，测试中需用 `alpha=1.000001` 绕过，这提示我们应针对不同平台/版本测试所有 alpha 取值。  
- **数据类型支持差异**：`BF16`、`FLOAT16` 在部分硬件上或数据转换存在问题，导致输出全 0，测试前应确认硬件支持列表。  
- **CPU 参考实现**：必须使用 `double` 且输入从 `float` 提升，避免因输入量化不一致导致误判。  
- **覆盖率驱动**：使用 `gcov` 能精准发现未覆盖分支，指导补充测试用例（如 V3 API、混合类型）。

**对 CANN 测试工具链的建议**  
- 提供更稳定的 `alpha=1` 路径实现，避免特定平台上的静默失败。  
- 增加调试日志宏，便于定位算子内部执行路径（例如打印选择的分支）。  
- 完善文档，明确各 SOC 版本支持的数据类型列表及已知限制。  
- 建议在 `aclnn_add_v3` 等 API 中提供更详细的错误码，区分参数错误与内部执行失败。
