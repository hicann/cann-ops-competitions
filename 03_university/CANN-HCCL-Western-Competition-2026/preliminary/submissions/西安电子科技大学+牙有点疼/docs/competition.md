AllReduce 集合通信算子赛题说明

## 一、赛题描述

实现集合通信算子 **AllReduce** 的操作接口：将通信域内所有节点的输入数据执行相加或其他归约操作，再将归约结果发送到所有节点的输出 Buffer。归约操作类型由 `op` 参数指定。

### 1.1 AllReduce 数据流示意

#### 输入数据

AllReduce 操作由 4 个 Rank 共同参与：

| Rank | 本地输入 |
|---|---|
| rank 0 | `in0` |
| rank 1 | `in1` |
| rank 2 | `in0` |
| rank 3 | `in1` |

#### AllReduce 操作

所有 Rank 的本地输入共同参与归约计算：

```text
in0 + in1 + in0 + in1 = 2 × in0 + 2 × in1
```

归约完成后，每个 Rank 的输出 Buffer 均得到相同结果：

| Rank | 输出结果 |
|---|---|
| rank 0 | `2 × in0 + 2 × in1` |
| rank 1 | `2 × in0 + 2 × in1` |
| rank 2 | `2 × in0 + 2 × in1` |
| rank 3 | `2 × in0 + 2 × in1` |

### 1.2 评测环境与网络拓扑

评测环境为 **2 × 8 卡昇腾 Ascend 950 仿真环境**，由 2 个 Server 组成，每个 Server 包含 8 个 NPU。

- Server 内部：8 个 NPU 之间采用 Full-Mesh 全互联，横向为 Mesh 互联。
- Server 之间：通过 Clos 网络互通，纵向为 Clos 组网。
- 带宽特征：每个 NPU 连接 Clos 网络的带宽约为 Server 内单条直连链路带宽的 8 倍。

## 二、核心定义与约束

### 2.1 函数原型

```cpp
HcclResult HcclAllReduce(
    void *sendBuf,
    void *recvBuf,
    uint64_t count,
    HcclDataType dataType,
    HcclReduceOp op,
    HcclComm comm,
    aclrtStream stream
);
```

### 2.2 参数说明

| 参数名 | 输入/输出 | 描述 |
|---|---|---|
| `sendBuf` | 输入 | 源数据 Buffer 地址。 |
| `recvBuf` | 输出 | 目的数据 Buffer 地址，集合通信结果输出至此 Buffer。 |
| `count` | 输入 | 参与 AllReduce 操作的数据个数。例如，仅有一个 `float32` 数据参与时，`count = 1`。 |
| `dataType` | 输入 | AllReduce 操作的数据类型，类型为 `HcclDataType`。 |
| `op` | 输入 | Reduce 操作类型，如 `sum`、`prod`、`max`、`min`。 |
| `comm` | 输入 | 集合通信操作所在的通信域。 |
| `stream` | 输入 | 本 Rank 使用的 Stream。 |

接口调用成功时返回 `HCCL_SUCCESS`，失败时返回其他错误码。

### 2.3 算子约束

- 所有 Rank 的 `count`、`dataType` 和 `op` 必须相同。
- 每个 Rank 仅有一个输入。
- 算子的输入、输出地址（`sendBuf` 与 `recvBuf`）须根据数据类型满足相应的地址对齐要求。
- `float32` 数据须按 **4 Byte** 地址对齐。

### 2.4 规则要求

- 限定使用 **AICPU + TS 通信引擎**。
- 算子实现须满足确定性要求：在相同输入下，尤其是浮点数输入时，多次通信计算必须得到相同的输出结果。

## 四、技术点补充说明

### 4.1 两层网络拓扑

赛题采用两层拓扑，允许使用 Layer 0 和 Layer 1 的链路。

通过 `HcclRankGraphGetLayers` 接口可查询当前通信域的 `netLayers`，其中包含 0 和 1 两层。可根据算法需要选择对应层级的链路。

### 4.2 规约类算子的确定性

AllReduce、ReduceScatter 等规约类算子可采用以下方式保证确定性：

#### 方案一：使用 CCL Buffer 中转

先将不同来源的数据存放到 CCL Buffer 的不同地址段，再按照固定顺序对这些数据执行本地规约操作。

#### 方案二：通过算法设计保证确定性

- **Halving-Doubling、Ring 算法**：每一步只接收一个对端发送的数据，天然满足确定性要求。
- **Mesh 算法**：将数据进一步切片；同一步内，不同对端分别针对不同内存段执行读、写或规约操作。

### 4.3 小数据量场景的性能优化

小数据量场景下，单个通信任务的执行时间较短。如果通信任务数量过多，任务下发时延可能占据较大比例，从而影响整体性能。因此，算法设计时应重点控制任务数量及下发开销。
