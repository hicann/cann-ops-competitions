# AllGather CCU 优化方案说明
本项目基于 Ascend CCU 硬件实现高性能 AllGather 集合通信算子，适配多 Rank 分布式训练聚合通信场景。
本文件为项目综合说明，详细代码执行流程、内核思路、分片与中继算法逻辑，详见项目内部算法思路文档，本文不再重复赘述。

## 一、方案概述
针对多 Die 拓扑链路不对称、大尺寸数据传输吞吐低、硬件资源利用率不足的问题，本实现基于 HCCL 框架，拆分 Host 调度层与 CCU Kernel 硬件传输层，实现双策略自适应通信机制。通过多 Die 并行、分片流水、中继转发、资源复用等优化，充分发挥 CCU 远端写硬件能力，提升多 Rank 场景下 AllGather 通信性能。

## 二、核心优化与创新点
1. **双策略自适应调度**
   根据 Rank 数量、拓扑分组、数据大小自动切换直传模式与中继流水模式，兼顾小数据低延迟、大数据高吞吐的场景需求。

2. **分片增量执行优化**
   首个分片完成地址与内存 Token 同步，后续分片复用同步资源，避免重复链路协商开销，提升迭代调用性能。

3. **多 Die 并行加速**
   按硬件 Die 拓扑分组，绑定独立线程与内核任务，实现多 Die 跨 rank 传输与本地拷贝并行执行，提升硬件利用率。

4. **中继流水链路优化**
   针对 12/16 Rank 非对称拓扑，将数据拆分为直传、中继两路流量并行流水，缓解跨 Die 链路带宽瓶颈，大幅提升大数据传输效率。

5. **细粒度本地拷贝优化**
   采用 4KiB 内存切片 + 多缓冲并行拷贝，解决大块内存串行拷贝耗时问题，降低本地数据复制开销。

6. **全局资源缓存复用**
   链路 Channel、内核句柄、线程资源一次初始化、全局缓存，消除重复创建资源的启动开销。

## 三、方案优势
- **全覆盖场景**：支持最大 16 Rank，适配 0~1GiB 不同数据量级，兼容对称/非对称硬件拓扑。
- **高性能低开销**：硬件并行加速、流水化执行、资源复用，有效降低通信时延。
- **高稳定性**：分片分批执行、全局事件同步、异常场景自动降级直传，保证数据聚合准确无误。

## 四、运行说明
项目编译、环境配置、运行方式详见项目原有 README 文档，本优化方案基于原生 HCCL 框架开发，无额外依赖，可直接编译部署运行。

## 五、适配约束
- 当前支持 FP32 数据类型，最大支持 16 Rank 集群通信。
- 中继流水优化仅在 12/16 Rank、单卡数据量 8MiB~1GiB 场景自动启用，其余场景默认直传策略。
