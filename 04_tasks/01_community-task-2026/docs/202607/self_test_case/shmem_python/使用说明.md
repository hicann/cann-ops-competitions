# 测试用例使用说明

本目录归档 **SHMEM Python 接口开发任务** 的验收测试用例与执行说明，风格对齐同月 `ops-collections/`。

覆盖范围仅限任务书中 **尚未实现、需补齐** 的 Host Python 绑定与 `shmem.core` 封装（已实现接口不在此重复验收）。


## 集成

任选其一：

### 方式 A：独立运行（推荐归档验收）

1. 准备已构建的 `shmem*.whl`（在 [cann/shmem](https://gitcode.com/cann/shmem) 根目录执行 `pip wheel .`）。
2. 进入本目录执行：

```bash
cd case_M7/shmem-python-api
bash tests/run.sh --shmem-root /path/to/shmem
```

### 方式 B：对接 shmem 工程内 python_extension

将 `tests/common`、`tests/functional`、`tests/performance` 复制到：

```
cann/shmem/examples/python_extension/community/
```

并在该处调用 `bash run.sh`（或把用例路径挂到现有 `examples/python_extension/run.sh`）。公共 fixture 与现有 `test/init_test.py` 风格一致，可并存。

## 编译 & 运行

本任务为 **Python 绑定验收**，无需在本仓编译 C++。只需安装 SHMEM Python 包后用 `torchrun` 跑测。

```bash
# 全量（功能 + 性能），默认 2 卡
bash tests/run.sh --shmem-root /path/to/shmem

# 仅功能 / 仅性能
bash tests/run.sh --suite functional
bash tests/run.sh --suite performance

# 单测（文件名去掉 .py）
bash tests/run.sh --test-name test_barrier_sync

# 已安装 shmem 时跳过 pip install
bash tests/run.sh --skip-install --test-name test_heap_mem_type

# 指定卡数
bash tests/run.sh --nproc 4 --suite functional
```

等价手写：

```bash
torchrun --nproc-per-node 2 tests/functional/test_barrier_sync.py
```

**关于 `[SKIP]`：** 若某 API 尚未在 `shmem._pyshmem` / `shmem.core` 中绑定，用例会打印 `[SKIP] ... not bound yet` 并以 exit 0 退出，便于任务实现前先归档脚本；实现完成后应全部变为 PASS，不再 SKIP。

## 测试场景

| 用例 | 场景 |
| --- | --- |
| set_attr_uniqueid_args | UID 广播后写 attr；校验 my_rank / n_ranks |
| instance_ctx_get/set | init 后 get 非空；set(0) 成功；非法 instance_id 失败 |
| x_malloc 族 | 正常分配；size=0 返回空；align 对齐；DEVICE/HOST_SIDE（条件） |
| engine config | 合法 offset/ub_size/sync_id；ub_size=0 边界 |
| barrier/sync | 全 PE 同步调用两轮；on_stream 后 synchronize |
| handle_wait | ≥2 卡 putmem_on_stream 后 wait，无 hang |
| prof | show_prof 不崩溃；get_prof 返回类型合法 |
| core wrappers | unique_id init + barrier；多实例符号；handle_wait 可调用 |
| put overhead | warmup + 计时；可选 C++ baseline 门禁 |
| barrier latency | 多轮 barrier，SIGALRM 防死锁 |

## 注意事项

1. **集合操作**（barrier / sync / malloc 对称堆）必须所有 PE 同步进入，禁止单卡冒充多卡。
2. **初始化顺序**：`torch.npu.set_device` → `dist.init_process_group` → `aclshmem_init`（与 shmem 官方 Python 样例一致）。
3. **GIL**：绑定侧应对阻塞 Host API 使用 `gil_scoped_release`；本测试通过 torchrun 多进程覆盖集合语义，不替代绑定侧 GIL 审查。
4. **跨机 handle_wait**：当前脚本默认单机多卡；跨机需改 `ip_port` / bootstrap，并在 RDMA 可用环境复测。
5. **引擎不具备时**：SDMA/RDMA/UDMA config 若运行时返回非 0，以实现文档为准；脚本记录返回值。HOST_SIDE / core 封装缺失时使用 `[SKIP]`。
6. **性能门禁**：未设置 `SHMEM_CPP_PUT_BASELINE_US` 时只出 Python 侧数据，不判 FAIL。
7. 开发者接口签名可能与用例略有出入（例如 stream 传 `npu_stream` 或 capsule），可按实际绑定微调，但覆盖接口集合不得删减。
8. **不要修改** `case_M7/ops-collections/`；本任务仅使用 `case_M7/shmem-python-api/`。
