## 集成

将tests目录下的文件复制到ops-collections/tests中对应的位置

## 编译 & 运行

```bash
source ${ASCEND_HOME_PATH}/set_env.sh

# 功能测试
bash scripts/build.sh -b

# 测试单个功能
bash scripts/build.sh -r --test-name bloom_filter_add_test
bash scripts/build.sh -r --test-name roaring_bitmap_contains_test

# 性能测试
bash scripts/build.sh -p
```

可执行文件生成在build/performance/<test_name>下，可以直接运行

## 测试场景

### BloomFilter

| 接口 | 测试场景 |
|------|---------|
| create | 多 block 数（1~10000）、单 block 边界、ArrowFilterPolicy |
| destroy | 空 filter 析构、添加大量 key 后析构 |
| Add | Sync/Async、TPR 验证（1~65536 key × 7 种 pattern）、重复 add、空 key |
| AddIf | Sync/Async、全零 stencil |
| Contains | Sync/Async、TPR=1.0、FPR<1.0、空 filter、混合查询 |
| ContainsIf | Sync/Async、全零 stencil |
| Clear | Sync/Async、多次 clear、clear 后 re-add TPR=1.0 |
| Merge | Sync/Async、空 filter merge、numBlocks 不同抛异常 |
| Intersect | Sync/Async、空 filter intersect、numBlocks 不同抛异常 |

**Key 类型**：int32_t / uint32_t / int64_t / uint64_t / float  
**数据模式**：sequential / random / duplicates / zero / sparse / min / max

### RoaringBitmap

| 接口 | 测试场景 |
|------|---------|
| create | 多元素数（0~65536）、空位图、单元素、SizeBytes 校验 |
| destroy | 空位图析构、查询后析构 |
| Contains | Sync/Async、in-set / out-of-set / mixed、零/max 边界、空查询数组 |

**Key 类型**：uint32_t / uint64_t

## 注意事项

- 通过 `COLLECTION_TEST_DEVICE_ID` 环境变量指定 NPU 设备，默认 0
- BloomFilter 无假阴性（TPR=1.0），Merge/Intersect 要求两个 filter 的 numBlocks 相同
- RoaringBitmap 是精确结构，Contains 结果应与 ground truth 100% 一致
- 查询结果使用 `unsigned char` 而非 `bool`，因 `std::vector<bool>` 是位压缩特化不支持 `data()`
- 具体事项详见项目中的文档
- 开发者接口函数和返回值可能和测试用例中的调用方式有所出入，可以适当调整
- 如果有新加的辅助参数或者接口，请自行测试功能
