# static_multimap 容器开发设计

Atlas 950 昇腾平台开发与验收方案

版本 V1.0　　日期 2026年9月16日　　文档性质 设计评审稿

本设计处于开发前评审阶段。功能、性能及内存数据中的目标和预算均为设计要求，尚未形成 Atlas 950 实测验收结论。

## 需求背景

### 1 项目目标与建设范围

本项目面向 Atlas 950 系列产品，使用 Ascend C 与 C++ 实现静态容量多值键值映射容器 StaticMultimap，并按 ops-collections 纯头文件容器模式完成工程集成、功能验证、性能优化及开源交付。交付目标为支持任务书规定的全部接口和 I32/I32、I64/I64 两组类型，满足多值、重复数据和容量边界语义，完成 1086 个既定功能用例及 32 个性能用例的验证。

容器保留同一 Key 对应的全部 Value，完全相同的键值对按不同记录保存。对外可观测的容器内容和查询输出应可重复；整数结果采用精确比较。性能逐用例达到标杆的 0.4 倍及以上，即实测时延不超过对应标杆时延的 2.5 倍。未达标用例须提交原因、分析证据和改进措施，并由甲方评审确认处理结论。

#### 1.1 开发范围

交付 Create、Destroy、Clear、Insert、InsertIf、Contains、ContainsIf、Find、FindIf、Count、Retrieve、RetrieveAll 共 12 类接口；提供测试所需的构造与析构、Size、Capacity，以及设备侧容器引用。完成接口文档、使用示例、构建与测试入口、自测报告和代码评审整改。

本期验收类型为 int32_t/int32_t 与 int64_t/int64_t。浮点类型、混合 Key/Value 类型、动态扩容、单条删除、跨设备共享和并发读写事务不列入本期交付范围。后续支持 SIMT 的昇腾产品通过硬件能力适配层扩展，兼容结论以对应设备的实测记录为准。

## 需求分析

### 2 功能语义与接口基线

#### 2.1 统一数据语义

容量按键值对记录数计算，不按不同 Key 的数量计算。Size 返回已成功插入的记录总数；Multiplicity 表示一个 Key 的记录数，包含完全相同键值对的重复次数。Capacity 返回实际可用容量，允许为满足内部对齐而不小于申请容量。

空键哨兵由构造参数指定，不能作为合法输入 Key。测试包使用对应整数类型的最小值作为 emptyKey 和 emptyValue。Value 是否允许等于 emptyValue 必须在接口契约中明确；拟允许其作为载荷保存，Find 的命中判别由 Contains 辅助完成，不能仅以返回值等于哨兵推断未命中。

numInputs 为 0 时，批量接口接受空输入和空输出指针，返回零或不执行数据访问。非零输入的指针、元素数量、输出容量和字节数溢出须检查；void* 接口无法仅凭地址证明实际分配长度，调用方应保证缓冲区覆盖声明的元素数量。

#### 2.2 需求差异处理

以下事项纳入设计评审基线，评审结论同步写入 API 文档、测试适配和验收记录，不通过修改原始断言掩盖差异。

| 事项 | 资料中的差异 | 拟采用口径 |
| --- | --- | --- |
| Insert 返回值 | 示例涉及成功数与失败数两种口径；测试断言失败数 | 返回插入失败数；条件未选中项不计失败 |
| 输入数量上限 | 通用约束写为不超过容量；边界测试传入 Capacity+5 | 插入允许超过剩余容量，部分成功并返回失败数 |
| Count 输出 | 通用参数表提及结果数组；测试调用返回标量 | 返回所有查询的总匹配数，重复查询重复累计 |
| 生命周期 | 任务列出 Create/Destroy；测试采用构造/析构 | 显式接口与 RAII 共用同一实现 |
| 参数顺序 | 参考采用起止迭代器；测试把数量放在部分输出之后 | 同时提供规范入口和测试兼容重载 |
| Retrieve 载荷 | 参考 output_match 为匹配键值对；测试输出 Value | 提供完整键值对入口及 Value 投影兼容入口 |
| 输出确定性 | 测试归一化比较，未约束原始返回顺序 | 另外定义稳定顺序并增加未经排序的重复性测试 |

参考实现 dev 分支会持续变化。编制核对时，其 static_multimap 的 insert 声明返回 void，不能将任务书中的 StaticMap 示例直接视为 static_multimap 的同版本声明。最终适配以锁定的参考版本和经评审的接口映射为准。[1]

### 3 对外接口设计

#### 3.1 类型与生命周期

容器类型为 aclco::StaticMultimap<Key, Value>。元素数量使用 64 位计数，输入序列通过 Device 首地址与 Extent 表示；输入 Pair<Key, Value> 的布局、对齐及字节大小在编译期检查。接口采用大驼峰命名，ACL 流置于参数末尾。

构造入口保留测试调用形式 StaticMultimap(capacity, emptyKey, emptyValue, stream)。Create 建立相同资源，Destroy 显式释放；析构执行同一释放逻辑。容器禁止隐式复制，支持资源所有权转移，满足测试中返回对象及 optional、unique_ptr 的使用方式。显式销毁后再次销毁安全返回，其他操作报告无效状态；析构不抛异常。

#### 3.2 操作与返回约定

| 接口 | 输入和行为 | 输出或返回 |
| --- | --- | --- |
| Create | 正容量、空键/空值哨兵、流；分配并初始化 | 可用容器，Size 为 0 |
| Destroy | 等待本容器相关操作结束并释放资源 | 进入已释放状态 |
| Clear | 清空全部记录，保留静态容量 | Size 为 0，可继续插入 |
| Insert | 按输入次序接纳合法 Pair，保留所有重复记录 | uint64 失败数量 |
| InsertIf | 对 stencil 执行 pred，仅接纳选中项 | 选中项中的失败数量 |
| Contains | 对每个查询 Key 判断是否存在 | 每查询 1 字节，0 或 1 |
| ContainsIf | 未选中位置写 0，其余执行 Contains | 与输入位置对应的标志数组 |
| Find | 返回该 Key 最早成功插入记录的 Value | 未命中写 emptyValue |
| FindIf | 未选中位置写 emptyValue，其余执行 Find | 与输入位置对应的 Value 数组 |
| Count | 累计每个查询 Key 的全部记录数 | uint64 总数 |
| Retrieve | 按查询顺序展开所有匹配记录，未命中不输出 | 实际输出记录数 |
| RetrieveAll | 按成功插入次序导出全部记录 | 实际输出记录数 |
| Size 与 Capacity | 查询有效记录数与实际可用容量 | uint64 标量 |

Find 的固定选择规则是本项目确定性设计。在参考实现允许返回任一匹配值的范围内，选择最早插入项；跨平台验证检查结果属于合法匹配集合，本实现内部重复执行则比较原始输出完全一致。[1]

#### 3.3 参数映射与兼容重载

规范入口以“首地址、数量”替代参考接口的“first、last”，保留其余参数的相对次序。条件接口接收实际谓词对象，以支持带状态谓词；测试兼容入口默认构造模板谓词并转调规范入口。下列签名为拟定公共接口，具体别名及错误类型随目标仓库规范冻结。

```cpp
using SizeType = uint64_t;
using Extent = aclco::Extent<std::size_t>;

SizeType Insert(void* pairs, Extent numInputs, aclrtStream stream);

template<class Stencil, class Pred>
SizeType InsertIf(void* pairs, Extent numInputs,
                  Stencil* stencil, Pred pred, aclrtStream stream);

void Contains(void* keys, Extent numInputs,
              void* flags, aclrtStream stream);
void Find(void* keys, Extent numInputs,
          void* values, aclrtStream stream);

template<class Stencil, class Pred>
void ContainsIf(void* keys, Extent numInputs, Stencil* stencil,
                Pred pred, void* flags, aclrtStream stream);
template<class Stencil, class Pred>
void FindIf(void* keys, Extent numInputs, Stencil* stencil,
            Pred pred, void* values, aclrtStream stream);

SizeType Count(void* keys, Extent numInputs, aclrtStream stream);
SizeType Retrieve(void* keys, Extent numInputs,
                  Key* probeOut, aclco::Pair<Key, Value>* matchOut,
                  Extent outputCapacity, aclrtStream stream);
SizeType RetrieveAll(void* keysOut, void* valuesOut,
                     Extent outputCapacity, aclrtStream stream);
```

Contains、Find 的测试重载采用 (keys, output, numInputs, stream)；ContainsIf、FindIf 采用 (keys, stencil, output, numInputs, stream)；InsertIf 采用 (pairs, stencil, numInputs, stream)。这些重载不复制输入数据，也不独立维护算法。

Retrieve 的测试重载输出 (probeKey, matchedValue)，与测试包一致；完整键值对重载保留参考 output_match 的含义。两者共用计数、偏移计算和匹配枚举，仅在写出载荷时选择投影。当前整数相等匹配场景中，probeKey 与 matchedKey 相同，投影不丢失匹配关系。增加 outputCapacity 是输出安全检查所需扩展。

## 详细设计

### 4 总体架构与存储设计

#### 4.1 分层结构

Host 容器层负责资源生命周期、参数校验、错误转换、ACL 流依赖及 Kernel 调度。设备引用层只持有 Device 地址、容量、计数与哈希配置，不拥有内存。Ascend C Kernel 层执行记录写入、索引构建、查询、归约和结果写出。

数据处理路径为：调用参数校验 → 计算工作空间和任务划分 → 提交 Device Kernel → 完成必要同步 → 返回数量或输出结果。所有批量键值数据直接在 Device 上处理，Host 仅回读必要标量和错误状态。

#### 4.2 主方案

拟采用“顺序记录区与哈希索引分离”的存储结构。顺序记录区保存全部成功插入的 Pair，其下标即稳定记录序号；哈希目录定位不同 Key 的首记录、记录数与最早记录；链接索引连接同一 Key 的其余记录。

该结构使重复键值对作为独立记录保存，并使 RetrieveAll 可按记录顺序连续读写。查询通过哈希目录定位，避免对全部记录逐一扫描。与直接依赖并发抢占槽位顺序的方案相比，该方案明确承担额外索引内存，用于满足确定性和高重复度查询要求。

| 存储项 | 布局 | 作用 |
| --- | --- | --- |
| 记录区 | 容量 C 的 Pair 数组 | 保存稳定顺序的完整键值对 |
| Key 目录 | 大小 H 的开放寻址哈希表 | 保存 Key、链头、计数、最早序号及状态 |
| 链接区 | 容量 C 的记录下标数组 | 串接同一 Key 的重复记录 |
| 元数据 | 少量 64 位计数及版本字段 | 有效数量、容量、初始化状态与错误 |
| 工作空间 | 分块计数、前缀和、索引整理缓冲 | 条件筛选、稳定排序和输出定位 |

H 与 C 分别表示目录槽数和记录容量。目录按目标负载率预留并保持静态，不因某个测试数据集临时缩减容量。容量、字节数、对齐与索引宽度均做溢出检查。生产接口使用 64 位规模；仅在证明容量和中间值均不溢出后启用 32 位索引特化。

#### 4.3 技术验证门槛

首阶段完成 I64 原子操作、目录竞争、重复链整理及大规模内存占用原型。若索引成本或整理开销不能满足约束，将提交开放寻址槽位方案的对比数据后调整内部结构；公共语义、接口和全部验收用例保持一致。算法复杂度与性能目标以真实硬件结果评估。

### 5 关键算法与确定性设计

#### 5.1 插入与条件插入

Insert 先检查合法性，再为有效输入确定稳定接纳序号；InsertIf 先计算谓词掩码，再用分块前缀和为选中且合法的输入编号。剩余容量不足时，按原输入顺序接纳能够容纳的前部有效记录，其他记录计入失败数。非法空键不占用记录槽，全部失败和零选中均保持容器内容不变。

记录写入顺序区后，SIMT 线程协同完成 Key 的哈希定位及索引更新。目录使用原子操作协调 Key 的建立与冲突，不将“相同 Key 已存在”视为插入失败。重复键对应的链接在插入完成前按记录序号整理，形成稳定遍历次序；无重复链可跳过整理。所用排序缓冲仅保存索引，不复制完整 Key/Value 输入数组。

哈希探测设置有限上界，覆盖目录全满和碰撞极端情况。目录建立与载荷可见性通过分阶段 Kernel 及明确的同步边界保证，禁止其他查询读取尚未完成的记录。原子操作宽度、对齐和可见性语义必须在目标 CANN 与设备组合上验证。

#### 5.2 查询与总计数

Contains 在定位到合法 Key 后返回命中；Find 返回目录记录的最早成功插入值。条件查询为每个输出位置显式写入结果，未选中的 ContainsIf 写 0，FindIf 写 emptyValue，不依赖调用方提前清零。

Count 对每个查询读取该 Key 的记录数，并进行线程局部、块内及跨块 64 位归约。查询中的重复 Key 不去重。例如容器中 Key=1 有 4 条记录，查询数组中出现 7 次 Key=1，则 Count 返回 28。计数乘加、中间归约及输出容量计算均检测整数溢出。

#### 5.3 批量检索

Retrieve 先计算每个查询的匹配数，通过排他前缀和确定输出起点；验证总结果数不大于 outputCapacity 后，再按查询位置和匹配记录序号写出结果。同一 Key 被查询多次时，各查询分别输出完整匹配集合。工作空间可按固定查询块复用，以控制大规模查询时的峰值内存。

RetrieveAll 检查 outputCapacity 不小于 Size，然后顺序扫描记录区并分离写出 Key 与 Value。禁止以全局原子抢占输出位置替代稳定定位。两类接口都在输出容量不足时报告错误，不越界写入；结果总数为 0 时允许空输出指针。

#### 5.4 确定性边界

确定性比较对象为相同初态、相同调用序列下的记录内容、插入失败数以及原始查询输出。哈希目录内部物理槽位不作为跨设备字节级一致性要求。并发修改通过容器级调度串行化；无数据依赖约束的多流写入不属于合法使用方式。

### 6 内存与执行流管理

#### 6.1 内存预算

以容量 C、目录槽数 H、Key/Value 字节数 K/V、索引字节数 I 计，记录区约为 C×(K+V)，链接区约为 C×I，目录约为 H×对齐后的单目录项大小。总峰值还须计入输入、输出、工作空间、ACL 分配对齐及运行时开销。最终报告分别列出容器常驻内存和单接口峰值，不能仅报告键值载荷大小。

性能脚本中，Create/Destroy 申请容量 100000000；其余接口按 NumInputs/Occupancy 创建容器，申请容量为 200000000。两者的内存预算不可混用。以下采用十进制 GB，仅表示键值记录区及测试数据，不含哈希目录、链接和工作空间。

| 项目 | I32/I32 | I64/I64 |
| --- | --- | --- |
| 1 亿容量的记录区 | 0.80 GB | 1.60 GB |
| 2 亿容量的记录区 | 1.60 GB | 3.20 GB |
| 1 亿条输入 Pair | 0.80 GB | 1.60 GB |
| 1 亿个查询 Key | 0.40 GB | 0.80 GB |
| 1 亿个 Contains 结果 | 0.10 GB | 0.10 GB |
| 1 亿条分离 Key/Value 输出 | 0.80 GB | 1.60 GB |

补充预算示例：在 I64、C=H=2 亿、I=8 字节、目录项按 40 字节对齐估算时，容器常驻约 12.8 GB；Retrieve 加输入 Pair、查询 Key 和分离输出后约 16.8 GB，尚需计入工作空间。该值是结构预算而非实测占用，目录布局与 H 的扩大将直接增加需求。必须依据目标设备可用内存预先验证，不能通过降低验收数据量替代完整规模测试。

工作空间优先采用分块计数与索引缓冲复用。必要的线性索引空间需说明用途、字节数及生命周期，避免同时保留多份完整输入副本。每个测试配置结束后释放上一个配置的 Context，防止 I32/I64 静态对象叠加形成非必要峰值。

#### 6.2 同步与错误处理

拟将任务要求的公共接口定义为同步完成：正常返回时，该流上对应操作已经完成，Host 标量返回值与 Device 输出均有效。底层可异步组织多个 Kernel，但只在接口完成边界同步，避免逐元素或逐块 Host 等待。若后续增加 Async 扩展，须独立命名和测试。

容器在 ACL 上下文和流仍有效时销毁。跨流访问需记录前序操作完成事件或进行等效同步，不假设不同流天然有序。分配或初始化失败时释放已取得资源；显式接口报告错误，析构记录释放失败且不抛异常。测试兼容入口对 Insert(nullptr, 3, stream) 返回 3，不启动非法访存。

#### 8.2 参考结果

沿用辅助文件的 CPU unordered_multimap 作为功能参考，按多重集合保留全部重复数据。Contains 比较命中标志，Find 检查合法匹配值，Count 比较总数，Retrieve/RetrieveAll 比较归一化后的键值对及重复次数。

另行建立锁定版本的 cuCollections 对照程序，核对空值、条件谓词及检索语义。CPU 对照、CUDA 参考对照和 Ascend 实测分别留存证据；参考实现未定义顺序的结果使用集合语义比较，确定性由本实现专用用例单独验证。

#### 8.3 补充验收用例

既定测试保证基础覆盖，以下补充项验证任务书要求中尚未被原始断言充分约束的行为。补充用例独立统计，不冲抵 1086 个既定用例。

| 类别 | 补充场景 | 通过标准 |
| --- | --- | --- |
| 确定性 | 相同初态和调用序列至少重复 20 次 | 失败数、Size、原始输出逐元素一致 |
| 容量不足 | 满容器继续插入，谓词筛选后超容量 | 稳定接纳相同记录，无越界及死循环 |
| 输出不足 | Retrieve/All 输出容量差 1 或为 0 | 报错且保护区不被修改 |
| 非法输入 | 非零数量空指针、保留空键、算术溢出 | 返回约定错误，容器状态可解释 |
| 数值边界 | 负数、零、最大值、接近最小值、哨兵 Value | 完整保留位宽，符合哨兵契约 |
| 哈希冲突 | 强碰撞、单热 Key、高重复度、非均匀输入 | 全部合法记录可计数和检索 |
| 条件输出 | 预填非零垃圾值，带状态谓词 | 未选中位置显式写入规定结果 |
| 生命周期 | 移动、显式销毁后析构、初始化失败 | 不重复释放，不遗留 Device 分配 |
| 执行流 | 同流连续调用、带依赖跨流访问 | 不读到未完成写入，不释放在用内存 |
| 泛化 | 随机长度、非对齐尾块、多个分批插入 | 与 CPU 参考一致，分批顺序可追踪 |

每项失败必须记录输入种子、容量、dtype、调用顺序和最小复现配置。修复后复测失败用例、相关接口以及完整既定功能集。对输出缓冲增加保护区，对生命周期监测分配与释放数量及峰值内存。

#### 8.4 自测报告内容

报告按接口与用例编号组织，至少包含参数、预期结果、实际结果、通过状态、日志路径、源码提交和环境版本。性能报告另列基线、实测、倍率、计时口径及运行统计。大规模输出保存校验摘要与抽样数据，错误用例保留可复现的输入或生成规则。

功能通过、性能通过、设计评审通过和代码合入分别形成记录。开发阶段不以构建成功或单个接口通过替代全量验收结论。

### 9 性能测试与优化方案

#### 9.1 测试口径

验收倍率按“标杆时延 ÷ 本实现时延”计算，每个用例须达到 0.4。32 个用例逐项判定，不以平均倍率抵消单项不足。全部时延统一使用毫秒，原脚本 Measure 返回微秒计数，报告层需明确换算。

原始性能源码使用 Host 高精度时钟包围接口调用，并把同一数值写入 TestResult 的两个时间字段。该记录本身不能证明获得独立的 Device 执行时间。须核实公共接口同步语义及性能框架定义；端到端耗时与设备事件耗时分列，禁止将纯提交时间报告为完整执行时延。

Create 计时包含容器分配与初始化完成，不含计时外析构；Destroy 在计时前完成初始化，只测等待必要依赖后的资源释放。Insert 在计时前完成上一轮 Clear，计时后核对插入成功数。查询与检索在预置数据完成后开始，输入生成、Host 到 Device 拷贝和测试输出校验不混入接口时间。

正式计时建议预热 5 次、有效重复不少于 20 次，记录全部样本、中位数、均值及 P95。最终采用与甲方标杆一致的统计值；未确认统计口径前，不直接用不同统计量计算验收结论。测试时保持设备运行模式和负载条件稳定。

#### 9.2 数据分布核对

任务书将性能分布标为 UNIFORM，而提供的 MakePairs 生成顺序 Key，查询命中和未命中亦按区段构造。正式基线保持原始生成规则，并在报告记录实际分布；随机均匀和打散查询作为补充压力测试，不能静默替换后沿用原标杆时延。

#### 9.3 优化路线

首先消除非必要分配、重复数据搬运和频繁同步，再依据设备分析数据优化。Insert 关注目录竞争、分块前缀和及重复链整理；Contains/Find 关注哈希探测、随机访存和小负载调度；Count 关注局部计数与分级归约；Retrieve 关注结果偏移及写出带宽；RetrieveAll 关注顺序读写和 Key/Value 分离存储带宽。

SIMT 线程组宽度、每线程处理条数、目录负载率及分块大小通过参数扫描确定，不预设未经验证的最佳配置。不得识别特定测试数据并返回预构造答案。每次优化同时记录功能回归、时延变化和内存变化，保留可复现的对比版本。
