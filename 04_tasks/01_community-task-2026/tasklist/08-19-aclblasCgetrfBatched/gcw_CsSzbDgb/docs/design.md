# aclblasCgetrfBatched 算子设计文档

## 1. 需求背景

本算子来自 [CANN 社区 aclblasCgetrfBatched 开发任务](https://www.hiascend.com/activities/task-center/details/6b3642af5df34d7d8b262d8693e2e048?menu=trends)，面向 Ascend 950PR，使用 CANN 9.1.0 和 Ascend C，在 ops-blas 中提供单精度复数批量 LU 分解。接口风格参考 cuBLAS，具体参数、主元编号和错误处理遵循本任务书。

对一批相互独立的方阵分别进行部分主元 LU 分解，数学关系为 `P × A = L × U`。这里 P 表示按主元序列依次执行行交换所得到的置换，L 为单位下三角矩阵，U 为上三角矩阵。分解结果覆盖原矩阵：严格下三角保存 L 的非对角元素，上三角及对角线保存 U，L 的单位对角线隐含保存。

## 2. 需求分析

支持 complex64 列主序方阵，实部和虚部各为 float32；允许列间由 lda 指定的填充，各矩阵独立分解，无广播。

支持部分主元和非主元两种模式，输出从 1 开始的主元行号，以及每个矩阵首次出现零主元的位置。

支持原地输出、空规模直接返回和参数错误检查；通过句柄绑定的 stream 异步执行，读取结果前由调用方同步。

在保持主元、奇异信息和数值要求的前提下，利用批量并行、片上数据复用和按容量分块减少重复读写。

## 3. 详细设计

公共声明位于 `include/cann_ops_blas.h`，实现位于 `blas/getrf_batched/arch35/`，测试位于 `test/getrf_batched/cgetrf_batched/`。

### 3.1 接口与数据语义

```cpp
aclblasStatus_t aclblasCgetrfBatched(
    aclblasHandle_t handle, int n, aclblasComplex* const Aarray[],
    int lda, int* PivotArray, int* infoArray, int batchSize);
```

| 参数 | 位置及方向 | 含义与约束 |
| --- | --- | --- |
| handle | Host，输入 | 有效 ops-blas 句柄，携带执行 stream |
| n | Host，输入 | 方阵阶数，n ≥ 0 |
| Aarray | Device，输入/输出 | batchSize 个设备指针；各自指向 lda × n 的复数存储区，逻辑矩阵为 n × n；矩阵间不得重叠 |
| lda | Host，输入 | 相邻列首元素的间距，以复数元素计；lda ≥ max(1, n) |
| PivotArray | Device，输出 | n × batchSize 个 int32；第 b 个矩阵第 k 步写入 `PivotArray[b*n+k]`；为空时关闭主元选取 |
| infoArray | Device，输出 | batchSize 个 int32；0 表示未遇到零主元，正数表示首个零主元的 1-based 位置；主元模式下不可为空 |
| batchSize | Host，输入 | 矩阵数量，batchSize ≥ 0 |

采用从 0 开始的 row、col 计算地址时，矩阵元素偏移为 `row + col*lda`，每个元素占 8 字节。仅更新逻辑 n × n 区域，保留 lda 引入的填充。

第 k 步从行 k 到 n−1 中选择 `|real| + |imag|` 最大的元素，值相等时取最小行号，主元数组写入该行号加 1。非主元模式使用当前对角元，不换行；此时允许 infoArray 为空，传入非空数组则正常输出奇异信息。

### 3.2 参数检查与边界

先检查 handle，空句柄返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`；再检查 n、batchSize 和 lda，非法时返回 `ACLBLAS_STATUS_INVALID_VALUE`。标量参数合法后，n=0 或 batchSize=0 直接返回成功，不访问数据指针，也不启动计算。非空规模要求 Aarray 非空，且 PivotArray 非空时 infoArray 必须非空。

零主元指实部和虚部均为零。首次遇到零主元时记录 `info=k+1`，跳过该步的除法与消元，继续后续列；以后遇到零主元不覆盖首次位置。奇异性是矩阵的计算结果，不作为接口调用失败。启动失败则返回 `ACLBLAS_STATUS_EXECUTION_FAILED`。

### 3.3 Host 调度与通用容量选择

Host 获取可用 AIV 核数 C，按 `q=ceil(batchSize/C)` 分配连续的矩阵区间，实际使用 `ceil(batchSize/q)` 个核，最后一个核处理剩余矩阵。每个矩阵的列间依赖在所属核内完成，核间不共享矩阵或主元结果。传给 Kernel 的信息包括 n、lda、使用核数、每核矩阵数、尾核矩阵数及主元模式。

Kernel 根据运行时阶数和片上存储容量选择以下方法：

| 范围或条件 | 实现方法 | 选择依据 |
| --- | --- | --- |
| 1 ≤ n ≤ 32 | 将最多 8 张矩阵组合存放，共同进行向量计算，各矩阵独立选主元 | 16/32 行存储档位与向量宽度 |
| 33 ≤ n ≤ 64 | 单矩阵完整存入 UB，完成分解后写回 | 单个向量可覆盖的 64 行 |
| n > 64，且两张完整矩阵和控制数据可同时放入 UB | 两张矩阵共同处理，批量尾部可只处理一张 | 由空间公式计算，当前上限为 101 阶 |
| 其余 102 ≤ n ≤ 4096 | 共用列面板分解与分块更新 | 行容量、面板宽度及剩余 UB 空间 |

选择不依赖用例编号、随机种子或指定阶数名单。分组不足时只读写实际存在的矩阵。容量方案覆盖 1～4096 阶，更大规模不属于本文容量方案的验证范围。

### 3.4 Kernel 计算与数据流

小矩阵路径从 GM 按列读入 UB，在片上完成选主元、换行、复数除法和后续元素更新，再将 L/U、主元序列和 info 写回。多张共同处理时，各矩阵的选主元和结果存储相互独立，利用向量通道并行执行相同的计算步骤。

分块路径将当前若干列组成面板，保留完整有效行。面板读入 UB 后，逐列选主元并交换面板内的行，计算该列乘子，更新面板中尚未处理的列。面板外的数据按列块读入，依主元的原始顺序补做行交换；右侧列块继续执行该面板对应的消元更新，左侧已分解列块只需换行。最后写回列块，进入下一个面板。

当前列的非零对角元记为 d，下方元素 x 的乘子为 `l=x/d`；后续元素按 `A(i,j) ← A(i,j) − L(i,k)×U(k,j)` 更新，不使用共轭。复数运算拆为 float32 实部和虚部运算；向量除法后计算余数并补偿一次，减小除法误差。分块路径的选主元和换行使用线程协作，乘子及消元使用向量计算。

只有计算出的主元序列确实没有换行时，才省去无效果的换行操作；此时也可跳过左侧列块的读写。数据搬入、向量计算、线程协作和写回之间按依赖同步，避免缓冲区尚在使用时被覆盖。

### 3.5 内存与约束

分块行容量 R 依次取 128、256、384、512，之后按 2 的幂扩展至 4096，选择能覆盖 n 的最小档位。UB 每列存储跨度为 R+4 个复数，既覆盖完整向量写入范围，也满足列首对齐；实际回写仍只包含 n 行。

动态 UB 预算为 212 KiB，其中控制区占 512 字节。令 `K=floor((212×1024−512)/((R+4)×8))`，面板列数 W 从 32 开始减半，直到 `W+W/2 ≤ K`；外部列块宽度 S 取不超过 K−W 的最大 2 的幂。空间满足：

```text
(W+S) × (R+4) × 8 + 512 ≤ 212 KiB
212 KiB + 8256 字节静态预留 ≤ 224 KiB
```

两张完整矩阵的容量按 `2×n×132×8 + 2×(512+176×4) ≤ 212 KiB` 计算。小矩阵使用各自较小的预算。控制数据与矩阵数据分区，按完整写入宽度保留空间，不以无效行掩码替代存储容量检查。

上述路径不申请额外 GM 工作区，复用调用方的输入输出存储。目标为 Ascend 950PR；不支持超出 lda 语义的任意非连续布局。批量较小时，可参与计算的核数受矩阵数限制。病态矩阵、极大或极小值及 Inf/NaN 需独立验证，不由普通随机输入的结果推断其覆盖情况。

## 4. 可维可测分析

### 4.1 精度

采用测试工程内自包含的 LAPACK 单精度复数语义 CPU 参考，执行逐列部分主元 LU；不动态链接 Netlib 或 OpenBLAS。主元按 `|real|+|imag|` 选择，info 和 pivot 逐元素精确比较。

非奇异矩阵的 L/U 实部、虚部分别同时检查两套要求：混合误差使用 `atol=2^-16`、`rtol=2^-10`，至少 99% 元素满足 `|actual−golden| ≤ atol+rtol×|golden|`，且逐元素绝对误差不超过 `max(1e-2,32×ULP(golden))`；补充相对误差要求平均值小于 `2^-13`、最大值小于 `10×2^-13`。补充检查沿用测试框架的近零排除及 `2^-14` 分母稳定项，混合误差检查仍覆盖近零元素。

是否免除奇异矩阵的 L/U 数值比较，由独立 CPU 参考的 info 判定；该矩阵的 info 和 pivot 仍完整检查。不能根据待测输出自行跳过比较。

### 4.2 验证范围与性能

覆盖任务提供的精度、功能和性能用例，并补充各容量切换点及相邻阶数、非整组批量、不同 lda、选主元并列、非主元模式、奇异与非奇异混合批量、非法参数和特殊值。检查逻辑矩阵、整数输出及填充区域，确认没有越界或漏写。

性能在 Ascend 950PR 上预热后采样超过 50 次，取平均耗时，与对应官方基线逐项比较。任务书三个代表规格的上限为：64 阶×512 张 294.43 μs，256 阶×64 张 3398.93 μs，512 阶×32 张 25619 μs。精度和性能分别验证，性能测试本身不代替数值检查；实测结果另列自测报告。

### 4.3 兼容性分析

新增复数批量 LU 接口，沿用 ops-blas 的句柄、stream 和错误码约定，不改变既有实数接口的行为。
