# Equal（EqTensor）算子设计文档

**版本**：v1.0  
**日期**：2026-09-06  
**文档状态**：方案设计  
**适配目标**：Atlas A2/A3 系列产品  
**开发语言**：Ascend C / C++

---

## 1. 需求背景

### 1.1 需求来源

基于 Ascend C 实现 Equal 算子，用于比较两个输入张量对应位置的数值是否相等。算子需要支持形状相同、单侧广播、双侧广播和标量广播，并输出广播后形状的 BOOL 张量。

本设计除完成 Equal 比较本身外，还需要在算子内部提供高效的广播数据组织能力，避免按输出元素逐个计算输入地址，降低复杂广播场景中的标量控制和非连续访存开销。

### 1.2 算子接口

| 参数 | 类型 | 数据类型 | 说明 |
|---|---|---|---|
| `x` | 输入 Tensor | FP16、FP32、BF16、INT8、UINT8、INT16、INT32、INT64、BOOL | 第一个输入 |
| `y` | 输入 Tensor | 与 `x` 相同 | 第二个输入 |
| `z` | 输出 Tensor | BOOL | 逐元素比较结果 |

输入采用 ND 连续布局，支持 0 维标量到 8 维张量。两个输入的数据类型必须一致，形状必须满足标准广播规则。

### 1.3 数学定义

设广播后的输出形状为 `O`，则：

```text
z[i] = (broadcast(x)[i] == broadcast(y)[i])
```

其中 `i` 为输出张量的逻辑坐标。浮点比较遵循数值相等语义：`+0.0` 与 `-0.0` 相等，NaN 与任何值均不相等。

## 2. 需求分析

### 2.1 功能目标

1. 支持等形输入和标准广播输入。
2. 支持单侧广播、双侧广播及最内维标量广播。
3. 输出形状与广播结果一致，输出数据类型固定为 BOOL。
4. 对所有支持的数据类型保持 CPU 逐元素比较语义。
5. 正确处理非 32B 对齐的最内维、尾 Tile 和超大最内维。

### 2.2 性能目标

1. 形状相同时采用连续流式处理，充分利用 GM 搬运和矢量计算吞吐。
2. 广播时优先复用输入数据，避免按输出元素重复从 GM 搬入广播源。
3. 0 Gm侧Workspace需求。
4. 在 UB 中形成规则、固定的数据布局，使广播索引能够复用。
5. 尽量扩大连续搬运和连续写回的长度，降低短 Burst、指令发射和循环控制开销。
6. 使用多核与双缓冲隐藏搬运延迟，同时避免为追求 UB 占满而降低任务并行度。

### 2.3 总体分层

本方案将算子拆分为两个相对独立的部分：

```text
输入 Shape
   |
   v
Broadcast 框架
  - 形状归一化
  - 任务与 Tile 规划
  - GM 数据搬入及 UB 广播物化
  - 生成等形、同布局的 X/Y 数据块
   |
   v
Equal 核心逻辑
  - 逐元素数值比较
  - BOOL 结果生成
   |
   v
连续或分段写回 GM
```

Equal 核心只处理已经对齐的数据块，不感知原始广播维度；Broadcast 框架只负责生成正确的等形输入，不参与具体比较语义。这样可以分别优化比较指令和广播调度，降低两部分之间的耦合。

## 3. Equal 核心逻辑设计

### 3.1 输入输出约定

Equal 核心接收两个元素数量相同、UB 布局一致的局部张量，并输出相同元素数量的 BOOL 结果。输入可以来自普通连续搬入，也可以来自 Broadcast 框架完成广播和紧凑化后的数据。

核心逻辑不负责：

- 推导广播形状；
- 计算多维广播地址；
- 维护输入缓存；
- 处理输出在原始逻辑空间中的任务坐标。

### 3.2 比较语义

| 输入类别 | 设计原则 |
|---|---|
| FP16 / FP32 | 使用数值相等比较，保持 IEEE 浮点比较语义,直接使用compare实现 |
| BF16 | 采用不损失比较语义的设备侧处理方式，无需cast到fp32 |
| INT8 / UINT8 / INT16 / INT32 | 使用对应位宽的整数相等比较 |
| INT64 | 按完整 64 位数值比较，高32位半部和低32位半部分别比较后按位与mask |
| BOOL | 按布尔值比较 |

不同数据类型可以采用不同的矢量实现，但对上层统一表现为“等长输入、BOOL 输出”。具体指令组合属于实现阶段的选择，不在设计阶段固定。

### 3.3 无广播路径

当两个输入形状一致时，不需要进入广播物化流程。Host 将连续输出区间均衡分配给各个核，Kernel 按 Tile 执行：

```text
CopyIn X/Y -> Equal -> CopyOut BOOL
```

主 Tile 采用固定长度，并通过双缓冲使下一 Tile 的搬入、当前 Tile 的计算和上一 Tile 的搬出尽量重叠；尾 Tile 单独处理有效元素。

### 3.4 输出处理

BOOL 结果按 1B 元素写入 GM。若比较阶段为了矢量效率使用了对齐行布局，则在写回前由 Broadcast 框架将结果转换为紧凑输出布局。Equal 核心本身不承担行间去填充工作。

## 4. Broadcast 框架设计

### 4.1 形状归一化

Host 将两个输入从尾部对齐并补齐到相同维数。对每个输出轴记录：

- 输出维度长度；
- `x` 在该轴是实际维还是广播维；
- `y` 在该轴是实际维还是广播维；
- 两侧输入在连续存储中的逻辑步长。

相邻且广播关系一致的维度可在不改变输出物理顺序的前提下合并，以减少调度维度。维度合并只用于地址和任务规划，不能改变输出轴的原始排列。

### 4.2 有序 Cartesian 模型

双侧广播可以视为保持输出轴顺序的局部 Cartesian Product。例如：

```text
A = [a, 1, c, 1, e, 1, x]
B = [1, b, c, d, 1, f, x]
O = [a, b, c, d, e, f, x]
```

固定外层坐标后，局部计算可表示为：

```text
A panel [Te, Tx]
B panel [Tf, Tx]
        |
        v
Output [Te, Tf, Tx]
```

这里 `e` 与 `f` 构成两侧输入的复用维，`x` 是最内层连续维。计算索引可以压缩为 panel 坐标，但输出仍必须严格按 `[a,b,c,d,e,f,x]` 的顺序写回。

该模型也可覆盖单侧广播：当一侧 Cartesian 维度退化为 1 时，框架转化为“广播输入常驻、非广播输入流式处理”的一维复用模式。

### 4.3 Macro Tile 与 Micro Panel

广播任务采用两级规划：

- **Micro Panel**：一次在 UB 中实际参与搬入、广播物化和比较的数据块。
- **Macro Tile**：分配给一个核连续执行的一组 Micro Panel，负责扩大工作粒度和复用范围。

二者不要求大小相同。Macro Tile 可以覆盖多个外层坐标，而 Kernel 在 UB 中依次处理其中的 Micro Panel，无需将整个 Macro Tile 同时放入 UB。

这种解耦允许 Host 在不增加 UB 峰值占用的情况下：

- 减少任务数量和标量控制开销；
- 跨外层坐标复用一侧输入；
- 保持每次实际计算的数据布局固定；
- 维持足够的多核并行度。

### 4.4 最内维规划

最内维是连续搬运和矢量计算的基础维度，优先完整纳入 Micro Panel。

设计规则如下：

1. 最内维数据量不超过 32KB 时，保持完整最内维，不进行列切分。
2. 最内维超过 32KB 时，才允许按列切分为多个 `Tx`。
3. 切分后的每段仍需形成足够长的连续 Burst，并正确处理最后一段。
4. 当 `Tx` 小于完整最内维时，跨行输出不再整体连续，写回按连续内段分段执行。

该规则优先保护常见中小内维的连续性，避免为了增加任务数而产生大量短行搬运。

### 4.5 Panel 选择

Host 不进行大规模暴力候选搜索。设计上采用公式估算结合少量贪心调整：

1. 先确定 `Tx`，优先取完整最内维。
2. 在 UB 预算内选择常驻 Panel 的行数。
3. 扩大另一侧的复用范围，使输入搬运量相对于输出量尽可能小。
4. 从输出连续后缀向外扩展 Macro Tile，直到工作粒度、核间并行度和尾块比例达到平衡。

候选评价主要考虑：

- 输入 GM 流量与复用次数；
- 输出连续段长度；
- 512B 事务粒度下的有效搬运比例；
- UB 占用；
- Micro Panel 数量及控制开销；
- 核间负载均衡和尾块比例。

精细 Cost Model 用于离线仿真和规则设计，最终 Host Tiling 只保留可解释、低开销的公式与贪心规则。

### 4.6 Cache + Stream + Store

Broadcast Kernel 的默认执行方式不是将整个 Macro Tile 放入 UB，也不是每次计算都重新搬入两侧输入，而是：

```text
可复用输入 Panel：常驻 UB
另一侧输入：流式搬入
输出：计算完成后立即写回
```

例如 `A[e,x]` 与 `B[f,x]` 生成 `O[e,f,x]` 时，可以让 `B[Tf,Tx]` 常驻 UB，并逐行流入 `A[Tx]`：

```text
Load B[Tf,Tx]
for each e:
    Load A[Tx]
    Broadcast/Compare A with B
    Store O[Tf,Tx]
```

若另一种循环顺序具有更高复用收益，则交换常驻侧和流式侧。对较小 Panel，也可以让两侧同时常驻，但输出原则上仍采用流式写回，避免不必要地占用 UB。

### 4.7 固定 UB 布局与 GatherB

广播物化计划采用 GatherB，以 32B DataBlock 为基础将源 Panel 组织为比较所需的重复行。

每次搬入时只改变 GM 起始地址，UB 中各输入 Panel 的起始地址、行步长和排列方式在一次 Kernel 调用内保持不变。因此 GatherB 索引描述的是固定 UB 布局中的相对偏移，而不是 GM 的绝对位置。

设计目标是：

```text
变化的 GM Base
      |
      v
固定 UB Panel Layout
      |
      v
可复用 GatherB Index
```

索引根据 Micro Panel 规模适量构造，并优先采用矢量方式生成。只要 `Tx`、Panel 行数和 UB 排列不变，后续 Macro Tile 只更新 GM 坐标，无需逐 Tile 重建索引。

### 4.8 行对齐与紧凑化

GatherB 以 32B DataBlock 为粒度，因此 UB 中的源行和广播后行采用最小 32B 向上对齐步长。广播完成后存在两种情况：

- 对齐行本身已构成最终连续数据，直接进入 Equal；
- 行间包含填充，先使用 GatherMask 将多行有效元素紧凑化，再进入 Equal。

推荐数据流为：

```text
GM 紧凑数据
   -> UB 对齐源行
   -> GatherB 广播物化
   -> GatherMask 去除行填充（按需）
   -> Equal
   -> BOOL 输出
```

若超大最内维被切成多个列段，每个列段在逻辑输出中可能由多个不连续片段组成，此时按连续片段分别紧凑化和写回。

### 4.9 1B 数据与 Scalar Inner

1B 类型的奇数行宽不适合直接作为 2B/4B 矢量重排单元。设计上可在广播重排阶段临时提升为 2B 表示，完成 GatherB 和去填充后，再在比较前恢复为原始 1B 数值语义。偶数行宽在满足布局要求时不强制扩宽。

当某一侧最内维为 1 时，不把单个标量直接物化成完整 `Tx` 行。先使用 Brcb 构造一个便于 GatherB 复用的小型模板：

```text
templateBytes = min(256B, 对齐后的目标行大小)
```

随后由 GatherB 通过循环索引完成实际行宽和多行的广播物化。这样 Brcb 的调用次数不随输出行数线性增长，同时避免小内维场景过度占用 UB。

### 4.10 GM 搬运粒度

性能模型按 512B GM 事务粒度估算有效带宽。这里的 512B 是性能建模粒度，不是接口的功能对齐要求。

当单次连续访问较短，或访问首尾跨越额外 512B 地址区间时，有效载荷比例会明显下降。因此 Tiling 应优先扩大单次连续 Burst；当单行已经足够长时，首尾额外事务的占比降低，可更关注计算并行度和尾块比例。

### 4.11 多核调度与流水

Macro Tile 之间没有数据依赖，可按虚拟任务序号分配给各个 AI Core。任务规划同时满足：

- 任务数足以覆盖可用核心；
- 单任务工作量不至于过小；
- 主任务大小尽量一致；
- 尾任务不会集中到单个核心。

Micro Panel 使用双缓冲组织流式输入和输出，使 GM 搬入、矢量广播/比较和 GM 搬出尽量重叠。常驻 Panel 不参与无意义的轮转，只在其逻辑坐标变化时重新搬入。

## 5. Host 与 Kernel 职责

### 5.1 Host 侧

Host 负责静态规划，包括：

1. 校验数据类型和广播合法性；
2. 推导输出形状并归一化输入维度；
3. 识别无广播、单侧广播和有序 Cartesian 广播；
4. 选择最内维 Tile、Micro Panel 和 Macro Tile；
5. 决定常驻侧、流式侧、是否需要行紧凑化；
6. 计算 UB 预算、核数、主尾任务和固定布局参数；
7. 将 Kernel 所需的最小参数写入 TilingData。

Host 不应把离线仿真的完整搜索模型搬入运行时，也不应让多个互相关联的字段独立回退。一个候选方案需要以整体规划对象完成生成、校验和提交，避免 Host 与 Kernel 对布局理解不一致。

### 5.2 Kernel 侧

Kernel 负责执行 Host 已确定的方案，包括：

1. 根据任务坐标计算各输入和输出的 GM 起点；
2. 将常驻 Panel 和流式数据搬入固定 UB 区域；
3. 初始化并复用 GatherB 索引；
4. 完成广播物化及按需紧凑化；
5. 调用 Equal 核心生成 BOOL 结果；
6. 按原始输出布局写回 GM；
7. 处理主 Tile、尾 Tile 和超大最内维的尾段。

Kernel 不重新搜索 Tiling 方案，不根据运行时数据内容改变布局。

### 5.3 TilingData 概念字段

设计阶段的 TilingData 按职责划分为以下信息组，具体字段名在实现阶段确定：

| 信息组 | 内容 |
|---|---|
| 基础信息 | 数据类型、元素字节数、维数、输出元素总数 |
| 广播描述 | 归一化维度、两侧逻辑步长、广播关系 |
| Micro Panel | `Tx`、两侧 Panel 行数、对齐行宽、常驻侧 |
| Macro Tile | 各外层扩展范围、任务总数、主尾任务大小 |
| UB 布局 | 输入、缓存、索引、紧凑化暂存和输出区域大小 |
| 执行模式 | 无广播/单侧/双侧、完整内维/切分内维、是否需要紧凑化 |

## 6. UB 空间规划

UB 预算至少包含：

- 常驻输入 Panel；
- 流式输入双缓冲；
- 广播物化结果；
- GatherB 索引；
- GatherMask 或类型转换暂存；
- BOOL 输出双缓冲；
- Equal 核心所需临时空间。

Host 应按真实生命周期复用互斥的临时区域，但不能让仍被异步指令使用的数据区提前复用。规划时保留安全余量，不以填满全部 UB 为目标。

离线仿真同时维护两种模型：

- 理想 Cache + Stream + Store 模型，用于判断数据复用和 Tile 形状；
- 含 Kernel 临时空间的可落地模型，用于验证实际 UB 容量。

最终 Host 采用第二种模型的简化公式。

## 8. 约束与边界

1. 输入数据类型必须一致。
2. 输入采用连续 ND 布局，不在本方案中支持任意物理 stride 的非连续 Tensor。
3. 广播维数不超过 8，且每个对应维度必须相等或其中一个为 1。
4. 输出数据类型固定为 BOOL，输出布局与广播后的 ND 逻辑顺序一致。
5. UB 地址和矢量操作数必须满足设备接口的对齐约束。
6. GatherB 索引必须位于合法 UB 范围，且指向完整可读的 32B DataBlock。
7. 最内维切分仅用于超过 32KB 的场景；切分后必须保持输出地址映射正确。
8. 空 Tensor、维度乘积溢出及超出设备寻址范围的输入由 Host 在执行前校验。

## 9. 测试设计

### 9.1 功能测试

覆盖以下场景：

- 等形输入；
- 标量与 Tensor 比较；
- 单侧广播与双侧广播；
- 1 至 8 维输入；
- 多个分散广播轴；
- 32B 对齐、高利用率非对齐和低利用率非对齐内维；
- 小于 32KB 的完整内维和大于 32KB 的切分内维；
- 主 Tile、尾 Tile、尾核和单核场景；
- 各支持数据类型及浮点特殊值。

结果应与 CPU 逐元素参考实现完全一致。

### 9.2 性能测试

性能测试按以下维度选取代表性极端 Shape，而不是对所有参数做笛卡尔积：

- 总数据量：小、中、大；
- 内维：超小、中等、512B 附近、1KB 以上、超过 UB 可容纳范围；
- 广播倍率：小、中、大及质数倍率；
- 广播轴数量：1 至 4；
- 广播类型：标量、单侧、双侧；
- 内维有效搬运率：对齐、非对齐高利用率、非对齐低利用率。

重点观察总耗时、MTE2/MTE3 带宽、Vector 利用率、Scalar 控制占比、任务均衡和实际 GM 流量。

## 10. 风险与后续工作

| 风险 | 影响 | 设计应对 |
|---|---|---|
| 复杂广播轴无法形成足够大的连续后缀 | Burst 较短、控制开销增大 | 通过 Macro Tile 外扩和输入复用降低摊销 |
| Micro Panel 过大 | 核间任务不足或 UB 压力过高 | 公式估算后限制 Panel，保留并行度 |
| Micro Panel 过小 | DMA 和标量发射成为瓶颈 | 优先完整内维并扩大连续输出段 |
| 1B 奇数行频繁转换 | Vector 开销上升 | 在广播重排阶段统一采用 2B 暂存，减少重复转换 |
| 超大内维被切分 | 输出不再整体连续 | 按列段独立紧凑化和写回 |
| Host 与 Kernel 布局定义不一致 | 错址或结果错误 | 使用整体规划对象并建立 Host/Kernel 一致性校验 |
| 固定索引不适用于尾 Panel | 尾块读取越界 | 为尾块保留合法填充空间或使用独立有效范围 |

后续实现阶段应先在仿真中验证 Micro Panel、Macro Tile、GM 事务和 UB 占用模型，再将简化后的规则落实到 Host 与 Kernel。优化顺序为：先保证地址映射与结果正确，再优化连续 Burst、数据复用、流水重叠和标量控制开销。
