# Ascend C Basic API 搬运类接口扩展测试设计文档

本文定义 Ascend C Basic API 搬运类接口指针化扩展的测试背景、需求分析、
测试对象、测试方法和判定标准。测试范围以 DMA 接口清单、任务书和任务
目录中的搬运样例为准。

| 项目 | 内容 |
| --- | --- |
| 任务名称 | Ascend C Basic API 指针化扩展（DMA · 数据搬运 / 缓存） |
| 目标仓库 | <code>cann/asc-devkit</code> |
| 接口范围 | 5 个 API 名称、44 个重载签名 |
| 目标硬件 | Ascend 950 系列，重点覆盖 Ascend 950PR、Ascend 950DT |
| 目标架构 | <code>dav-3510</code> |
| 目标软件 | CANN 9.0.0 至 CANN 9.1.0 |
| 开发语言 | Ascend C、C++ |
| 对比路径 | 原有 Tensor 路径与新增硬件指针路径 |
| 测试资料 | 任务书、DMA 接口清单、6 组搬运样例及其生成和校验脚本 |

## 一、需求背景

本节说明搬运类 Basic API 指针化扩展的来源和测试必要性。

Ascend C 搬运类 Basic API 原有调用方式主要使用
<code>LocalTensor</code> 和 <code>GlobalTensor</code>。任务要求在保持
Tensor 调用功能和兼容性不变的前提下，为 DMA 类接口增加
<code>__gm__</code>、<code>__ubuf__</code>、<code>__cbuf__</code> 等
硬件指针入参能力。

指针化扩展不仅改变运行时入参表达，还会影响模板推导、重载选择、地址
空间限定、SFINAE 条件和 pipe 属性。因此，测试需要同时覆盖编译期接口
行为和运行时搬运语义，不能只对少量样例做数值比较。

任务范围限定为 DMA 类型码 D 的 5 个 API 名称和 44 个重载签名。
VECTOR、CUBE 分册及未列入 DMA 清单的接口不属于本设计的测试对象。

## 二、需求分析

本节只关注外部可观察的接口、编译和运行行为。测试需求分为接口可调用
性、路径等价性、Tensor 回归、地址空间、复杂参数、平台兼容、资源语义
和样例迁移八类。

### 2.1 测试需求拆解

每类需求均使用独立的测试对象、执行方法和判定标准。

| 需求维度 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 编译期接口 | 44 个重载的 Tensor、指针和适用混合调用 | 为每个签名建立正向编译用例，并为非法类型和地址空间建立预期拒绝用例 | 合法调用唯一匹配目标重载，非法调用不能被错误接受 |
| 运行时等价 | 指针路径与 Tensor 路径的数据搬运语义 | 使用相同输入、参数、同步和输出区域执行两条路径 | 输出 Shape、布局和有效元素满足同一参考逻辑 |
| Tensor 回归 | 原有 <code>LocalTensor</code>、<code>GlobalTensor</code> 调用 | 重跑对应 Tensor 用例并检查重载选择和输出 | 接口形式、参数语义、同步和输出行为保持不变 |
| 地址空间 | GM、UB、L1、L0 及签名允许的方向组合 | 按 DMA 清单为源和目的地址配置限定符 | 每个参数只接受签名允许的地址空间 |
| 复杂参数 | <code>DataCopyParams</code>、切片、多维、格式转换、Pad 和量化参数 | 使用样例场景和补充边界组合逐类执行 | 参数解释、格式映射、填充值和有效区域符合接口定义 |
| 平台兼容 | Ascend 950 和 CANN 9.0.0 至 9.1.0 | 在任务规定的版本和架构下编译并执行相同用例定义 | 支持组合的接口和运行行为一致 |
| 内存语义 | 指针适配是否引入额外 Device 搬运或中间 Tensor | 比较两条路径的分配、搬运事件和输出保护区域 | 不引入随输入规模线性增长的额外 Device 副本 |
| 样例迁移 | 官方搬运样例由 Tensor 调用改为指针调用后的行为 | 保持样例数据流和参数不变，只替换适用的 API 入参表达 | 指针样例与 Tensor 基线及参考输出一致 |

### 2.2 API 范围

测试以任务书第 2.4 节的 DMA 接口清单为最终依据。下表按 API 名称归纳
测试职责，重载数量以接口清单逐条映射。

| API | 将测试什么 | 主要测试方式 |
| --- | --- | --- |
| <code>DataCopy</code> | 连续搬运、参数结构、多维、切片、格式转换、量化和激活相关搬运 | 编译期重载覆盖加 Tensor/指针运行时对拍 |
| <code>DataCopyPad</code> | 非对齐搬运、左右填充、Compact、Normal 和 LoopMode | 使用 Pad 样例和对齐边界补充用例 |
| <code>DataCopyL1ToUB</code> | L1 到 UB 的合法地址方向、数据类型和参数结构 | 为两个接口签名建立编译及功能用例 |
| <code>DataCachePreload</code> | 指针入参、预取参数和数据不变性 | 编译用例加预取后读取一致性测试 |
| <code>DataCacheCleanAndInvalid</code> | 指针入参、缓存清理或失效参数和内存一致性 | 编译用例加写回、读取一致性测试 |

### 2.3 测试边界和版本约束

任务验收版本与样例材料的版本声明需要分开处理。测试不得使用更高版本的
样例执行代替任务书规定的验收环境。

| 边界项 | 测试处理 |
| --- | --- |
| CANN 版本 | 验收范围固定为 CANN 9.0.0 至 9.1.0 |
| 样例版本 | 样例 README 若声明更高版本，只用于提取场景和数据流；测试需在验收版本重建等价调用 |
| 硬件范围 | 验收以 Ascend 950 系列为主，其他样例支持产品不能替代 <code>dav-3510</code> 测试 |
| 接口范围 | 只测试 DMA 清单中的 5 个 API 名称和 44 个签名 |
| 底层语义 | 不以指针扩展为由改变原有 <code>*Impl</code> 数值语义 |
| 性能指标 | 任务无独立性能门槛，性能观察不替代功能和精度判定 |
| 样例中的非 DMA 计算 | Mmad、LoadData、Fixpipe 等只作为搬运结果的下游观察点，不作为本任务接口覆盖数 |

## 三、测试主线与判定总览

本节给出验收测试主线。每一类测试都明确测试对象、执行方法和判定标准。

| 验收门类 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 重载覆盖 | 5 个 API 名称和 44 个重载签名 | 建立签名清单与编译用例的一一映射 | 每个签名至少有一个合法指针调用和一个 Tensor 回归调用 |
| 模板与地址空间 | 推导、显式模板参数、限定符和 SFINAE | 编译正向调用和预期拒绝调用 | 无歧义命中，非法组合不进入通用模板 |
| 搬运功能 | GM、UB、L1、L0 间合法数据通路 | 对拍 Tensor、指针和参考输出 | 有效输出元素与布局符合参考语义 |
| 格式和 Pad | ND、NZ、DN、切片、多维、Pad 和 LoopMode | 执行样例场景并补充边界组合 | 格式映射、填充值、步长和尾块正确 |
| 量化与激活 | DataCopy 随路量化、类型转换和 ReLU 组合 | 使用相同量化参数执行两条路径 | 转换结果满足对应精度和饱和规则 |
| 缓存接口 | 预取、清理和失效相关指针调用 | 执行缓存操作前后的数据一致性测试 | 缓存操作不改变逻辑数据并满足一致性语义 |
| Tensor 兼容 | 原有 Tensor 调用和样例 | 使用改造前等价调用重新编译、执行 | 原有接口行为不变 |
| 资源语义 | Device 分配、额外搬运和越界访问 | 比较资源事件并设置保护区域 | 无新增线性副本，无越界读写 |

## 四、测试设计与判定标准

本节展开编译期、运行时、样例场景、兼容性、资源和性能测试方法。

### 4.1 测试环境和工具

测试环境以任务书验收要求为准，样例脚本只承担输入生成和参考输出校验。

| 项目 | 测试配置 |
| --- | --- |
| 目标设备 | Ascend 950PR、Ascend 950DT |
| 目标架构 | <code>dav-3510</code> |
| CANN | 9.0.0 至 9.1.0 |
| 编译器 | 任务环境支持的 <code>ccec</code> 或毕昇 ASC 编译器 |
| 构建系统 | asc-devkit 样例使用的 CMake 构建流程 |
| 运行模式 | NPU 模式；样例支持时补充 CPU 调试或 NPU 仿真编译检查 |
| 输入生成 | 各样例目录的 <code>gen_data.py</code> 或等价确定性生成逻辑 |
| 参考校验 | 各样例目录的 <code>verify_result.py</code> 或等价比较器 |

如果样例源码依赖验收版本之外的接口，测试只提取其场景、参数和参考数据
逻辑，并在 CANN 9.0.0 至 9.1.0 支持的工程结构中构造等价用例。

### 4.2 编译期接口测试

编译期测试覆盖重载可见性、模板推导、地址空间、显式模板参数和参数结构。
每个测试源文件只包含一组可定位的调用，便于识别重载歧义。

#### 4.2.1 正向编译矩阵

每个重载按其形参方向测试以下适用调用形式：

| 调用形式 | 将测试什么 | 判定标准 |
| --- | --- | --- |
| Tensor → Tensor | 原有 Tensor 重载和模板推导 | 可唯一匹配原有调用语义 |
| 指针 → 指针 | 新增硬件指针路径 | 可保留地址空间并唯一匹配目标重载 |
| Tensor → 指针 | 目的或源为指针的混合形式 | 仅在该签名和方向允许时可编译 |
| 指针 → Tensor | 另一方向的混合形式 | 仅在该签名和方向允许时可编译 |
| 显式模板实参 | 带维度、配置或类型模板参数的调用 | 显式参数不改变预期重载和参数结构 |

编译矩阵至少检查以下参数结构：

- 基础 <code>count</code> 形式；
- <code>DataCopyParams</code>；
- <code>DataCopyPadParams</code> 和扩展 Pad 参数；
- <code>Nd2NzParams</code>、<code>Dn2NzParams</code>；
- 切片和多维搬运参数；
- L0C 到 GM 的量化、激活和输出格式参数；
- DataCache 系列的地址和控制参数。

#### 4.2.2 预期拒绝编译

预期拒绝用例验证通用模板不会吞掉非法调用。每个用例单独构建，并将编译
拒绝作为该用例的判定目标。

| 非法组合 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- |
| 错误地址空间 | 交换源、目的限定符或使用签名未允许的空间 | 编译器拒绝该调用 |
| 错误元素类型 | 使用重载不支持的类型或转换组合 | SFINAE 或类型检查拒绝该调用 |
| 错误参数结构 | 将不匹配的参数对象传给目标重载 | 不产生意外的通用模板匹配 |
| 丢失限定符 | 使用不能表达目标硬件空间的普通指针 | 不被当作合法硬件指针路径 |
| 重载歧义 | 构造可能同时匹配多个模板的调用 | 编译结果必须唯一，不能依赖不稳定的候选顺序 |

### 4.3 运行时路径等价测试

运行时测试为同一接口准备 Tensor 路径、指针路径和参考输出。除入参表达
方式外，三者的输入、参数、地址偏移、同步和输出容量保持一致。

每个功能用例按以下顺序执行：

1. 按固定规则生成输入和参考输出；
2. 使用 Tensor 入参执行基线调用；
3. 使用等价硬件指针执行指针调用；
4. 对适用签名执行 Tensor 与指针混合调用；
5. 在读取输出前完成对应 pipe 或执行队列同步；
6. 比较输出 Shape、布局、有效元素、Pad 区和保护区域；
7. 按接口签名记录覆盖关系和判定规则。

纯搬运且不发生类型转换的场景要求有效字节精确一致。包含格式转换、
量化或激活的场景按参考逻辑和生态算子精度标准比较。

### 4.4 API 专项测试矩阵

不同 API 的可观察行为不同，测试方法和判定标准需要分别定义。

| API | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| <code>DataCopy</code> | 连续、切片、多维、格式转换和随路处理 | 覆盖清单中的参数结构和样例数据流，比较两条路径 | 搬运区域、顺序、布局和转换结果符合参考逻辑 |
| <code>DataCopyPad</code> | 非对齐长度、左右 Pad、Compact、Normal 和 LoopMode | 扫描对齐边界、Pad 长度、步长和维度 | 有效数据与 Pad 区分别满足定义 |
| <code>DataCopyL1ToUB</code> | L1→UB 的两个重载和支持类型 | 为每个签名准备 Tensor、指针和边界长度 | UB 输出与 L1 源逻辑区域一致 |
| <code>DataCachePreload</code> | 合法 GM 指针、预取范围和数据不变性 | 调用预取后使用受控搬运读取同一数据 | 读取值与预取前参考值一致，预取不改写数据 |
| <code>DataCacheCleanAndInvalid</code> | 清理或失效范围和内存一致性 | 在受控写入后调用接口，再从规定可见路径读取 | 数据可见性符合接口语义，目标区域不被错误改写 |

缓存接口若没有直接数值输出，测试以编译可调用性、内存一致性和保护区域
为观察点，不能用“无输出”代替运行时验证。

### 4.5 地址空间和数据通路测试

地址空间测试按照接口清单允许的源和目的组合建立矩阵。每个组合同时检查
编译期限定符和运行时数据方向。

| 数据通路 | 测试重点 | 判定标准 |
| --- | --- | --- |
| GM → UB | MTE2 搬入、连续和多维参数 | UB 有效区域与 GM 源映射一致 |
| UB → GM | MTE3 搬出、尾块和非对齐区域 | GM 目标有效区域正确且保护区域不变 |
| GM → L1 | ND、NZ、DN 及任务支持的转换 | L1 中间数据驱动的下游输出与参考一致 |
| UB → L1 | 连续搬运和样例定义的 ND→NZ 数据流 | L1 布局与参考映射一致 |
| L1 → UB | <code>DataCopyL1ToUB</code> 参数和长度边界 | UB 输出与 L1 逻辑数据一致 |
| UB → UB | 重叠限制、步长和临时区域 | 输出区域按接口定义更新，不改写无关区域 |
| L0C → GM | 格式、量化、激活和类型转换 | GM 输出满足参考格式和精度标准 |

对于接口清单未允许的方向，只建立预期拒绝编译用例，不构造正向运行时
用例。

### 4.6 参数、类型和边界覆盖

参数覆盖以任务书建议范围为基础，并增加对齐、尾块、最小值和多维边界。

| 参数类别 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 搬运长度 | 任务建议长度及对齐边界两侧的合法长度 | 使用 <code>1</code>、<code>32</code>、<code>1024</code>、<code>2048</code> 和接口允许的边界组合 | 只更新定义的有效区域 |
| 输入数值 | 一般有限值和接口支持的类型范围 | 使用确定性生成规则，范围按任务建议或接口合法域设置 | 纯搬运保持字节，转换场景满足精度规则 |
| 数据类型 | <code>half</code>、<code>float</code>、<code>int8_t</code> 及重载支持类型 | 按签名支持矩阵分别编译和执行 | 不发生未定义转换或错误重载 |
| 对齐 | 32 字节对齐、非对齐和尾块 | 在合法边界两侧构造长度和地址偏移 | 数据与 Pad 区正确，保护区域不变 |
| Stride | 源、目的步长和多维步长 | 使用连续、带间隔和维度边界组合 | 每个维度映射到正确地址 |
| Shape | 一维、二维、切片和多维场景 | 按参数结构构造最小、中等和较大合法规模 | 输出容量、布局和元素数量符合参数 |
| 量化参数 | Scalar、Vector、饱和和激活组合 | 使用样例定义的参数类别生成参考结果 | 类型转换、饱和和 ReLU 语义一致 |

| <code>data_copy_pad_gm2ub_ub2gm</code> | 1 | 自定义 Pad 值的非对齐搬运 | <code>SetPadValue</code>、右侧填充 |
| <code>data_copy_pad_gm2ub_ub2gm</code> | 2 | 默认 Pad 值的非对齐搬运 | <code>rightPadding</code> |
| <code>data_copy_pad_gm2ub_ub2gm</code> | 3 | Compact 模式 | 32 字节对齐、Pad |
| <code>data_copy_pad_gm2ub_ub2gm</code> | 4 | LoopMode Compact | 源和目的 Stride |
| <code>data_copy_pad_gm2ub_ub2gm</code> | 5 | LoopMode Normal | Block、Stride、Pad |
| <code>data_copy_pad_gm2ub_ub2gm</code> | 6 | 五维 LoopMode Normal | 多维尺寸、行填充 |
| <code>data_copy_l0c2gm</code> | 1 | Scalar 量化、ReLU 和 ND 输出 | 量化、激活、输出格式 |
| <code>data_copy_l0c2gm</code> | 2 | Vector 量化和 NZ 输出 | 量化参数、输出格式 |
| <code>data_copy_l0c2gm</code> | 3 | Scalar 量化和类型转换 | 输出类型、NZ |
| <code>data_copy_l0c2gm</code> | 4 | Vector 量化、ReLU 和 ND 输出 | 量化、激活 |
| <code>data_copy_l0c2gm</code> | 5 | Scalar 量化和 ND 输出 | 输出类型、格式 |
| <code>data_copy_l0c2gm</code> | 6 | Vector 量化、ReLU 和 NZ 输出 | 量化、激活、格式 |
| <code>data_copy_ub2l1</code> | 1 | UB→L1 连续搬运 | NZ、连续地址 |
| <code>data_copy_ub2l1</code> | 2 | UB 内 ND→NZ 后搬运至 L1 | UB 临时区、同步、布局 |

每个场景分别保留 Tensor 和指针调用版本。场景中的 Mmad、LoadData 或
Fixpipe 只用于使搬运结果形成可比较输出，不计入 DMA 重载覆盖数量。

### 4.8 参考输出和精度判定

参考输出按搬运类型分层生成，避免用一个统一浮点容差掩盖布局或字节错误。

| 场景类型 | 比较方法 | 判定标准 |
| --- | --- | --- |
| 无转换连续搬运 | 比较有效区域的原始字节 | 指针、Tensor 和参考输出逐字节一致 |
| 切片和多维搬运 | 按源坐标到目的坐标的映射比较 | 每个有效元素位于正确目标地址 |
| ND、NZ、DN 转换 | 将输出按目标格式解码后比较逻辑元素 | 逻辑 Shape、分形顺序和元素值一致 |
| Pad | 分开比较有效数据区和填充区 | 有效数据保持不变，填充值和长度符合参数 |
| 量化和类型转换 | 使用样例参考逻辑和数据类型误差规则 | 满足生态算子开源精度标准和类型饱和语义 |
| ReLU | 比较激活前后参考映射 | 负值和非负值按接口定义处理 |
| 缓存接口 | 比较接口调用前后的逻辑数据 | 预取不改写数据，清理或失效满足一致性语义 |

比较器需要同时检查输出容量、有效元素数量和保护区域。只比较部分输出、
只比较均值或只检查程序返回状态不能替代逐元素或逐字节检查。

### 4.9 Pad、格式和多维专项测试

Pad、格式转换和多维搬运具有独立的地址计算风险，需要单独扫描参数边界。

| 专项 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- |
| 左右 Pad | 分别设置左侧、右侧和两侧填充 | Pad 区长度和值符合参数，有效区不偏移 |
| Compact | 使用接口允许的对齐和非对齐组合 | 紧凑输出无缺失、重复或越界元素 |
| Normal | 扫描 block 数、block 长度和 Stride | 每个 block 映射到正确源和目的位置 |
| LoopMode | 覆盖 Compact、Normal 和多维循环 | 循环次数、步长和尾块符合参数 |
| Slice | 扫描起始位置、长度和多个片段 | 输出顺序与切片定义一致 |
| Transpose | 使用非方形和边界维度补充用例 | 行列映射完全一致 |
| Broadcast | 覆盖不同广播维度和重复次数 | 广播元素和值的重复位置正确 |

### 4.10 Tensor 回归和源兼容测试

Tensor 回归用例验证指针扩展没有改变已有调用。测试源代码保持原有
Tensor 类型、参数顺序和显式模板实参。

Tensor 回归至少检查以下内容：

- 原有调用能够编译并唯一匹配预期重载；
- <code>LocalTensor</code> 和 <code>GlobalTensor</code> 的类型推导不变；
- 原有 SFINAE 条件和默认模板参数仍然生效；
- pipe 同步顺序和调用位置不变；
- 运行时输出与参考值一致；
- 指针重载不会造成原有调用歧义；
- 未迁移的官方样例仍可按原方式构建。

判定时，Tensor 回归和指针功能是两个独立条件。指针路径正确不能抵消
Tensor 回归问题。

### 4.11 版本、架构和运行模式测试

版本测试使用相同的接口覆盖表和用例定义，在任务规定的环境组合中执行。

| 维度 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- |
| CANN 9.0.0 | 编译 44 个签名并执行可用功能用例 | 支持范围内的 Tensor 和指针调用符合接口定义 |
| CANN 9.1.0 | 使用同一测试源和参数重新编译执行 | 判定口径与 9.0.0 一致 |
| <code>dav-3510</code> | 覆盖 950 专属多维、DN、Compact 和 LoopMode 场景 | 架构专属功能只在支持范围内进入正向测试 |
| CPU 调试 | 样例支持时用于参数和地址计算检查 | 不能代替 NPU 功能和精度判定 |
| NPU 仿真 | 样例支持时用于流水线和边界检查 | 不能代替真实设备性能观察 |
| NPU 模式 | 执行功能、精度、资源和可选性能测试 | 作为运行时验收的设备结果来源 |

样例 README 中标注的更高 CANN 版本不改变任务书的验收范围。若样例不能
直接用于目标版本，测试需抽取对应 API 调用和参考逻辑建立兼容用例。

### 4.12 构建和执行方法

每个样例目录按相同阶段执行，并确保场景编号、架构和输入生成参数一致。

1. 配置目标 CANN 环境和 <code>dav-3510</code> 架构；
2. 为目标场景创建独立构建目录；
3. 编译 Tensor、指针和适用混合调用版本；
4. 使用样例生成脚本或等价逻辑生成同一输入和参考输出；
5. 执行对应二进制并同步相关执行队列；
6. 使用同一比较器检查两条路径和参考输出；
7. 切换场景、架构或运行模式时使用独立构建缓存；
8. 将签名覆盖映射与功能用例映射分别检查。

构建参数中的场景编号必须与输入生成参数一致。不同路径不得使用不同输入
文件、不同输出容量或不同同步范围。

### 4.13 资源和内存测试

资源测试验证指针适配不会引入任务书禁止的线性额外 Device 拷贝，并检查
所有搬运的地址边界。

测试方法如下：

1. 为源、目的和相邻区域分配带保护区的缓冲；
2. 分别执行 Tensor 和指针路径；
3. 检查有效输出和保护区；
4. 对多个输入规模采集 Device 分配和搬运事件类别；
5. 区分样例自身需要的搬运与指针适配新增的搬运；
6. 重复调用并检查缓冲复用和资源释放边界。

判定标准如下：

- 指针适配不申请与完整输入或输出同规模的额外 Device 副本；
- 指针适配不增加一次完整数据量级的额外搬运；
- 源、目的和临时区域不发生越界访问；
- UB、L1、L0 和 GM 地址范围符合对应参数；
- 重复调用不会造成用例之间的缓冲串写。

### 4.14 性能观察方法

任务书没有硬性性能阈值。性能测试用于识别接口适配引入的额外开销，
不产生独立的验收比例。

性能观察使用相同输入、相同参数、相同设备、相同编译选项、相同预热和
相同设备侧计时范围比较 Tensor 与指针路径。输入生成、Host 分配、编译
和参考输出比较不计入接口执行时间。

性能观察的判定边界如下：

- 性能信息不能替代编译、功能、精度和兼容性判定；
- 不设置任务书之外的固定时延或倍率门槛；
- 若观察到差异，后续分析需保持两条路径的计时范围一致；
- 性能用例可以为空，但 4.13 节的额外搬运和内存要求仍是必测项。

### 4.15 综合判定流程

各测试类别按固定顺序判断，避免运行时用例掩盖编译期遗漏。

1. 核对 5 个 API 名称和 44 个重载的测试映射；
2. 执行合法和预期拒绝编译用例；
3. 执行 Tensor 回归；
4. 执行指针和混合路径功能测试；
5. 执行格式、Pad、多维、量化和缓存专项测试；
6. 执行版本、架构和运行模式测试；
7. 执行资源、内存和边界测试；
8. 按编译、功能、精度、兼容性和资源类别分别判定。

## 五、接口契约与可测性

本节定义测试工程需要保留的接口映射、用例字段和回归关注点。

### 5.1 输入形态契约

每个签名的测试记录需要标明源类型、目的类型、元素类型、参数结构和
地址空间。混合调用只在任务接口范式允许时进入正向矩阵。

| 字段 | 测试用途 |
| --- | --- |
| API 名称 | 关联 5 个 DMA API 家族 |
| 重载编号 | 与 44 行接口清单一一对应 |
| 源入参形态 | Tensor 或硬件指针 |
| 目的入参形态 | Tensor 或硬件指针 |
| 地址空间 | GM、UB、L1、L0 或签名规定空间 |
| 元素类型 | 标记支持类型和转换关系 |
| 参数结构 | 标记 count、Pad、切片、多维、量化或缓存参数 |
| 架构条件 | 标记通用场景或 <code>dav-3510</code> 专属场景 |
| 判定规则 | 编译、字节一致、数值精度、布局或内存一致性 |

### 5.2 用例标识和覆盖关系

测试用例按类别分配稳定标识，便于从接口清单追踪到测试方法。

| 前缀 | 用例类别 |
| --- | --- |
| <code>DMA-COMP</code> | 合法重载编译 |
| <code>DMA-REJECT</code> | 预期拒绝编译 |
| <code>DMA-EQ</code> | Tensor 与指针路径等价 |
| <code>DMA-FMT</code> | 格式转换和多维搬运 |
| <code>DMA-PAD</code> | 非对齐和填充 |
| <code>DMA-CACHE</code> | 缓存接口 |
| <code>DMA-REG</code> | Tensor 回归 |
| <code>DMA-MEM</code> | 内存和边界 |

每个重载至少关联一个 <code>DMA-COMP</code> 用例和一个 Tensor 回归用例。
存在运行时语义的重载还需要关联对应的等价或专项功能用例。

### 5.3 回归关注点

回归测试重点检查以下风险：

- 泛型模板错误接受普通指针或非法地址空间；
- 新增指针候选导致 Tensor 调用出现重载歧义；
- 显式模板参数改变元素类型推导；
- 地址空间信息在辅助函数中丢失；
- SFINAE 条件对指针和 Tensor 路径不一致；
- pipe 属性或同步顺序发生变化；
- 多维参数的 Shape、Stride 和尾块解释不一致；
- Pad 区与有效数据区发生偏移；
- L0C 搬出时量化、激活或格式组合错误；
- 缓存接口误改写逻辑数据；
- 指针适配引入额外全量 Device 副本。
