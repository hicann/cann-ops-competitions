# 需求背景

## 需求来源

CANN 社区任务 aclblasSsbmv A2/A3 算子开发任务。

## 背景介绍

在昇腾 NPU（Atlas 800I A2 / A3，910B3）上使用 Ascend C 开发单精度实数对称带状矩阵-向量乘法算子
`aclblasSsbmv`，完成设计、开发、精度与性能自测全流程，验收通过后合入昇腾算子开源仓 ops-blas
（`blas/sbmv/arch22/`）。

# 需求分析

## 需求描述

实现 `y = alpha * A * x + beta * y`：alpha、beta 为 float32 标量，x、y 为长度 n 的向量（步长
incx/incy 支持正负），A 为 n×n 对称带状矩阵、半带宽 k、列主序存储于 `lda×n`（`lda >= k+1`），
仅存储 uplo 指定三角内的带状部分。

核心功能与参数语义同 cuBLAS `cublasSsbmv`（语义参考 Netlib `ssbmv`）。

## 需求拆解

1. 支持 `uplo = ACLBLAS_FILL_MODE_UPPER / LOWER`；
2. 按对称性引用未存储的另一半带；
3. 支持 `incx / incy` 为任意非零正负整数；
4. 边界语义：`n = 0` 合法 no-op 直接返回 SUCCESS；`alpha = 0` 时不引用 A 与 x，
   `beta = 0` 时不引用原 y；异常码按任务书 §2.4（非法 uplo → `INVALID_ENUM`）；
5. 多核并行，核数取 `GetAivCoreNum()`，**禁止硬编码**；
6. 性能不低于任务书 §3.3 的 4 组标杆（A100 基线 ÷ 0.8）。

# 详细设计

## 算子分析

### 数学公式

`y[i] = alpha * sum_j( A[i][j] * x[j] ) + beta * y[i]`，A 对称（`A = A^T`），仅存 uplo 三角。

### 支持数据类型

float32（real single precision）。

### 支持形状

向量运算，逻辑长度均为 n；矩阵 A 的逻辑形状为 n×n，物理存储 lda×n。
功能范围 n ≤ 8192（任务书约定，更大 shape 不保证功能）。

### 带状索引

存储约定（与 Netlib `ssbmv` 逐位复核一致）：

| uplo | 元素 `M[i][j]` 存于 | 列内索引 t | 对角元位置 |
| --- | --- | --- | --- |
| UPPER | `A[lda*j + (k+i-j)]`，`i <= j <= i+k` | `t = k+i-j` | `t = k` |
| LOWER | `A[lda*j + (i-j)]`，`j <= i <= j+k` | `t = i-j` | `t = 0` |

即 UPPER 时 `aIdx = (k+i-j) + lda*j`（`|i-j| <= k`），LOWER 时 `aIdx = (i-j) + lda*j`。

## 算子实现

### 设计思路与关键决策

**总体思路**：本算子的本质是「带状存储中的每个元素都要被用到两次」——一次作用于它**所在列**对应的输出行
（scatter），一次作用于它**所在行**对应的输出列（mirror，即对称的另一半）。设计的全部取舍都围绕一个目标：
**让这两次使用都落在连续访存上，并且不跨核**。

| # | 决策 | 被否决 / 备选方案 | 选择理由 |
| --- | --- | --- | --- |
| 1 | **行块独占**：输出行按连续块分配给各核，每行只被一个核写 | 按列划分；GM 原子加（`SetAtomicAdd`，仓内 `symv/arch22` 的做法） | 列主序下按列划分会让 y 的同一元素被多个核写，必须原子；GM 原子慢，且破坏「y 每元素只写一次」，in-place（x == y）时跨核竞争无法规避。行块独占则无原子、无 workspace |
| 2 | **以列为访存主轴**（scatter 固定列） | 按行 / 按对角线方向主序访问 | 列主序下**唯一连续的方向就是列方向**；沿行方向步长为 `lda`，每个元素只占 32B 扇区中的 4B，会造成 8× 访存浪费 |
| 3 | **mirror 用「连续 span + `Gather`」** | `DataCopyPad` 多 block 跨步搬运 | 实测多 block 搬运在 UB 侧按 32B datablock 落位、4B 元素无法紧凑打包（约束 1）；而连续 span 恰好就是本算子要读的那块内存 = 访存下界，不增加任何冗余读取 |
| 4 | **把列内移位吸收进 `DataCopyPad` 的 `leftPadding`** | 边界元素用标量 `SetValue` 逐个补 | 向量指令起始地址必须 32B 对齐（约束 5，非对齐运行期报错 507035）；标量补数走 S 流水线逐元素执行，本场景每列最多 7 个、规模下会成为瓶颈；`leftPadding` 对 fp32 恰好可吸收 0..7 任意移位 |
| 5 | **x 按窗口一次性载入 + `Gather` 切** | 每个 t 单独搬一次 x 切片 | 后者每 chunk 产生 `k` 次小 DMA 及跨流水线同步，实测为主要瓶颈；窗口方案使循环内**无 DMA、无同步**，且 scatter 复用同一窗口，x 不二次取回 |
| 6 | **scatter 按批暂存多列**（`segBatch`） | 逐列一进一出队列 | 实测每列成本几乎全在队列的四次旗标操作上，与搬运字节数无关（约束 6），故让一次队列往返服务多列 |
| 7 | **tiling 按值传参；核数、UB 大小运行期查询** | tiling 走 GM 指针 + `aclrtMemcpy`；硬编码核数 | 实测后者每次调用多付 11.08us（直接出局）；仓内 `symv/arch22` 硬编码 8 核，本算子按任务要求**禁止硬编码**，改用 `GetAivCoreNum()` 与 `PlatformAscendCManager` |

> 上述决策中 3/4/5/6 均来自**本机探针实测**而非文档推断，对应约束见「kernel 侧设计」一节。
> 由此得到的两个额外收益：访存量等于内存下界（任务书中「尾部三角 t 上界」「大 k 额外访存」两个风险点
> 在本方案下不存在）；行块自然截断 `iHi`，**尾部三角无需特判**。

### 实现方案

**行块独占**：输出行按连续块分配给各 AIV 核，核 b 独占行 `[r0, r1)`。
**每行只被一个核写** → 不需要原子操作、不需要 workspace、y 的每个元素只写一次，
天然规避了 in-place（x == y）场景下的跨核竞争。

每个存储元素 `A(t, j)` 被使用两次，两次都由「拥有目标行」的核计算：

| 用途 | 公式 | 实现 |
| --- | --- | --- |
| **scatter** | `y[j-k+t] += A(t,j) * x[j]`（UPPER）<br>`y[j+t] += A(t,j) * x[j]`（LOWER） | 固定列时 band 在 GM 上**连续**，该列在本行块内的贡献是一段连续区间；用 `DataCopyPad` 的 `leftPadding` 把这段整体移位到 32B 对齐的累加器偏移上。**列按 `segBatch` 成批暂存**：一轮队列往返连续发 `segBatch` 个 `DataCopyPad`（各占一个 slot、各带自己的 `leftPadding`），一次 `EnQue/DeQue` 后再逐列做 head 修正与 `Axpy` —— 因为实测列的成本几乎全在队列的四次旗标上（见下） |
| **mirror**（对称的另一半） | `y[j] += Σ_t A(t,j) * x[j-k+t]`（UPPER）<br>`y[j] += Σ_t A(t,j) * x[j+t]`（LOWER） | 固定 t 时是沿存储列、步长 lda 的跨步取数：先把该行块需要的 band 区间**连续**装入 UB（span），再用 `Gather`（偏移单位为字节、允许 4B 非对齐）逐 t 取出 |

**访存**：span 恰好覆盖该核需要的全部 band 元素 = 严格内存下界，**零冗余读取**；
因此任务书中「尾部三角 t 上界」「大 k 额外访存」两个风险在本方案下不存在。

**x 的取用**：mirror 每轮 t 的 x 切片逐元素移动一位，若每轮单独搬运会产生 k 次小 DMA
（实测这是主要瓶颈）。改为每 chunk 只搬一次 x 窗口 `[c0-k, c1+k)`（窗口外以 0 补齐，
即 x 的越界下标读到 0），每轮用 `Gather` 从窗口切出，偏移表恒为 `0,1,2,...`，整步退化为一个标量基址
——循环内**无 DMA、无跨流水线同步**。scatter 读同一个窗口，x 不二次取回。

#### host 侧设计

- **tiling 策略**：`blockRows = CeilAlign(ceil(n / coreNum), 8)`；
  `chunkRows` 由 host 按**运行期查询的 UB 大小**反算，满足
  「8 个行尺寸缓冲 + A span `lda*(chunkRows-1)+k+1` + x 窗口 `chunkRows+2k`」的预算；
  大 k 时 chunkRows 自动收缩，极端情况退到 1 行也保持正确。
- **核数**：`min(n, GetAivCoreNum())`，运行期查询，无硬编码。
- **开销控制**：tiling **按值传参**（实测走 GM 指针 + 每次 `aclrtMemcpy` 每调用多付 11.08us，
  直接出局）；host 侧**无分配、无 Host-Device 同步**，单 kernel 下发。
- **in-place**：检测到 `x == y` 时用 `aclrtMemcpyAsync`（D2D）把 x 拷到 handle 自带的 workspace；
  workspace **复用 `GetEffectiveWorkspace(h)`**，不在每次调用中申请/释放。

#### kernel 侧设计

`Init` + `Process` 两阶段，`Process` 内按 chunk 循环（Duplicate 累加器 → 载入 x 窗口 →
`ScatterChunk` → `MirrorChunk` → `FinalizeChunk`）。

**关键实现约束（均为本机实测，非文档推断）**：

| # | 实测结论 | 对策 |
| --- | --- | --- |
| 1 | `DataCopyPad` GM→UB 多 block 搬运，**UB 侧目的地按 32B datablock 落位**，4 字节块无法紧凑打包（实测 4 个 block 落在 UB 偏移 0/8/16/24） | mirror 改用「连续 span + `Gather`」 |
| 2 | `rightPadding` 超过一个 32B 块时**整条搬运静默失效**（不报错、什么都不写，UB 保持原值） | 所有 rightPadding 限制在 32B 之内，缓冲先清零 |
| 3 | 标量写 GM 走每核私有 cache，**两个核写同一条 64B cache line 时，后刷新的核用旧值覆盖整行**，导致跨核丢写（单核不复现） | `incy != 1` 的 y 改走「连续 span 读-改-写」全 DMA 路径，完全不用标量写 GM |
| 4 | band 存储中列被补齐到 lda，存在不属于任何矩阵元素的空槽（UPPER `t<k-j`；LOWER `t>n-1-j`），其乘数越界读为 0，但 **0×Inf = NaN** | 这些 lane **显式清零**，不靠乘 0 屏蔽 |
| 5 | 向量指令起始地址必须 32B 对齐（非对齐在运行期报错 507035） | 用 `leftPadding` 吸收移位，所有向量基址保持 8 元素对齐 |
| 6 | **一次队列往返的成本几乎全在四次旗标操作上，与搬运字节数无关**：探针实测「删掉逐列 DMA 只省 1%」「把双缓冲换成单缓冲反而慢 14%」「scatter 只留循环+标量时耗时从 10.79 降到 5.56us，标量算术仅 15ns/列」 | scatter **按批暂存多列**摊薄旗标（`segBatch` 上限 16，按 UB 的 1/8 额度自动降级） |

**同步设计**：kernel 内缓冲区为手写管理，跨流水线复用全部显式用 `SetFlag/WaitFlag` 成对排序
（含 chunk 之间的标量/MTE3/MTE2/向量四条流水线的收尾屏障）。

**alpha/beta 语义**：

- `alpha == 0`：走 `y = beta*y` 轻量路径，单次 float 乘 → **位精确**（对齐 netlib 的显式分支）；
- `beta == 0`：**不读原 y**（对齐 netlib `Y(I)=ZERO`；否则 `0×NaN=NaN` 会使 Inf/NaN 组行为与 cblas 不一致）；
- alpha 只在末尾对累加器乘一次，不逐元素乘。

### 精度验证

- Golden：**Netlib `cblas_ssbmv`**（生态标准实现，任务书 §3.2 约定 golden 由 cblas 生成）。
- 容差：float32 混合容差 `rtol = 2^-10`、`atol = 2^-16`，逐元素 `|actual-golden| <= atol + rtol*|golden|`；
  用例通过要求 `matched_ratio >= 0.99`。
- 结果：随任务提供的 **1000 条**精度用例经官方脚本 `verify_accuracy.py` 验收：
  **PASS=1000 / FAIL=0**；仓内 GTest **1003/1003** 通过，连续多遍结果一致。
- 特殊值组（`RANDOM_EXTREME` / Inf / NaN 填充）：逐元素 NaN/Inf 图案与参考实现不可能一致——
  band 值接近 `FLT_MAX` 时乘积溢出，溢出后相消的结果依赖求和顺序。
  实测 `TC_FL_124` 第 13 行：double 精确和为 +3.32e38（有限），参考实现给出 -Inf、本算子给出 +Inf。
  故该组按「边界不越界」判定：golden 有限的元素必须有限且落在容差内；golden 饱和的元素必须保持饱和。
  该判据仍能检出越界读、脏缓冲、未初始化累加器等问题。

### 性能验证

口径：任务书 §3.3（warmup 后有效采样 >50 次取平均）。实测本机 910B3、CANN 9.1.0，
warmup 50 次后连续下发 500 次取平均：

| case | n | k | uplo | 本算子(us) | 标杆(us) | 倍率 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1024 | 16 | UPPER | **8.32** | 13.57 | **1.632** |
| 2 | 2048 | 32 | UPPER | **12.85** | 24.67 | **1.920** |
| 3 | 1024 | 16 | LOWER | **8.32** | 14.41 | **1.733** |
| 4 | 4096 | 64 | UPPER | **23.14** | 47.74 | **2.063** |

21 轮独立复测（每轮 500 次采样）组内波动 < 0.5%；设备侧 `msprof` 交叉验证 kernel 时长
8.60 / 13.04 / 8.56 / 22.80 us（Block Num 32 / 37 / 32 / 40），与上表一致。

**优化过程（先定位、再按占比改，每轮只改一个变量）**：

| 轮次 | 改动 | 结果 |
|---|---|---|
| 0 基线 | 行块 + 列连续 scatter + span/Gather mirror | 13.93 / 23.16 / 14.19 / 39.61 |
| 1 | mirror 的 x 操作数改为「每 chunk 一次 x 窗口 + `Gather`」，循环内再无 DMA 与跨流水线同步 | -16~21% |
| 2 | 向量指令融合（`Muls`+`Add`→`Axpy`；`Mul`+`Add`→`MulAddDst`） | 再降 8~10% |
| 3 | **scatter 按批暂存多列**，摊薄队列旗标 | 再降 19~23% |
| 4 | 按 codecheck 拆分 `ScatterChunk`（纯函数抽取，附带小幅提速） | 再降 1~4% → **8.32 / 12.85 / 8.32 / 23.14** |

第 3 轮的归因来自四个实测探针（均推翻了直觉假设）：删掉逐列 DMA 只省 **1%**（搬运字节不是瓶颈）；
把 `segQueue` 双缓冲换成普通 TBuf + 全量同步反而 **慢 14%**（重叠被打断才是伤害）；
span 分片加倍、队列深度 2→4 均无变化；**scatter 只保留列循环与标量计算时耗时从 10.79 降到 5.56us**
（标量算术仅 15ns/列）—— 由此判定列成本几乎全在队列的四次旗标操作上，故让一次队列往返服务多列。

**固定开销地板**：`msprof` 实测空 kernel 约 2.84~4.0us，对 n=1024 的 case 占约 40%，
是任务书标杆下不可再压缩的部分。

## 算子约束限制

1. 功能范围 n ≤ 8192（任务书约定）；
2. 仅支持 float32；
3. 要求 `lda >= k+1`、`incx != 0`、`incy != 0`，不满足时返回 `INVALID_VALUE`；
4. `A`、`x` 仅在 `n > 0 且 alpha != 0` 时必须非空。
