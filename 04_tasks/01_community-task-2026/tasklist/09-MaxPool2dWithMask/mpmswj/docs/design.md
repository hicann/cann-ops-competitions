本文定义 MaxPool2dWithMask 的测试对象、测试内容、测试方法和判定标准。
测试设计依据任务书、算子描述、测试用例和 golden 函数。

| 项目 | 内容 |
| --- | --- |
| 任务名称 | 9月社区任务：MaxPool2dWithMask 算子开发 |
| 算子接口 | <code>MaxPool2dWithMask</code> |
| 目标硬件 | Atlas 800T A2、Atlas 300V Pro |
| 目标软件 | CANN 9.0.0 或 CANN 9.1.0 |
| 开发语言 | Ascend C |
| 输入数据类型 | <code>float</code>、<code>float16</code>、<code>bfloat16</code> |

| 测试资料 | 任务书、算子描述、测试用例和 golden 函数 |

## 一、需求背景

本节说明 MaxPool2dWithMask 算子的任务来源、功能定位、接口特点和验收
背景，为后续测试需求拆解提供依据。

### 1.1 任务来源

社区任务要求参考 <code>aclnnMaxPool2dWithMask</code> 的接口说明，在
昇腾 NPU 上使用 Ascend C 开发功能一致的算子，并将算子纳入
<code>ops-nn</code> 的 pooling 类算子目录。验收范围不仅包含固定用例的
功能和精度，还包含合法参数组合的泛化能力及目标设备上的性能要求。

任务提供算子描述、用例集合和 golden 函数。算子描述规定输入输出类型及
属性形式；用例集合给出需要覆盖的 Shape、数据类型和典型参数组合；
golden 函数定义输出 Shape、池化结果和索引容器的参考生成方式。测试设计
需要同时约束这三类资料，避免只验证数值而遗漏接口或布局。

### 1.2 算子功能背景

MaxPool2dWithMask 对输入的每个批次和通道独立执行二维最大池化。窗口由
<code>kernelSize</code> 指定，并按照 <code>stride</code> 在空间维度移动；
<code>padding</code> 对输入边界补充负无穷语义；
<code>ceilMode</code> 决定输出 Shape 使用向上还是向下取整。

算子产生两个相互关联的输出：

- <code>out</code> 保存每个池化窗口的最大值，数据类型与输入一致；
- <code>indices</code> 保存最大值在输入通道空间内的位置，其逻辑语义为
  <code>int32 argmax</code>，物理输出类型为 <code>int8</code> 容器。

因此，一个输出位置的验证不能只比较 <code>out</code>。测试还必须确认
<code>indices</code> 指向同一个最大值位置，并验证并列最大值、通道独立
和容器编码等语义。

### 1.3 双输出和布局背景

<code>out</code> 的空间维度由输入尺寸、窗口、步长、填充、膨胀和取整
方式共同决定。<code>indices</code> 的 Shape 又依赖
<code>H_out * W_out</code>、窗口面积和 16 元素分组规则。Shape 计算错误
会同时影响输出容量、有效索引数量和容器尾部区域。

任务书允许 <code>out</code> 使用非连续 Tensor，而 <code>indices</code>
不支持非连续 Tensor。测试需要分别检查逻辑 Shape 和物理存储，确保
非连续 <code>out</code> 按物理步长写入，连续
<code>indices</code> 按规定容器布局写入，并且两个输出均不越界。

任务用例按 ND 格式组织，任务书同时声明 NCHW、ND 输出表达。测试需要按
对应格式解析逻辑维度，不能将物理排布差异误判为池化计算差异。

### 1.4 泛化和验收背景

任务要求算子支持合法输入泛化。测试不能依赖单一网络 Shape、固定窗口
或固定通道数，需要覆盖 3D 和 4D 输入、小中大空间尺寸、不同批次和通道、
不同窗口及步长组合，以及输出元素数量跨越索引分组边界的场景。

验收环境覆盖 Atlas 800T A2、Atlas 300V Pro，以及 CANN 9.0.0 或
CANN 9.1.0。<code>bfloat16</code> 只在 Atlas 800T A2 上支持；
Atlas 推理系列在 <code>ceilMode=true</code> 时存在步长限制；Atlas 训练
系列的 <code>float</code> 输入存在转换计算带来的精度约束。测试需要按
设备支持矩阵组织用例，不能使用一种设备的结论替代另一种设备的判定。

任务还规定 Ascend C 实现与 TBE 基线的性能关系。性能测试需要与功能和
精度测试分开判定，并使用相同 Shape、数据类型、属性、设备和计时范围
进行比较。

## 二、需求分析

本节提取需要验证的可观察行为，并将其转换为测试方法和判定标准。测试
需求从功能语义、接口参数、Shape、索引、泛化、设备兼容和验收指标等
方面拆分。

### 2.1 功能需求分析

功能测试需要同时验证池化值、索引位置和确定性。三个对象使用不同的比较
方法，不能共用单一浮点容差。

| 需求维度 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 池化功能 | 每个窗口的最大值和边界填充语义 | 使用 golden 函数逐位置生成参考值并与设备输出比较 | 池化值满足对应数据类型的精度标准 |
| 索引功能 | 每通道 <code>int32 argmax</code>、并列最大值和小端编码 | 构造最大值位置、并列值和多通道输入，解析 <code>int8</code> 容器 | 有效索引逐元素精确一致，容器 Shape 符合公式 |
| 边界窗口 | 窗口部分落在 padding 区域时的有效元素选择 | 将最大值分别放在输入边缘和窗口四角 | 只从有效输入和负无穷填充语义中选取最大值 |
| 负值窗口 | 窗口内所有有效值均为负数 | 构造全负有限输入并生成参考结果 | 最大负值被正确选中，不被零替换 |
| 通道独立 | 不同通道拥有不同最大值和索引 | 为各通道设置不同的最大值位置 | 每个通道独立输出，不发生索引串扰 |
| 批次独立 | 不同批次使用不同输入模式 | 分批次生成参考值并比较 | 每个批次只对应自身输入 |
| 确定性 | 相同输入和属性的重复调用 | 固定输入构造和执行条件，多次比较两个输出 | 每次池化值和索引保持一致 |

### 2.2 接口和参数需求分析

算子包含一个必选输入、四个必选列表属性、一个可选布尔属性和两个输出。
测试需要验证属性规范化后的空间语义。

| 接口项 | 需求含义 | 测试重点 | 判定标准 |
| --- | --- | --- | --- |
| <code>x</code> | 浮点输入 Tensor | 3D/4D Shape、批次、通道、空间尺寸和数据类型 | 输入按对应维度和类型解释 |
| <code>kernelSize</code> | 最大池化窗口 | 长度 1、长度 2、正数和非对称窗口 | 合法列表映射到正确的高宽窗口 |
| <code>stride</code> | 窗口移动步长 | 空列表默认值、长度 1、长度 2 及非对称步长 | 默认和扩展规则符合接口定义 |
| <code>padding</code> | 输入四周的负无穷填充 | 零填充、合法正填充、单值和双值表达 | 边界窗口和 Shape 推导正确 |
| <code>dilation</code> | 窗口内部元素间距 | 正向值 1 和其他值的约束场景 | 只有任务支持值进入正向测试 |
| <code>ceilMode</code> | 输出 Shape 的取整模式 | 默认值、<code>false</code>、<code>true</code> 和设备限制 | 使用对应取整公式和末端窗口规则 |
| <code>out</code> | 池化值输出 | 类型、Shape、数值和非连续存储 | 与输入类型及参考结果一致 |
| <code>indices</code> | 最大值索引容器 | Shape、有效字节、小端编码和尾部区域 | 有效索引及容器布局完全一致 |

列表属性的单元素形式需要扩展到高、宽两个空间维度；双元素形式分别作用于
高和宽。测试需要使用非对称参数发现错误的维度复用，不能只使用
<code>[k,k]</code>、<code>[s,s]</code> 和 <code>[p,p]</code>。

### 2.3 Shape 需求分析

<code>out</code> 和 <code>indices</code> 的 Shape 都是功能契约的一部分。
Shape 测试需要独立于数值测试执行。

| Shape 对象 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 3D <code>out</code> | <code>[C,H_out,W_out]</code> | 使用 3D 输入计算参考空间尺寸 | 输出保持 3D 层级且各维长度一致 |
| 4D <code>out</code> | <code>[N,C,H_out,W_out]</code> | 使用多批次、多通道输入 | 批次、通道和空间维度一致 |
| <code>ceilMode=false</code> | 向下取整的空间尺寸 | 构造整除和有余数场景 | 按 floor 公式计算 |
| <code>ceilMode=true</code> | 向上取整及末端窗口修正 | 构造末端窗口越过有效起点的场景 | 按 ceil 公式并应用末端规则 |
| <code>indices</code> | 窗口面积和 <code>mask_w</code> | 扫描不同窗口及输出元素数量 | 所有维度与容器公式完全一致 |
| 分组边界 | <code>H_out*W_out</code> 跨越 16 的倍数 | 构造边界两侧的输出规模 | <code>mask_w</code> 分组数计算正确 |

Shape 比较使用整数精确比较，不适用浮点误差。输出缓冲区必须按参考 Shape
分配，避免容量过大掩盖 Shape 推导错误。

### 2.4 索引语义需求分析

<code>indices</code> 不是普通的逐元素 <code>int8</code> 索引数组。测试
需要按其逻辑和物理两层语义解析。

逻辑层面，每个输出位置对应一个通道内输入空间线性索引
<code>i_h * W_in + i_w</code>。索引不包含批次或通道偏移，不同通道独立
计算。窗口内存在相同最大值时，严格大于更新规则要求保留行优先扫描中
最先遇到的位置。

物理层面，逻辑索引以小端 <code>int32</code> 字节写入
<code>int8</code> 容器。测试需要分别检查：

- 有效索引数量与 <code>H_out * W_out</code> 一致；
- 每个逻辑索引的 4 个字节按小端顺序解析；
- 容器 Shape 中的窗口面积维和 <code>mask_w</code> 正确；
- 有效字节之外的容器区域符合参考模型约定；
- 索引值位于对应通道输入空间的合法范围内；
- 索引位置对应的输入值与 <code>out</code> 值满足同一窗口最大值语义。

### 2.5 泛化需求分析

任务书明确要求使用泛化数据验收，因此任务用例集合是基础覆盖，不是全部
输入空间。补充测试需要系统改变以下维度：

| 泛化维度 | 覆盖内容 | 判定目标 |
| --- | --- | --- |
| 输入维度 | 3D、4D | 两种维度层级均正确 |
| 批次和通道 | 1、大于 1、非典型通道数 | 不依赖固定 N、C |
| 空间尺寸 | 小尺寸、常用网络尺寸、非对齐尺寸和长宽不等 | 不依赖固定 H、W |
| 窗口 | 小窗口、大窗口、正方形和合法非对称窗口 | 不依赖固定窗口面积 |
| 步长 | 小于、等于窗口及合法非对称步长 | 输出位置映射正确 |
| 填充 | 零、正值、对称和合法非对称填充 | 边界处理与 Shape 一致 |
| 取整 | floor、ceil、整除和有余数 | 输出尺寸及末端窗口正确 |
| 数据分布 | 随机有限值、全负值、重复最大值和结构化边界值 | 数值和索引语义稳定 |

泛化用例需要在任务支持范围内组合参数，同时控制组合数量，确保每个新增
用例对应明确的风险和判定目标。

### 2.6 数据类型、设备和版本需求分析

数据类型和设备支持范围影响正向用例选择及精度口径。

## 四、测试设计与判定标准

本节说明测试环境、参考计算、用例覆盖、执行步骤和各专项的判定口径。

### 4.1 测试环境和工具

测试环境按任务书的软硬件范围配置，测试工具使用任务目录提供的用例和
参考函数。

| 项目 | 测试配置 |
| --- | --- |
| 设备 | Atlas 800T A2、Atlas 300V Pro |
| CANN | CANN 9.0.0、CANN 9.1.0 |
| 编程语言 | Ascend C |
| 输入和用例格式 | 任务用例按 ND 组织；按任务书声明补充输出的 ND、NCHW 布局测试 |
| 参考函数 | <code>max_pool2d_with_mask_golden_func.py</code> |
| 用例定义 | <code>max_pool2d_with_mask_cases.json</code> |
| 算子描述 | <code>max_pool2d_with_mask_op.json</code> |

测试执行器需要能够完成以下操作：

- 读取用例中的输入 Shape、数据类型和属性；
- 按设备支持矩阵筛选正向用例；
- 编译并执行目标算子；
- 读取 <code>out</code> 和 <code>indices</code> 的有效输出区域；
- 使用统一比较器检查数值、整数索引、Shape 和内存边界。

### 4.2 参考模型和比对对象

参考模型用于生成池化值、索引、输出 Shape 和索引容器 Shape。参考模型与
被测算子使用同一组输入属性，但参考模型不得替代目标设备上的算子执行。

#### 4.2.1 池化值

对每个批次、每个通道和每个输出空间位置，按窗口的行优先顺序扫描：

$$
out[n,c,h,w] =
\max_{m,n'} input[n,c,s_h h-p_h+m,s_w w-p_w+n']
$$

超出输入空间范围的位置按负无穷参与比较。输入准备只使用任务书允许的
有限值，不使用 NaN 或负无穷作为正向输入。

#### 4.2.2 输出 Shape

输入为 4D 时按 <code>[N,C,H,W]</code> 解释，输入为 3D 时按
<code>[C,H,W]</code> 解释。<code>kernelSize</code>、<code>stride</code>
和 <code>padding</code> 先规范化为两个空间维度，<code>dilation</code>
按任务书约束取 1。

当 <code>ceilMode=false</code> 时，空间输出尺寸按下式计算：

$$
H_{out} =
\left\lfloor
\frac{H_{in}+2p_h-(k_h-1)-1}{s_h}
\right\rfloor+1
$$

$$
W_{out} =
\left\lfloor
\frac{W_{in}+2p_w-(k_w-1)-1}{s_w}
\right\rfloor+1
$$

当 <code>ceilMode=true</code> 时使用向上取整，并按参考函数处理末端窗口
边界。3D 和 4D 输出分别保持输入的维度层级。

#### 4.2.3 索引容器

每个通道独立保存输入空间位置的线性索引：

$$
argmax=i_h \times W_{in}+i_w
$$

窗口内出现相同最大值时，索引取行优先扫描顺序中最先出现的位置。
逻辑索引为 <code>int32</code>，按小端字节序写入 <code>int8</code> 容器。
每个有效输出位置占用 4 个字节，容器的其余区域按参考函数定义检查。

设

$$
mask_w =
\left(\left\lceil\frac{H_{out}W_{out}}{16}\right\rceil+1\right)
\times 2 \times 16
$$

则 4D 输入的 <code>indices</code> Shape 为
<code>[N,C,k_h*k_w,mask_w]</code>，3D 输入的 <code>indices</code> Shape
为 <code>[C,k_h*k_w,mask_w]</code>。

### 4.3 精度用例覆盖

精度测试覆盖任务用例文件中的全部正向用例，并使用补充用例覆盖任务
书要求的合法泛化场景。

| 测试维度 | 将测试什么 | 怎么测试 |
| --- | --- | --- |
| 输入维度 | 3D 和 4D 输入，批次和通道的独立计算 | 对每个维度组织相同属性的输入，分别检查输出维度和通道结果 |
| 数据类型 | <code>float</code>、<code>float16</code>、<code>bfloat16</code> | 为每种类型配置等价属性；<code>bfloat16</code> 只在 Atlas 800T A2 上安排正向测试 |
| 窗口组合 | <code>k=2,s=2,p=0</code>、<code>k=3,s=1,p=1</code>、<code>k=3,s=2,p=1</code>、<code>k=7,s=2,p=3</code> | 逐组读取任务用例，比较池化值和索引 |
| 输入规模 | 小、中、大及长空间尺寸，覆盖索引容器分组边界 | 使用任务用例规模，并补充跨越 16 元素分组边界的合法规模 |
| 输出对象 | <code>out</code> 和 <code>indices</code> | 分别解析浮点输出和 <code>int32</code> 索引，不能只比较池化值 |

补充的合法参数测试至少覆盖以下组合：

- <code>kernelSize</code> 使用单元素列表和双元素列表；
- <code>stride</code> 使用空列表、单元素列表和双元素列表；
- <code>padding</code> 使用单元素列表和双元素列表，并覆盖零填充、对称填充及合法
  的非对称填充；
- <code>ceilMode</code> 使用 <code>false</code> 和 <code>true</code>，并覆盖输出尺寸整除和有余数的情况；
- 输入空间尺寸小于、等于和大于窗口尺寸的合法组合；
- 批次为 1 和大于 1、通道为 1 和大于 1 的组合；
- <code>dilation=1</code> 的正向组合。

Atlas 推理系列的 <code>ceilMode=true</code> 测试只选择任务书允许的步长
组合。任务书明确不支持的步长组合归入约束测试，不归入正向精度测试。

### 4.4 参数和边界测试方法

参数测试将合法组合和不支持组合分开。合法组合用于验证算子计算，
不支持组合用于验证接口边界，二者使用不同的判定口径。

| 场景 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- |
| <code>kernelSize</code> | 测试长度为 1 或 2 且元素为正数的组合，并构造其他长度或非正值组合 | 合法组合按两个空间维度解释；其他组合按接口约束处理 |
| <code>stride</code> | 测试空列表、单元素列表、双元素列表和不支持的组合 | 空列表使用 <code>kernelSize</code>；单元素列表扩展到两个空间维度；非法组合不作为正向输入 |
| <code>padding</code> | 测试长度为 1 或 2 的零填充、对称填充和合法非对称填充 | 元素满足非负且不超过窗口约束；越界组合按接口约束处理 |
| <code>dilation</code> | 测试值为 1，并单独准备其他值的约束用例 | 值为 1 进入正向测试；其他值不得被当作正向支持 |
| <code>ceilMode</code> | 分别测试 <code>false</code>、<code>true</code> 及末端窗口场景 | 输出 Shape 和末端处理与参考模型一致 |
| 特殊值 | 使用有限输入，并排除 NaN、负无穷 | 不以不支持的特殊值推导正向功能标准 |
| 并列最大值 | 在窗口内设置多个相同最大值 | <code>indices</code> 选择行优先扫描中最先出现的位置 |
| 边界最大值 | 让最大值位于窗口四个角和输入边界 | 池化值和线性索引均符合窗口有效区域 |
| 负值输入 | 使用全部为负的有限候选值 | 不得把负值错误替换成零或填充值 |
| 通道独立性 | 为不同通道设置不同的最大值位置 | 每个通道的池化值和索引独立计算 |
| 重复执行 | 使用相同输入、属性和执行条件重复调用 | 每次 <code>out</code> 和 <code>indices</code> 完全一致 |

### 4.5 非连续输出和内存边界测试

任务书允许 <code>out</code> 使用非连续 Tensor，<code>indices</code> 按连续
<code>int8</code> 容器组织。测试分别检查逻辑 Shape、物理步长、有效区域
和边界外区域。

测试按以下方式执行：

1. 为 <code>out</code> 准备连续存储和带合法物理步长的非连续存储；
2. 为 <code>indices</code> 按容器 Shape 分配连续 <code>int8</code> 存储；
3. 在有效输出区域周围设置保护区域；
4. 执行算子并读取逻辑有效区域；
5. 检查保护区域、容器尾部和相邻存储是否保持约定状态。

判定时，连续和非连续 <code>out</code> 的逻辑结果必须一致，物理步长解析
必须与 Tensor 描述一致，算子不得越界写入保护区域。

### 4.6 精度测试方法

精度测试使用任务用例中的属性和补充用例中的合法参数，按以下步骤执行：

1. 读取输入 Shape、数据类型和属性参数；
2. 按固定规则生成有限输入，并为边界、并列最大值和通道独立性准备
   专项输入；
3. 调用 golden 函数生成参考 <code>out</code>、<code>indices</code> 和输出 Shape；
4. 根据参考 Shape 分配被测算子的输出；
5. 在目标设备执行 MaxPool2dWithMask，并在读取结果前同步对应执行队列；
6. 检查输出 Shape、<code>indices</code> 容器 Shape、元素数量和有效存储范围；
7. 分别解析 <code>out</code> 和 <code>indices</code>，按 4.7 节的标准比较。

参考函数中的 3D 输入扩展为内部批次表示，比较时恢复为 3D 输出。
索引比较必须先按小端字节序解析有效 <code>int32</code> 区域，不能将
<code>int8</code> 容器直接作为浮点结果比较。

### 4.7 精度判定标准

浮点输出 <code>out</code> 使用逐元素相对误差和绝对误差比较：

$$
|actual-golden| \leq atol+rtol \times |golden|
$$

判定参数如下：

| 输出 | 比较方法 | 判定标准 |
| --- | --- | --- |
| <code>out</code> | 按输入数据类型逐元素比较池化值 | 任务用例使用 <code>rtol=0.001</code>、<code>atol=0.001</code>；补充用例使用生态算子开源精度标准 |
| <code>indices</code> | 将有效字节解析为小端 <code>int32</code> 后逐元素比较 | 相对误差和绝对误差均为 0，索引必须精确一致 |
| <code>out</code> Shape | 比较逻辑 Shape | 与参考模型按输入维度和属性推导的 Shape 完全一致 |
| <code>indices</code> Shape | 比较容器 Shape | 与 <code>mask_w</code> 公式和输入维度完全一致 |
| 索引容器 | 检查有效字节和约定尾部区域 | 有效索引编码正确，未使用区域符合参考模型约定 |

Atlas 800T A2 上的 <code>bfloat16</code> 按该数据类型的输出语义比较。
Atlas 训练系列的 <code>float</code> 测试按任务书规定考虑计算转换带来的精度
要求。

### 4.8 性能测试方法

性能测试与功能测试使用一致的输入属性和输出规模，将 Ascend C 实现与
TBE 基线放在相同设备、CANN 版本、编译选项和运行模式下比较。

性能测试按以下步骤执行：

1. 选择任务书规定的性能场景及具有代表性的合法补充规模；
2. 为 Ascend C 和 TBE 准备相同的输入、数据类型和属性；
3. 分别完成编译、初始化和必要的内存准备；
4. 使用相同的预热策略排除首次初始化影响；
5. 使用相同的设备侧计时范围和采样次数采集算子耗时；
6. 使用相同统计方法计算时延比或吞吐率比；
7. 对小 Shape 的 100 微秒以下场景单独检查专项条件。

计时范围只包含被测算子对应的设备侧执行时间，不把输入生成、Host 分配、
编译、首次初始化和结果比较计入算子耗时。

### 4.9 性能判定标准

性能按任务书规定的设备基线和专项条件判断：

| 设备或场景 | 判定标准 |
| --- | --- |
| Atlas 800T A2 | Ascend C 实现性能不低于 TBE 基线的 95%；用吞吐率比较时，吞吐率比不低于 0.95，用时延比较时使用等价口径 |
| Atlas 800T A2 小 Shape | 对低于 100 微秒的场景，若 Ascend C 时延超过 TBE 基线 30%，执行性能仿真和原因分析 |
| Atlas 300V Pro | 以 Atlas 800T A2（910B3）对应耗时的 5 倍作为参考；超过该参考值 30% 时执行性能仿真和原因分析 |
| 计时有效性 | 两种实现的计时范围、同步方式、输入属性、预热策略和采样口径一致 |

性能判定不能替代功能、精度、参数约束和内存边界判定。

用例按照功能语义、参数维度、数据类型、布局和性能目标分组。每个用例
只属于一个主判定组，同时可以关联多个覆盖维度。

| 用例分组 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 任务基线用例 | 任务用例文件定义的全部正向场景 | 逐条读取输入描述、属性和输出描述，生成参考值并执行算子 | 每条用例均检查 <code>out</code>、<code>indices</code>、Shape 和有效区域 |

| 泛化用例 | 不依赖固定 Shape、窗口或通道数的合法输入 | 使用未出现在任务基线中的合法组合扩展测试 | 合法参数均按接口语义计算 |
| 约束用例 | 非法属性和设备不支持的参数组合 | 在调用前单独标记为约束用例，检查接口处理 | 不支持组合按接口约束处理，不混入正向精度判定 |
| 布局用例 | 连续、非连续 <code>out</code> 及 <code>indices</code> 容器布局 | 使用不同物理步长和保护区域执行并解析有效区域 | 逻辑结果一致，边界外存储不被改写 |
| 性能用例 | 任务书规定的设备性能场景和补充规模 | 以相同输入、属性和计时范围对比 TBE | 满足 4.9 节的设备倍率和专项条件 |

### 4.11 输入构造和 golden 策略

输入生成只定义输入的构造规则，不在设计文档中保存具体输入数组、
输出数组或运行数据。

| 构造类型 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| 有限随机输入 | 一般池化计算、不同数据类型和不同 Shape | 使用固定随机规则生成任务允许范围内的有限值 | 输出值按数据类型精度标准比较 |
| 边界位置输入 | 最大值位于窗口边缘、输入边缘和填充邻域 | 使用结构化构造将最大值放置在指定窗口位置 | 池化值和线性索引均指向有效位置 |
| 并列最大值输入 | 并列最大值时的确定性索引 | 在同一窗口设置多个相同最大值，保持其他条件不变 | 选择行优先扫描顺序中的首个最大值 |
| 负值输入 | 负数参与最大值比较的语义 | 生成全部候选值为负的有限窗口 | 结果不被零或填充语义错误替换 |
| 多通道输入 | 通道维度独立性 | 为不同通道配置互不相同的最大值位置 | 各通道 <code>out</code> 和 <code>indices</code> 独立一致 |
| 多批次输入 | 批次维度独立性 | 为不同批次配置独立输入并分别解析输出 | 各批次结果与对应参考值一致 |
| 类型边界输入 | <code>float</code>、<code>float16</code>、<code>bfloat16</code> 的转换和比较 | 使用同一逻辑输入按目标类型转换后分别执行 | 类型转换符合精度标准，索引不因类型改变 |
| 重复输入 | 确定性计算 | 固定生成规则、属性和执行条件，重复调用 | 同一条件下 <code>out</code> 和 <code>indices</code> 完全一致 |

golden 计算按以下顺序组织：

1. 规范化 <code>kernelSize</code>、<code>stride</code> 和 <code>padding</code> 的维度表达；
2. 根据 <code>ceilMode</code> 计算空间输出尺寸；
3. 对每个批次和通道扫描有效窗口；
4. 使用严格大于比较保留首个最大值；
5. 将空间坐标转换为通道内线性索引；
6. 按索引容器布局写入小端 <code>int32</code> 字节；
7. 输出参考值、输出 Shape 和容器 Shape。

golden 生成逻辑需要与
<code>max_pool2d_with_mask_golden_func.py</code> 的输入输出约定一致。
测试程序不得修改参考值、跳过索引比较或更改 Shape 公式以放宽判定。

设备和软件测试用于确认支持矩阵内的功能、精度和接口行为具有一致的
判定口径。设备不支持的组合单独分类，不把它们作为正向用例。

| 测试维度 | 将测试什么 | 怎么测试 | 用什么标准判断 |
| --- | --- | --- | --- |
| Atlas 800T A2 | <code>float</code>、<code>float16</code> 和 <code>bfloat16</code> | 在 A2 上分别编译并执行对应数据类型的功能用例 | 支持类型满足功能、精度、Shape 和索引标准 |

兼容性测试需要保留用例定义中的设备、软件版本、数据类型和属性字段，
使同一测试可以在不同支持环境中按相同规则重新执行。

### 4.13 异步执行和多次调用测试

异步测试检查算子在执行队列中的依赖关系和输出生命周期。测试程序只在
需要读取结果时同步对应执行队列，不用 Host 调用返回顺序代替设备执行
顺序。

测试按以下场景组织：

1. 在同一执行队列连续提交不同输入和属性的调用；
2. 在结果读取前同步该调用对应的执行队列；
3. 在不同执行队列提交相互独立的输入和输出；
4. 重复使用相同输出布局执行多轮调用；
5. 在调用之间更换输入、输出和属性对象，检查对象关联关系；
6. 在连续和非连续 <code>out</code> 场景分别执行上述调用。

判定标准如下：

- 每个调用只写入自己声明的输出区域；
- 同一执行队列保持提交顺序对应的数据依赖；
- 不同执行队列的独立调用不发生输入或输出串扰；
- 读取结果前完成对应队列同步；
- 多轮调用的 Shape、池化值和索引均符合各自参考模型；
- 调用结束后不遗留影响后续用例的输出存储状态。

### 4.14 资源和非法访问测试

资源测试关注输出容量、物理布局和边界访问，不引入任务书之外的独立性能
指标。测试覆盖正常输出、尾块输出、非连续输出和索引容器尾部。

测试按以下步骤执行：

1. 按参考 Shape 和容器 Shape 分配 <code>out</code>、<code>indices</code>；
2. 在输出前后设置可检查的保护区域；
3. 对 <code>out</code> 设置连续和合法非连续物理步长；
4. 对 <code>indices</code> 分配完整连续 <code>int8</code> 容器；
5. 执行算子并同步后检查有效区域、保护区域和容器尾部；
6. 重复分配、执行和释放，检查后续用例的资源隔离。

资源判定标准如下：

- 输出有效区域内的数据与参考模型一致；
- <code>out</code>、<code>indices</code> 和保护区域之间没有越界写入；
- <code>indices</code> 的容器容量覆盖其定义的 Shape；
- 非连续 <code>out</code> 的物理步长与逻辑索引解析一致；
- 输入输出缓冲区按用例独立使用，不因多次调用发生串写；
- 资源检查不以缩小输出容量、跳过尾块或跳过非连续场景代替正向测试。

### 4.15 综合执行顺序

测试执行器按固定顺序组织各类用例，使功能、约束、性能和资源测试具有
独立的输入准备和判定口径。

1. 读取任务书、算子描述和用例定义；
2. 建立设备、CANN 版本、数据类型和格式的支持矩阵；
3. 为每条正向用例生成输入、参考值和输出描述；
4. 先执行编译期接口检查，再执行设备功能和精度测试；
5. 执行 Shape、索引编码、边界、非连续输出和确定性测试；
6. 单独执行非法属性和设备不支持组合的约束测试；
7. 在功能条件满足后，按统一计时范围执行性能测试；
8. 汇总各用例的判定项，按功能、精度、约束、资源和性能分别判断。

## 五、接口契约与可测性

本节列出测试需观察的接口行为和可重复执行条件。

### 5.1 输入、属性和输出契约

输入、属性和输出按照任务书及算子描述组织测试：

| 项目 | 测试契约 |
| --- | --- |
| 输入 <code>x</code> | 测试 3D/4D 空间布局，以及任务支持的浮点数据类型 |
| <code>kernelSize</code> | 长度为 1 或 2，元素为正数 |
| <code>stride</code> | 空列表使用窗口尺寸，单元素列表扩展到两个空间维度，双元素列表按维度使用 |
| <code>padding</code> | 长度为 1 或 2，元素满足非负和窗口约束 |
| <code>dilation</code> | 正向只测试值 1 |
| <code>ceilMode</code> | 测试向下取整和向上取整，并遵守设备限制 |
| <code>out</code> | 数据类型与输入一致，检查逻辑 Shape、数值和非连续存储 |
| <code>indices</code> | <code>int8</code> 容器承载每通道独立的 <code>int32 argmax</code>，检查编码和容器 Shape |

### 5.2 用例可追踪性和可重复性

每个测试用例至少保留以下可复现输入定义：用例标识、输入 Shape、数据
类型、属性、目标设备、参考函数入口和比较规则。

测试程序使用固定的输入生成规则；专项边界用例使用明确的构造逻辑。
测试执行不得依赖未声明的随机状态、不同的输出解析方式或不同的计时
范围。

### 5.3 回归关注点

回归测试围绕以下风险重复执行：

- 3D 输入被错误解释为 4D，或输出维度未恢复；
- <code>stride</code> 为空、单元素和双元素列表的默认语义错误；
- <code>ceilMode=true</code> 的输出 Shape 或末端窗口处理错误；
- 填充区域参与比较时未使用负无穷语义；
- 并列最大值的索引没有保持行优先首个位置；
- 不同通道之间错误共享最大值或索引；
- <code>indices</code> 的小端编码、容器宽度和尾部区域处理错误；
- 非连续 <code>out</code> 的物理步长解析错误或发生越界写入；
- <code>float</code>、<code>float16</code> 和 <code>bfloat16</code> 的精度比较口径不一致。
