# aclblasIcamax 算子设计说明

## 1. 需求背景

### 1.1 需求来源

面向 Ascend 950PR，在 ops-blas 中提供复数向量最大比较值位置查询接口 `aclblasIcamax`。实现采用 CANN 9.1.0，沿用仓库的句柄、执行流、返回状态和工作区约定。

### 1.2 背景介绍

该操作的输出不是最大值，而是一个整数位置。输入的每个复数先转换为 `|实部| + |虚部|`，再确定目标元素在逻辑向量中的位置。对于不含 NaN 的输入，重复最大值必须选择最早位置。

实现的主要工作是读取向量、形成比较值并合并候选。连续地址适合集中搬运和向量计算；正步长地址适合由线程直接读取需要的元素。两种读取方式共用结果定义，但无需使用相同的执行流程。

## 2. 需求分析

### 2.1 需求描述

接口声明如下：

```cpp
aclblasStatus_t aclblasIcamax(
    aclblasHandle_t handle,
    int n,
    const aclblasComplex* x,
    int incx,
    int* result);
```

`n` 表示参与比较的复数个数，`incx` 表示相邻逻辑元素在物理存储中的间隔。`x` 和 `result` 位于设备内存；后者只需保存一个 INT32 值。正常结果从 1 开始计数，不是输入数组的物理偏移。

接口把设备工作加入 `handle` 绑定的执行流。返回成功不等于设备已经执行完毕，读取输出前需等待该执行流完成。

### 2.2 需求拆解

设计分为三项责任：

1. 主机入口负责参数有效性、资源数量和任务分配，不在主机上计算向量结果。
2. 设备扫描负责读取有效元素，同时保存比较值、位置以及特殊值标记。
3. 结果生成负责核间合并，必要时执行保持比较顺序的特殊值处理，最后写一个整数。

参数处理按以下次序进行，避免空指针与快速返回条件相互掩盖：

| 检查顺序 | 条件 | 行为 |
|---:|---|---|
| 1 | `handle == nullptr` | 返回句柄为空状态 |
| 2 | `n < 0` | 返回非法参数状态 |
| 3 | `result == nullptr` | 返回非法参数状态 |
| 4 | `n == 0` 或 `incx < 1` | 异步写入 0，不读取 `x` |
| 5 | 正常计算但 `x == nullptr` | 返回非法参数状态 |
| 6 | 平台核数不可用或工作区不足 | 返回相应错误，不启动正常计算 |

### 2.3 数据与使用边界

输入类型为 COMPLEX64，每项包含两个 FP32 分量，共 8 字节。逻辑位置 `i` 从 0 开始，对应物理元素 `i × incx`。正步长正常输入至少需要 `1 + (n - 1) × incx` 个复数的有效存储空间。

当前接口不提供负步长反向扫描、矩阵广播或复数高精度版本。调用方负责输入存储有效，并保证同一公共工作区不会被相互重叠的独立调用同时使用。

## 3. 详细设计

### 3.1 算子分析

#### 3.1.1 普通输入的结果定义

对于 `n > 0`、`incx > 0` 且不含 NaN 的输入，定义：

```text
s(i) = abs(real(x[i × incx])) + abs(imag(x[i × incx]))
m    = max(s(i)), 0 ≤ i < n
r    = min({i | s(i) = m}) + 1
```

比较量不是欧氏模长，不需要乘法、平方根或矩阵乘运算。每个候选由 `(比较值, 逻辑位置)` 组成，先选择更大值，相等时选择更小位置。Inf 可以作为最大比较值；没有 NaN 时，多个 Inf 仍选择最早位置。

#### 3.1.2 特殊值的结果定义

NaN 不满足普通全序比较，因此包含 NaN 的输入不能直接套用上述最大值公式。当前实现对齐的参考配置为 OpenBLAS 0.3.20 的 Barcelona 内核。精度检查实际调用该配置的 `cblas_icamax`，将其从 0 开始的结果加 1 后比对。不同版本或不同 CPU 内核的特殊值结果不在本设计的兼容保证内。

普通扫描与特殊值结果生成分开处理：只要任何有效元素的比较值为 NaN，核间摘要就传播这个事实，最终改走有序比较与查找。该标记不表示“NaN 是最大值”，也不直接指定输出位置。

### 3.2 算子实现

#### 3.2.1 执行路径与数据流

```text
参数检查与任务划分
  ├─ 快速返回：在执行流中写 0
  ├─ incx = 1：GM → MTE2 → UB → SIMD → 每核摘要
  │                                        ↓ 全核同步
  │                                   核 0 合并摘要
  └─ incx > 1：SIMT 按步长读 GM → 每核摘要
                                           ↓ 同一流上的后续执行
                                      单核合并摘要

合并结果
  ├─ 未发现 NaN：写最早最大值位置 + 1
  └─ 发现 NaN：有序比较 → 分组查找 → 写位置 + 1
```

GM 是设备全局内存，UB 是计算核的片上缓冲。连续路径的 MTE2 负责把有效输入搬入 UB；SIMD 从 UB 读取数据并在寄存器中处理。跨步路径由 SIMT 线程直接访问 GM，不先生成紧凑的全长副本。两条路径都不保存与输入等长的比较值数组。

#### 3.2.2 主机任务划分

主机动态读取可用矢量核数 `C`，参与核数为 `B = min(n, C)`。

连续输入足以给每个核分配一个完整向量组时，先把输入划成 `V` 个复数一组，再按组均分：每核取得基础组数，前面的核分担余下完整组，最后不足一组的元素交给末核。这样多数核的起点和主体长度保持对齐。

输入过小或步长大于 1 时，按元素均分，前面的核各多处理一个余数元素。分工只描述起始位置和数量，不预先生成每核地址表。

跨步扫描的线程数由最忙核的任务量向公共最小线程数对齐后得到，并限制在公共最大线程数内。每个线程以线程总数为间隔继续扫描，因而线程数不足以一次覆盖所有输入时仍能完成任意长度任务。

#### 3.2.3 连续输入的分片扫描

每核循环处理自己的逻辑区间。每次将一个分片搬入唯一的输入 UB 缓冲；对齐部分使用常规搬运，非对齐分片使用带补齐的搬运。补齐项不属于逻辑输入，由有效掩码排除。

复数原本按 `real0, imag0, real1, imag1, ...` 排列。向量加载后，`DeInterleave` 把寄存器中的实部和虚部分开，随后执行绝对值和加法。这个步骤不修改 GM 中的布局，也不额外保存两份实虚部数组。

循环中保留各向量通道的最大比较值和候选位置。二路或四路独立计算链交错推进，在片内合并时再统一比较值和位置。片内输出由最大值、位置和 NaN 检测结果构成，直接复用输入缓冲开头，不另外申请大缓冲。

核内继续合并各分片结果；发现 NaN 后可以停止该核剩余的普通扫描，因为最终有序处理会重新读取原输入。所有核写出摘要后执行全核同步，由核 0 读取并合并。连续路径的扫描和最终输出位于同一次设备内核启动内。

#### 3.2.4 跨步输入的线程扫描

线程按照逻辑索引计算物理位置，乘法先转成 64 位，防止大步长的地址运算提前溢出。每次读取一个完整复数，再形成比较值。

候选首先在线程寄存器中更新，然后通过线程组内交换合并。各组的局部结果写入小型 UB 数组，经过线程同步后由首组完成核内合并。每核只向公共工作区写出一个摘要。

跨步路径由两次设备内核启动组成：第一阶段并行扫描，第二阶段用一个核合并摘要。两次启动加入同一执行流，后续阶段按流顺序读取前一阶段结果。使用这种路径是当前实现的选择，并不表示跨步数据在硬件上绝对不能使用其他搬运方式。

#### 3.2.5 含 NaN 时的有序处理

有序处理在一个核上完成，读取地址仍遵循 `i × incx`，因此连续和跨步输入使用相同规则。过程分为两步。

第一步生成用于查找的比较值。四条链均从首元素的比较值初始化，分别从逻辑位置 `1 + lane` 开始，每次递增 4。每次更新使用：

```text
ordered_max(a, b) = a > b ? a : b
```

当比较涉及 NaN 时，条件不成立，选择后一个操作数。完整四项之外的尾部按参考次序更新主链和辅助值；各链再与辅助值合并。设四条结果为 `v0` 至 `v3`，最后的合并顺序固定为：

```text
ordered_max(ordered_max(v3, v1), ordered_max(v2, v0))
```

第二步查找输出位置。线程并行检查连续的四元素逻辑组，先寻找组内存在普通相等比较的组；在该组内，按元素顺序选择相等或无序比较命中的第一项。剩余不足四项的尾部按独立规则处理；没有前面候选时使用尾部回退位置，并保证输出在合法范围。各线程候选最后按较小索引合并。

这里的“四条链”固定比较语义，与普通 SIMD 路径为隐藏依赖而使用的“四路计算链”是不同概念。普通路径的链数选择可以随工作量变化，有序路径的操作数次序不能随意改写。其额外读取由输入中是否出现 NaN 决定，与测试编号或指定规模无关。

#### 3.2.6 同步和存储复用

数据生产与消费之间保留明确的完成条件：

| 交接位置 | 完成条件 | 保护的对象 |
|---|---|---|
| 输入搬运到向量计算 | `MTE2_V` 事件设置与等待 | UB 中本片输入 |
| 向量结果到标量读取 | `V_S` 事件设置与等待 | 最大值、位置和检测位 |
| 各核摘要到连续路径最终合并 | `SyncAll` | 公共工作区的全部摘要 |
| SIMT 线程之间 | 线程同步与分级合并 | UB 中的线程组摘要 |
| 两次跨步执行之间 | 同一执行流的先后顺序 | 第一阶段写出的摘要 |

同一 UB 缓冲按分片顺序复用。当前设计没有双缓冲搬运与计算重叠，不能把多路寄存器计算描述为双缓冲流水线。

#### 3.2.7 参数来源与资源上界

| 参数 | 当前规则 | 设计含义 |
|---|---|---|
| 向量组 `V` | 向量寄存器字节宽度除以 `sizeof(float)`，当前为 64 | 实虚部拆分后每个通道对应一个复数 |
| 分片上限 `T` | `floor((248 KiB / 8) / V) × V = 31744` | 由公共 UB 预算与输入元素大小推导 |
| 普通四路计算门槛 | 每核元素数不少于 `2 × T` | 以更长工作量分摊四路初始化和合并成本，是通用策略而非性能最优性的证明 |
| 跨步扫描线程数 | 工作量向 128 对齐，上限 2048 | 来自公共线程限制，不绑定某个测试规模 |
| 最终合并线程数 | 公共最小线程数，当前为 128 | 覆盖少量核间摘要及后续查找 |
| 有序比较链数 | 4 | 由特殊值参考配置决定，不是调优参数 |
| 核间摘要 | 每核两个 32 位字 | 一个比较值和一个携带标志的位置 |

摘要索引的高位用作 NaN 标志；合法逻辑索引位于非负 INT32 范围，与该位分开。无效候选使用独立哨兵，比较前先排除。全局工作区字节数为：

```text
workspace_bytes = ceil((B × 2) / 64) × 64 × 4
```

工作区按 256 字节粒度对齐。主机在启动前验证句柄提供的容量，算子执行期间不申请新的设备全局内存。

### 3.3 支持硬件

本实现面向 Ascend 950PR，源码位于 `blas/iamax/arch35/`。使用矢量计算路径，不调用矩阵计算单元。其他产品不由这份设计声明支持，不能用 CA Model 或其他设备测试替代真实 950 验证。

### 3.4 算子约束限制

接口只保证访问逻辑向量覆盖的有效输入。正常调用期间，输入、输出及句柄工作区必须保持有效，且调用方不得并发修改输入。

包含 NaN 时必须维持有序处理规则，不能将其替换为普通最大值归约。该路径含有顺序依赖和额外扫描，不承诺具有普通有限值输入相同的耗时。对于极端长度或步长，可用内存及地址范围仍受实际设备环境限制。

## 4. 可维可测分析

### 4.1 验证要求

- 精度：输出整数索引与指定参考配置的结果完全相等；非法参数检查返回状态，快速返回检查输出为 0。
- 性能：仅统计算子的完整设备执行时间，逐条按用例规定上限判定；不计入输入准备、数据传输和参考计算。

具体测试方法、用例数量、性能上限、实测结果及截图由测试说明和自测报告统一记录。

### 4.2 性能优化设计

优化围绕减少读写和缩短合并过程展开：连续输入按完整向量组分核，减少尾段；较大的通用分片降低循环次数；实虚部分离后直接在寄存器中更新候选，减少中间数据落地；多条独立计算链降低单条依赖对推进速度的限制；连续扫描与核间结果生成合并在一次设备启动中。

跨步输入不搬运无用间隙，而是直接读取目标元素，并使用分级线程合并减少全局写回数量。特殊值处理单独触发，普通输入无需执行有序重扫。

构建仅对 Icamax 的 Host 和 Kernel 源文件追加 `-O3`，其他算子保持原有选项。该局部设置不等于将整个仓库切换为 Release；编译优化也不能代替必要的数据等待。

### 4.3 内存分析

全局输入最小容量为 `(1 + (n - 1) × incx) × 8` 字节，输出为 4 字节，工作区随参与核数增长，不随向量长度线性扩张。

连续扫描每核分配一个最大 248 KiB 的输入缓冲。分片摘要复用该缓冲，SIMT 合并及有序处理另外使用少量片上数组。248 KiB 只描述输入分片容量，不应写成所有片上资源占用的精确总和。

工作区公式可通过 Host 代码检查；片上资源总量以编译资源信息为依据；运行时峰值设备内存则需要单独采样。这三类证据不能相互替代。

### 4.4 兼容性分析

公开接口、结果类型和句柄使用方式保持与 ops-blas 一致。实现落在独立 Icamax 文件中，不改变同族其他接口的结果规则。

主要维护位置为 `icamax_host.cpp`（参数与分工）、`icamax_tiling_data.h`（参数定义）、`icamax_kernel.cpp`（扫描与结果生成）以及 `test/iamax/icamax/`（精度测试）。资源参数修改后需重查分片与分核边界；比较规则修改后需重查特殊值的有序行为。实际测试数、测量值与截图由自测报告保存，本设计文档不重复维护运行记录。
