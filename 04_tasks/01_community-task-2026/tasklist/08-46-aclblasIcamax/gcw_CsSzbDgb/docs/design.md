# aclblasIcamax 算子设计

# 需求背景

## 需求来源

本需求用于新增 aclblasIcamax 算子，在 Ascend 950PR 上提供 COMPLEX64 向量最大模索引能力，并采用 ops-blas 的句柄式调用方式。

## 背景介绍

最大模索引可用于异常值定位、归一化前尺度检查和稀疏更新。对 COMPLEX64 数据，BLAS 规定的比较量为实部绝对值与虚部绝对值之和；当多个元素的比较量相同时，返回第一次出现的位置。

设计根据输入步长选择计算路径：`incx = 1` 时采用连续批量计算，`incx > 1` 时采用线程并行扫描。两条路径使用相同的候选比较和特殊值处理规则。

# 需求分析

## 需求描述

新增接口：

```cpp
aclblasStatus_t aclblasIcamax(
    aclblasHandle_t handle,
    int n,
    const aclblasComplex* x,
    int incx,
    int* result);
```

接口在逻辑向量中寻找 `abs(real) + abs(imag)` 最大的元素，并返回其 1-based 索引。正常计算异步排入 handle 绑定的 stream；`n == 0` 或 `incx <= 0` 时只把输出写为 0。

## 需求拆解

**连续向量**：成块读取并批量计算复数模，处理完整分块和尾块。

**跨步向量**：线程按逻辑位置直接读取，检查 `incx = 2/3` 和大步长地址。

**任务划分**：参与核数取输入长度与可用矢量核数中的较小值，各核均衡处理逻辑区间。

**多核结果合并**：保存每核最大值和最早索引，检查跨核并列和 Inf。

**特殊值**：遵循 Netlib `icamax` 的更新顺序，检查首元素 NaN、后续 NaN 和首个 Inf。

**接口行为**：完成参数检查并保证 stream 顺序，检查 quick return、空指针和异步可见性。

实现目录规划为 `blas/iamax/arch35/`，测试目录规划为 `test/iamax/icamax/arch35/`。公共声明加入 `include/cann_ops_blas.h`，不增加 Ascend 950PR 私有接口。

# 详细设计

## 算子分析

### 数学公式

设逻辑位置为 `i`，物理位置为 `p(i)`：

```text
p(i)     = uint64(i) * uint64(incx)
abs1(i)  = abs(real(x[p(i)])) + abs(imag(x[p(i)]))
result   = first_argmax(abs1) + 1
```

比较过程不使用 `sqrt(real * real + imag * imag)`，也不返回最大模值本身。

### 严格更新语义

索引从第一个元素开始建立，只有后续元素的比较值严格更大时才更新。并行实现遵循以下规则：

- 普通候选按 `abs1` 降序选择，数值相同选择较小逻辑索引；
- 后续位置产生 NaN 时不形成候选；
- 若逻辑第 0 个元素产生 NaN，将它映射为“锁定候选”，使索引 0 在全局汇总时保持胜出；
- 正无穷参与普通比较，因此多个正无穷仍返回最早位置。

“锁定候选”使用内部索引的保留位标记，不改变公开接口或核间摘要大小。首元素为 NaN 时，后面的有限值和 Inf 均不得替换索引 1。

### 支持数据类型

- x 为 COMPLEX64，每个元素由两个 FP32 分量组成。
- result 为单个 INT32 索引。
- n 和 incx 为 Host 侧 INT32 标量。

### 支持形状

x 是逻辑一维向量 `[n]`，实部和虚部交错存放，一个逻辑元素占 8 字节。`incx >= 1` 时最末访问位置为 `(n - 1) * incx`。正常结果在 `[1, n]`，quick return 结果为 0。算子不涉及广播、转置、原地更新或多维 shape 推导。

## 算子实现

### Host 侧：路径选择与任务划分

Host 完成参数检查并读取平台信息，再根据 `incx` 选择计算路径：

| 计算路径 | 适用条件 | 设计目的 |
| --- | --- | --- |
| 连续批量路径 | `incx = 1` | 使用连续搬运和批量计算 |
| 跨步线程路径 | `incx > 1` | 按逻辑位置直接读取，避免生成连续中间数组 |

参与核数为 `min(n, 可用矢量核数)`。连续路径优先按 64 个复数对齐分配，各核每次最多处理 32768 个复数；不能对齐的元素由尾块处理。跨步路径按各核最大元素数选择线程数，线程数向 128 对齐且不超过 2048。

参数顺序遵循公共 BLAS 接口约定：handle 为空先返回专用状态；负 `n` 返回非法参数；result 为空返回非法参数；quick return 不读取 x，并在绑定 stream 上异步写零；只有正常路径才要求 x 有效。

Host 为每核预留两个 32 位字，保存最大值和全局逻辑索引。工作区按 64 个 32 位字对齐，所有输入偏移使用 64 位无符号数计算。

### 连续路径：成块计算复数模

连续路径按复数元素切成适合片上空间的 tile：

```text
GM 中的交错复数
  → 成块搬入片上缓冲
  → 对实部、虚部分别取绝对值
  → 按复数配对相加得到 abs1
  → 取得 tile 最大值及第一次出现的位置
  → 更新本核候选
```

完整 tile 使用普通批量搬运，尾 tile 使用带有效长度的搬运和填充。填充值不参与候选比较。若底层最大值接口不能保证并列时返回最早位置，则先求最大值，再对等值位置生成掩码并提取首个有效位置。

每核将 8 字节候选摘要写入工作区。核间同步后，由第一个核合并全部摘要并写入 1-based result，因此连续路径只启动一次 kernel。

### 跨步路径：按逻辑位置直接取数

跨步输入不先复制成连续数组。每个线程计算自己的 64 位物理位置，用一次 8 字节读取同时取得实部和虚部，在寄存器内维护最大候选。线程组完成核内合并后写入工作区，再由第二个 kernel 汇总各核结果。

跨步路径与连续路径使用相同的摘要格式和比较规则。

### 结果汇总与首元素保护

每核摘要包含最大比较值和全局逻辑索引。包含逻辑第 0 个元素的核负责识别首元素 NaN，并写出锁定候选；其他位置的 NaN 不进入摘要。汇总按“锁定优先、数值更大优先、索引更小优先”的次序选择，最后将 0-based 索引加 1。

需要覆盖以下边界场景：

1. 第一个元素为 NaN，后面包含有限值和 Inf，结果仍为 1；
2. 第一个元素有限，后面出现 NaN，NaN 不改变结果；
3. 多个元素的模相同且分布在不同核，结果取最早位置；
4. 多个 Inf 分布在 tile 边界和核边界，结果取第一个 Inf。

## 算子约束限制

1. `n < 0` 返回 `ACLBLAS_STATUS_INVALID_VALUE`。
2. `n == 0` 或 `incx <= 0` 返回成功并写 0，不支持负步长反向遍历。
3. 正常路径要求 x 和 result 指向有效 Device 内存。
4. 输入仅支持 COMPLEX64，输出仅支持 INT32 索引。
5. 调用方读取结果前需要同步绑定 stream。
6. 路径切换只改变执行方式，不得改变并列、NaN、Inf 和索引基数语义。

# 可维可测分析

## 精度标准/性能标准

| 指标 | 测试方法 | 通过标准 |
| --- | --- | --- |
| 精度 | NPU 输出与 CPU 参考结果逐项比较 | INT32 索引完全相等，`actual == expected` |
| 性能 | Ascend 950PR 上使用 ACL Event 统计单次平均耗时 | 有效采样超过 50 次，平均耗时不高于规定上限 |

### 精度标准

精度测试使用 ops-blas 的 GTest/CSV 框架。每条 CSV 用例生成一组 COMPLEX64 输入，分别调用 NPU 算子和独立 CPU 参考实现。CPU 参考实现复现 Netlib/cblas `icamax` 的严格更新规则并生成 1-based 索引，再与 NPU 的 INT32 输出精确比较。`n == 0` 或 `incx <= 0` 时不执行归约，预期结果为 0。

测试使用任务包提供的 1200 条 CSV 用例，覆盖：

- `n = 0/1`、小质数、2 的幂、2 的幂前后相邻值、非对齐尺寸和大尺寸；
- `incx = 1/2/3`，以及 `incx = 0/-1/-2/-3` 的 quick return；
- 均匀分布、正态分布、全零、常量和正负交替；
- NaN、Inf、极端值和并列最大值；
- x、result 空指针及 `n < 0` 非法参数。

全部用例的返回状态和索引均与预期一致才通过精度测试。

### 性能标准

性能指标为 COMPLEX64 连续输入在 Ascend 950PR 上的平均单次耗时：

| n | incx | 平均耗时上限（us） |
| ---: | ---: | ---: |
| 1,048,576 | 1 | 3.92 |
| 4,194,304 | 1 | 4.13 |
| 16,777,216 | 1 | 5.03 |

每个性能用例先执行 10 次预热，再执行 5 轮测试，每轮连续调用 100 次。每轮使用 ACL Event 记录总耗时，再除以 100 得到单次平均耗时，共计 500 次有效调用。输入中仅设置一个唯一最大值，计时后检查返回索引是否正确；性能结果记录总平均值以及各轮最小值和最大值。

### 内存分析

- 输入最小占用为 `(1 + (n - 1) * incx) * 8` 字节，输出为 4 字节。
- 工作区有效数据为 `参与核数 * 8` 字节，并按 256 字节对齐；64 个核时需要 512 字节。
- 连续路径每核最多使用 256 KiB 片上分片；跨步路径只保留线程组摘要。
- 两条路径均不生成与输入等长的模值数组。

## 兼容性分析

Icamax 使用现有 handle、stream、状态码和工作区机制，两条计算路径仅属于接口内部实现，不改变调用方式。新增代码进入独立的 Icamax 文件，不修改 Isamax 或其他 iamax 接口行为。路径切换不改变结果格式和异常返回约定。
