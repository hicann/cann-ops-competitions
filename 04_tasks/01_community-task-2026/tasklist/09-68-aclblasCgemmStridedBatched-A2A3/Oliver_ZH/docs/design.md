# 需求背景

## 需求来源

面向 Atlas A2/A3 系列产品，在 ops-blas 中使用 Ascend C 实现单精度复数带步长批量矩阵乘算子 `aclblasCgemmStridedBatched`。

## 背景介绍

### 算子应用与优化目标

带步长批量矩阵乘用于一次处理多个形状相同的矩阵。各批次共享计算参数，矩阵地址通过基址和固定步长确定，适用于成组复数线性代数运算。

小矩阵场景主要减少任务启动、数据搬运和中间结果写回开销；大矩阵场景主要提高矩阵计算单元利用率，并复用分块数据。对于较长的归约维度，同时考虑复数乘加的舍入误差。

### 算子功能分析

| 参数 | 含义 | 类型与存储 |
| --- | --- | --- |
| handle | 运算句柄，提供执行流与工作空间 | Host 句柄 |
| transa、transb | 不转置、转置或共轭转置 | N、T、C 枚举 |
| m、n、k | 输出行数、输出列数、归约长度 | int |
| alpha、beta | 各批次共享的复数系数 | Host 侧 COMPLEX64 标量 |
| A、B | 批量输入矩阵 | Device 侧 COMPLEX64，列主序 |
| C | 原始输出矩阵及计算结果 | Device 侧 COMPLEX64，列主序 |
| lda、ldb、ldc | 各矩阵相邻列起点的距离 | int，以复数元素计 |
| strideA、strideB、strideC | 相邻批次矩阵起点的距离 | 有符号 64 位整数，以复数元素计 |
| batchCount | 批次数量 | int |

# 需求分析

## 需求描述

提供以下公共接口，对每个批次计算复数矩阵乘加，结果写入 C。接口通过 handle 绑定的 stream 异步执行。

```cpp
aclblasStatus_t aclblasCgemmStridedBatched(
    aclblasHandle_t handle, aclblasOperation_t transa, aclblasOperation_t transb,
    int m, int n, int k,
    const aclblasComplex *alpha,
    const aclblasComplex *A, int lda, long long strideA,
    const aclblasComplex *B, int ldb, long long strideB,
    const aclblasComplex *beta,
    aclblasComplex *C, int ldc, long long strideC,
    int batchCount);
```

## 需求拆解

1. 支持 COMPLEX64 输入输出，以及 A、B 的全部九种转置组合。
2. 支持矩形矩阵、非对齐尺寸、前导维填充和批次间隔；支持通过零输入步长复用 A 或 B。
3. 根据矩阵尺寸、批次数量和数据布局选择向量计算、分组计算或矩阵分块计算。
4. 处理复数系数、空计算及非法参数，保持有效输出以外的填充区域不变。

# 详细设计

## 算子分析

### 数学公式

对批次 `i = 0, …, batchCount−1`：

```text
A_i = A + i × strideA
B_i = B + i × strideB
C_i = C + i × strideC
C_i ← alpha × op(A_i) × op(B_i) + beta × C_i
```

`op(X)` 在 N、T、C 模式下分别表示 X、X 的转置及 X 的共轭转置。设变换后的输入为 `A_r + jA_i` 和 `B_r + jB_i`，则乘积 P 可分解为：

```text
P_r = A_r × B_r − A_i × B_i
P_i = A_r × B_i + A_i × B_r
C_new = alpha × (P_r + jP_i) + beta × C_old
```

通用矩阵计算路径以四次实数矩阵乘实现复数乘法，再合并实部、虚部及标量系数。

### 支持数据类型

输入、输出及 alpha、beta 均为 COMPLEX64，每个复数由两个 FP32 分量组成。矩阵计算使用 FP32 输入和累加，关闭 HF32 模式。

### 支持形状

`op(A)`、`op(B)` 和 C 的逻辑形状分别为 `m×k`、`k×n` 和 `m×n`。各批次的尺寸与转置方式相同，尺寸和步长由运行时参数给出。

| 矩阵 | N 模式下的存储形状 | T/C 模式下的存储形状 | 前导维约束 |
| --- | --- | --- | --- |
| A | m×k | k×m | N：lda≥max(1,m)；T/C：lda≥max(1,k) |
| B | k×n | n×k | N：ldb≥max(1,k)；T/C：ldb≥max(1,n) |
| C | m×n | 不涉及 | ldc≥max(1,m) |

## 算子实现

### 实现方案

采用 Host 参数处理与 Device 计算分离的结构。Host 完成校验、分块和工作空间管理；Device 完成输入整理、复数矩阵计算以及结果写回。实现位于 `blas/gemm_strided_batched/arch22/`。

#### Host 侧设计

**参数校验与特殊分支。** 首先校验句柄、标量指针、转置枚举、非负维度及前导维。空句柄返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`，非法参数返回 `ACLBLAS_STATUS_INVALID_VALUE`。合法参数下，m、n、k 或 batchCount 任一为零时直接返回成功。非空计算中，alpha 为零时只处理 beta 与 C，不访问 A、B；alpha 为零且 beta 为一时直接返回。

**地址计算。** 使用基址加批次步长定位矩阵，使用行号加列号乘前导维定位列主序元素，不构造矩阵指针数组。地址偏移及空间大小使用宽整数计算，检查可表示范围，防止乘法或加法溢出；输入分配范围由调用方保证。

**分块与分核。** 将尺寸、前导维、步长、转置方式和复数系数写入 tiling 参数。通用矩阵路径采用 32、64、128 三档输出分块，根据尺寸选择，归约维度按计算粒度补齐。按输出转置方向组织内部矩阵，方便列主序数据整理与写回。将批次和输出块共同分配到计算核心；批次较少且边缘块大小不均时，比较不同任务排列的负载，减少核心空闲。小矩阵向量路径根据实际批次数量缩减启动核心数。

**工作空间。** 通用路径为输入的实部、虚部及四组实数乘积预留空间，同时考虑分组和流水路径的空间需求。按工作空间预算切分批次，在同一 stream 中顺序提交并复用空间。分组末尾不足一组时预留补齐空间，输出仅保留有效批次。空间申请失败时返回相应状态。

**路径选择。** 根据尺寸、归约长度、转置方式、系数、布局及资源限制选择计算路径；直接搬运或直接写回条件不满足时使用通用整理与写回路径。

| 场景 | 计算安排 | 主要目的 |
| --- | --- | --- |
| alpha=0 | 向量计算 beta×C 或清零 | 省去输入读取和矩阵乘法 |
| 可驻留的小矩阵 | 在向量本地存储中保存输入并完成计算 | 减少启动及中间结果搬运 |
| 适合分组的小矩阵批次 | 将多个矩阵组合到矩阵计算块中 | 提高计算块利用率 |
| 中大矩阵 | 分块执行实数矩阵乘，再合并复数结果 | 利用矩阵计算能力与数据复用 |
| 需要控制累加误差的长归约 | 分段读取，按归约顺序完成复数累加 | 控制舍入顺序带来的误差 |

#### Kernel 侧设计

**输入整理。** 根据 transa、transb 和前导维读取原始矩阵，将交错存储的复数拆为实部与虚部。转置通过地址映射完成，共轭转置同时对虚部取反。补齐区域置零。连续布局采用成段搬运；带填充或转置布局采用分块映射。较大的前导维超出快捷搬运指令的表达范围时，切换到通用地址计算。

**矩阵计算。** 将整理后的数据分块搬入 L1，再送入 L0A、L0B 完成实数矩阵乘，在 L0C 中累加。归约维度分段推进，保留当前输出块的累加结果。通过交替缓冲衔接相邻数据块的搬运和计算；最后一块按有效尺寸处理。

**分组与向量路径。** 小矩阵可由单个向量核心处理一个或多个批次，在本地存储中复用输入。适合矩阵计算的批次按资源容量分组，整理成适合计算单元的实数布局，并映射回各自输出。分组尾部使用补零与有效批次判断，避免写入不存在的批次。

**长归约处理。** 对需要严格控制误差的场景，保持 K 方向的复数乘加顺序，通过分段读取限制本地存储占用，累加状态跨段保留，不将 K 分段结果独立求和后再合并。必要时使用乘加误差补偿控制舍入影响。对于布局和系数满足条件的输入，先整理为连续平面，再分块流式读取，减少逐元素地址处理开销。

**计算与搬运协同。** 在向量核心和矩阵核心配比、缓冲容量满足条件时，向量核心整理输入，矩阵核心计算，向量核心合并并写回。交替缓冲通过就绪和完成通知控制复用，确保读取完成后才覆盖缓冲；每次调用处理完本次通知，避免后续调用使用残留状态。其他场景按顺序提交各计算阶段。

**复数合并与写回。** 合并四组实数乘积后执行 alpha×P+beta×C。beta 为零时跳过旧 C 的读取，两系数同时为零时直接清零。满足系数和布局条件的路径直接写回；其余路径统一处理复数系数和列主序映射。仅写入每批次的 m×n 有效区域，保留列填充及批次间隔。

## 算子约束限制

- A、B、C 使用列主序及固定批次步长，不支持超出前导维与批次步长描述能力的任意非连续布局。
- strideA 或 strideB 为零时复用同一输入；各批次输出区域应相互独立，C 不与 A、B 重叠。
- 调用方保证设备内存有效且覆盖实际访问范围；算子不查询用户分配的内存边界。
- m、n、k 或 batchCount 为零时按任务定义执行空操作，其中 k=0 不更新 C。
- 不保证浮点结果逐位一致。调用为异步执行，读取结果前由调用方同步执行流。

## 兼容性分析

公共接口沿用 ops-blas 的句柄、复数类型、转置枚举及状态码，参数顺序与任务定义一致。通过现有 handle 获取 stream 和工作空间，不引入额外的调用方同步要求。

算子为新增接口，实现与测试分别放在对应的 `gemm_strided_batched/arch22` 目录中；各计算路径共用参数语义和输出布局，路径切换不改变调用方式。
