# aclblasIcamin 算子设计文档

## 1 需求背景（required）

### 1.1 需求来源

2026 年 9 月社区任务：aclblasIcamin 算子开发（950）。使用 Ascend C 在 Ascend 950PR
上实现单精度复数向量最小模元素索引计算，采用 kernel 直调方式接入 ops-blas 公共接口。

### 1.2 背景介绍

#### 1.2.1 算子实现优化

在 Ascend 950PR 上使用 Ascend C 实现复数向量最小索引计算，通过分核处理、分块搬运
和分层归约组织计算。连续步长采用向量化处理，非连续步长按逻辑元素分工读取，
避免构造与输入等长的中间结果。

#### 1.2.2 算子实现现状分析

ops-blas 已有同族实数接口 `aclblasIsamin`，本任务在 `blas/iamin/arch35/` 中
扩展复数输入的最小索引计算。设计沿用现有的句柄、stream、工作区和构建组织方式，
复用同族算子的归约思路，新增复数读取、实虚部处理和对应接口声明。

接口名称及参数顺序与 `cublasIcamin` 对齐。Ascend 950PR 使用统一的公共 API，
不另外定义仅面向该硬件的平行接口。

#### 1.2.3 算子功能分析

`aclblasIcamin` 属于 BLAS Level 1 向量归约算子，用于在复数向量中定位最小模元素。
输入为复数向量 `x`、元素个数 `n` 和步长 `incx`，输出为独立的整数标量 `result`。
比较值为 `abs(real) + abs(imag)`，不是欧几里得模；返回最小值对应的 1-based
逻辑索引，多个元素并列时取最小索引。支持 COMPLEX64 输入和 INT32 输出，不涉及广播。

## 2 需求分析（required）

### 2.1 需求描述

实现 COMPLEX64 向量到 INT32 标量索引的归约。正常路径输出范围为 `[1, n]`，
零长度或非正步长的快速返回结果为 0。输入只读，结果写入句柄绑定的 stream。

#### 2.1.1 接口与参数

在 `include/cann_ops_blas.h` 中新增以下公共接口：

```cpp
aclblasStatus_t aclblasIcamin(
    aclblasHandle_t handle,
    int n,
    const aclblasComplex* x,
    int incx,
    int* result);
```

| 参数 | 方向 | 类型与位置 | 说明 |
| --- | --- | --- | --- |
| `handle` | 输入 | `aclblasHandle_t`，Host | 已创建的有效上下文，携带执行 stream |
| `n` | 输入 | `int`，Host | 参与比较的复数元素个数，正常值域为 `n >= 0` |
| `x` | 输入 | `const aclblasComplex*`，Device | COMPLEX64 一维向量，只读 |
| `incx` | 输入 | `int`，Host | 相邻逻辑元素的步长，以复数元素为单位；正步长正常计算 |
| `result` | 输出 | `int*`，Device | 单个 INT32，保存 0 或 `[1, n]` 内的索引 |

返回值为 `aclblasStatus_t`。参数错误、句柄错误及执行错误使用 ops-blas 现有状态码，
不得将失败路径报告为成功。

### 2.2 需求拆解

| 需求项 | 设计要求 |
| --- | --- |
| 数据类型 | 支持 COMPLEX64 输入，实部、虚部均为 FLOAT32；输出为 INT32 |
| 计算规则 | 计算实部绝对值与虚部绝对值之和，返回最小值对应的逻辑索引 |
| 并列处理 | 相等时选择较小逻辑索引，所有分片使用同一比较规则 |
| 步长支持 | 支持正整数步长；非正步长快速返回，不进行反向遍历 |
| 参数处理 | 检查句柄、长度和必需指针；快速返回时不访问输入 |
| 并行计算 | 按逻辑元素分片，先生成局部候选，再汇总得到最终索引 |
| 执行方式 | 使用句柄绑定的 stream 异步执行，保持输入只读 |

## 3 详细设计（required）

### 3.1 算子分析

#### 3.1.1 数学公式

使用 0-based 逻辑索引 `i`，实际访问位置和比较值为：

```text
physical_index(i) = i * incx
score(i) = abs(x[physical_index(i)].real)
         + abs(x[physical_index(i)].imag)
result = min { i | score(i) 为有效候选中的最小值 } + 1
0 <= i < n
```

内部保存 0-based 逻辑索引，只在最终写回时加 1。`incx` 只影响读取地址，
不改变输出索引的含义。例如 `incx = 2` 时，访问 `x[0]、x[2]、x[4]`，
若最小值位于 `x[4]`，输出为 3。

#### 3.1.2 支持数据类型

| 对象 | 类型 | 形状与排布 |
| --- | --- | --- |
| 输入向量 | COMPLEX64 | 逻辑形状 `[n]`，每个元素占 8 字节，实虚部交错存储 |
| 比较值 | FLOAT32 | `abs(real) + abs(imag)`，不计算平方或平方根 |
| 输出索引 | INT32 | 单元素 Device 输出，正常计算采用 1-based 索引 |

#### 3.1.3 支持形状

输入逻辑形状为一维 `[n]`，输出为单个标量。正常路径的物理存储至少包含
`1 + (n - 1) * incx` 个复数元素。`n == 0` 走快速返回，不访问输入。
本算子不涉及广播和多维形状推导；`n`、`incx` 为运行时参数，不要求额外的动态形状机制。

#### 3.1.4 候选比较与特殊值

每个候选由“比较值、逻辑索引、是否有效”组成，有效性可由保留的无效索引表示。
候选合并时，先排除无效候选，再比较数值，数值相等时选择较小逻辑索引。
不能仅用 `FLT_MAX` 代表无效值，否则会与有效的最大有限值或 Inf 混淆。

| 输入情形 | 处理规则 |
| --- | --- |
| 相同最小值 | 返回最小逻辑索引 |
| 全零或正负零 | 比较值均为 0，返回 1 |
| 含 Inf | Inf 作为有效比较值参与归约；全部为 Inf 时取最小索引 |
| 比较值为 NaN | 该候选不参与最小值比较 |
| 全部为 NaN | 本设计约定无有效候选时返回 1 |

比较值按 FLOAT32 计算，不降低为半精度。局部归约与最终归约采用相同的比较和并列规则。
任务书对 NaN 细节仍注明待研发确认，因此全 NaN、NaN 与 Inf 混合等组合的最终行为，
应以任务方确认的接口约定为准；上表明确的是本设计采用的处理规则。

### 3.2 算子实现

#### 3.2.1 实现方案与整体流程

```text
Host 参数检查
  -> 快速返回：在 stream 上写 result = 0
  -> 正常计算：划分逻辑元素区间，准备工作区
       -> 各分片读取输入并计算局部最小候选
       -> 局部结果写入工作区
       -> 同步后汇总所有候选
       -> 写回 1-based 索引
```

#### 3.2.2 Host 侧设计

参数检查按以下顺序进行：

1. `handle == nullptr`：返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`。
2. `n < 0` 或 `result == nullptr`：返回 `ACLBLAS_STATUS_INVALID_VALUE`。
3. `n == 0` 或 `incx < 1`：通过运行时异步写零接口设置 `result = 0`，成功后返回
   `ACLBLAS_STATUS_SUCCESS`，不检查或读取 `x`，不启动计算 kernel。
4. 正常计算时，若 `x == nullptr`，返回 `ACLBLAS_STATUS_INVALID_VALUE`。
5. 获取设备核数，准备分片参数并检查工作区容量，然后下发计算。

运行时写零、资源获取或下发失败时，按库内状态码约定返回错误。正常路径只提交
异步操作，不在接口内部增加不必要的 Host 等待。

#### 3.2.3 分核与分块

按设备可用 AIV 核数和输入长度确定分片数 `P`，保证 `1 <= P <= n`，避免空分片。
每个分片处理连续的逻辑索引区间；设 `q = n / P`、`r = n % P`，第 `b` 个分片为：

```text
count(b) = q + (b < r ? 1 : 0)
start(b) = b * q + min(b, r)
区间 = [start(b), start(b) + count(b))
```

连续输入在分片内部继续按 tile 处理，tile 大小根据 UB 容量、缓冲数量和归约临时空间
确定。非连续输入由线程分担逻辑元素，再按 `incx` 映射实际地址。小规模输入减少
参与核数，避免启动无有效工作量的分片。

Host 传递的主要信息如下：

| 信息 | 用途 |
| --- | --- |
| 输入长度与步长 | 确定逻辑范围及实际地址 |
| 分片数量、每片基础长度和余数 | 计算各分片起点及长度 |
| tile 大小 | 控制连续输入的单次搬运量及 UB 使用 |
| 线程配置 | 控制非连续输入的线程分工 |

#### 3.2.4 Kernel 侧设计

计算分为数据读取、局部归约、最终汇总三个步骤：

1. **数据读取**：`incx == 1` 时分块搬入交错的实虚部数据，通过双缓冲组织搬运和计算；
   `incx > 1` 时由线程按逻辑索引读取实际复数元素，不额外展开整个输入。
2. **局部归约**：计算 `abs(real) + abs(imag)`，过滤 NaN，合并比较值与逻辑索引。
   连续路径在 UB 和向量寄存器中归约；非连续路径先保留线程局部候选，再做线程间归约。
3. **最终汇总**：每个分片只写出一个候选，汇总阶段读取这些候选，使用相同规则选出
   全局最小索引。有效索引加 1 后写回；没有有效候选时按特殊值约定写回 1。

最后一个 tile 或线程组只处理实际存在的元素。填充位置须标记为无效，不能以补零
方式参与最小值比较。实际地址使用 64 位整数计算，先扩宽索引再乘以步长，防止乘法溢出。

#### 3.2.5 工作区与同步

工作区按分片保存比较值和索引，并按底层访问要求对齐；无效索引用于表达候选有效性。
容量随分片数增长，不随输入长度线性增长。每次调用必须覆盖所有将被读取的候选位置，
不能依赖工作区上一次调用留下的内容。

连续路径在同一 kernel 内完成局部计算，使用设备支持的核间同步及可见性机制后，
由指定核汇总。非连续路径分别提交局部归约和最终归约 kernel，通过同一 stream 的
执行顺序保证最终汇总读取到完整结果。最终输出只由一个执行单元写入。

输入、输出和工作区须在异步操作完成前保持有效。同一工作区不得被未建立依赖关系的
并发调用同时写入。调用方读回 `result` 前需要同步绑定的 stream。

#### 3.2.6 工程组织

| 文件或目录 | 职责 |
| --- | --- |
| `include/cann_ops_blas.h` | 新增公共接口声明 |
| `blas/iamin/arch35/icamin_host.cpp` | 参数检查、快速返回、任务划分和下发 |
| `blas/iamin/arch35/icamin_tiling_data.h` | Host 与 Device 共享的任务参数 |
| `blas/iamin/arch35/icamin_kernel.h` | kernel 下发入口声明 |
| `blas/iamin/arch35/icamin_kernel.cpp` | 输入读取、局部归约及最终汇总 |

### 3.4 算子约束限制

| 场景 | 处理方式 |
| --- | --- |
| `handle == nullptr` | 返回句柄为空错误 |
| `n < 0` 或 `result == nullptr` | 返回参数错误 |
| `n == 0` 或 `incx < 1`，其余必需参数合法 | 写入 0 并返回成功，不要求 `x` 非空 |
| `n > 0`、`incx >= 1` 且 `x == nullptr` | 返回参数错误 |
| 正常计算 | `x` 和 `result` 为有效的 Device 指针，输出空间不与输入重叠 |

正常输入的存储空间至少覆盖 `1 + (n - 1) * incx` 个复数元素，且不超过有效分配范围。
不支持广播、多维张量或原地修改；其他硬件不属于本次设计范围。

## 4 可维可测分析

### 4.1 精度要求

输出为 INT32 整数索引，要求与接口约定的结果精确一致，不采用浮点容差放宽索引差异。
正常结果使用 1-based 索引；并列最小值取最小逻辑索引；快速返回结果为 0。
比较值按 FLOAT32 计算，不将复数模替换为平方和，也不改变 NaN 过滤和并列处理规则。

### 4.2 可维护性分析

Host 参数处理、任务划分与 Device 计算职责分开，局部归约和最终归约共用一致的
候选比较规则。工作区大小和分片信息由 Host 统一计算，便于后续调整分块而不改变接口。
异常路径沿用库内状态码和日志机制，区分非法参数、资源不足和执行失败。

### 4.3 兼容性分析

在 `include/cann_ops_blas.h` 中新增接口声明，实现放在 `blas/iamin/arch35/`。
沿用 ops-blas 现有的句柄、stream、状态码和工作区机制，不修改已有接口的行为。

`aclblasComplex` 使用公共头文件的定义，不重新定义复数结构或改变其内存排布。
新增 Host、Kernel 和任务参数使用独立的 Icamin 符号，避免与 `aclblasIsamin` 冲突。
调用方继续使用现有的句柄创建、stream 绑定和结果读回流程。

本设计只增加 Ascend 950PR 的实现支持，不改变其他架构的构建和调用行为。
