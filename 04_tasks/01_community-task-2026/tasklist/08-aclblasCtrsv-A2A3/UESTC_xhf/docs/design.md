# aclblasCtrsv 算子设计文档

> 自测状态（2026-09-16，patch92）：任务已由参赛者领取，尚未取得官方审核或验收结论。A2/910B3 与 A3（平台标签 910C，实例内 SoC `ascend910_9362`）均完成 CANN 9.1.0 构建和真机自测。A2 三项完整运行性能为 70.700900 / 106.927083 / 179.110733 μs；A3 为 69.873 / 109.261 / 186.869 μs，均低于任务书的三项 910B3 数值。两端的 1000 精度、200 性能、内存和 Profiler 原始证据均已下载并通过 SHA-256 与完整性审计，验收时可随自测报告提供；环境均已关机。参赛者侧通过不等于官方审核或验收通过。

# 需求背景（required）

## 需求来源

CANN 社区任务“8月社区任务-aclblasCtrsv算子开发（A2/A3）”。目标是在 Atlas 800I/T A2/A3 上，
基于 ops-blas 句柄式 API 和 Ascend C kernel 直调框架，实现与 cuBLAS/Netlib BLAS `ctrsv` 参数语义一致的
单精度复数三角矩阵求解。

## 背景介绍

`ctrsv` 求解单右端三角线性系统：

```text
op(A) * x = b
```

其中 A 为列主序的 n×n 上/下三角 complex64 矩阵，x 入口为右端 b、出口原地覆写为解。
`op(A)` 支持 A、A^T 和 A^H；对角支持显式非单位和隐式单位两种语义。

当前 ops-blas 公共头文件只有实数 `aclblasStrsv` 声明，arch22 目录缺少完整的 complex64 实现。
本设计新增共用的 `aclblasCtrsv` 公共 API、A2/A3 Host/Kernel 实现、CSV 驱动测试和自验脚本。

# 需求分析（required）

## 需求描述

- 支持 complex64 输入输出。
- 支持 UPPER/LOWER × N/T/C × UNIT/NON_UNIT 共 12 种组合。
- 支持 `lda >= max(1,n)`、`incx=±1/±2/±3` 及运行时动态 n。
- `n=0` 合法直接返回成功；其余非法参数返回任务书规定状态码。
- A 与 x 是 Device 指针；x 原地更新；使用 handle 绑定 stream 异步发射，算子内部不搬运用户 Tensor、
  不同步 stream。
- 910B3 三个性能门槛分别为 75.43 us、149.67 us、243.46 us。

## 需求拆解

1. 公共 API 与严格参数校验。
2. 正确处理列主序、三角引用、转置/共轭、单位对角和负步长。
3. 利用三角求解的串行依赖选择单 AIV 核，避免无效多核同步。
4. 对 OP_N 做 SIMD 复数 AXPY、对 OP_T/OP_C 做 SIMD 复数点积优化，并让正负非连续步长复用
   UB 驻留求解路径。
5. 为超出 UB 驻留容量的扩展输入保留完整正确性路径。
6. 建立 1000 条精度 + 200 条性能用例、cblas golden、混合容差、异常和特殊值校验。

# 详细设计（required）

## 算子分析

### 数学公式

无转置下，下三角前代为：

```text
x[i] = (b[i] - Σ(j=0..i-1) A[i,j] * x[j]) / A[i,i]
```

上三角采用逆序回代。转置/共轭转置会交换有效三角方向；共轭转置读取 A 时还需对虚部取反。
当 `diag=UNIT` 时除法省略且 A 对角不得读取。

complex64 除法使用：

```text
(a+bi)/(c+di) = ((ac+bd) + (bc-ad)i)/(c²+d²)
```

任务书明确不要求奇异性检测，调用方负责 NON_UNIT 对角非零。

### 支持数据类型与形状

| 对象 | 类型 | 布局/形状 |
| --- | --- | --- |
| A | aclblasComplex / complex64 | Device，列主序物理 `lda × n` |
| x | aclblasComplex / complex64 | Device，逻辑 `[n]`，物理 `1+(n-1)×abs(incx)` |
| uplo/trans/diag/n/lda/incx | Host 标量 | 运行时属性 |

## 算子实现

### Host 侧设计

Host 分为 `ValidateCtrsvScalarParams` 和 `LaunchCtrsvKernel`：

1. 首先检查 handle；随后检查 `uplo/trans/diag`、`n>=0`、`lda>=max(1,n)` 和 `incx!=0`。
2. 标量合法的 `n=0` 在读取 A/x 前返回成功，允许 A/x 为空且不发射 kernel。
3. `n>0` 时再检查 A/x 指针。
4. 将 n、lda、uplo、trans、diag、incx 写入小型 POD tiling，并按值传入 kernel。
5. A/x Device 地址直接传给 kernel；不调用 `aclrtMalloc`、用户 Tensor H2D/D2H 或
   `aclrtSynchronizeStream`。

### Kernel 侧总体策略

三角求解每个未知量依赖先前结果。当前按布局、容量和对角类型选择多AIV分块更新、UNIT严格顺序路径或单AIV驻留回退；不是所有输入都简单按行并行。

#### 0. NON_UNIT 连续布局：多AIV分块路径

`incx=1`、`256<=n<=4096`、`n%8=0`，且N或UPPER转置时，Host按实际`GetAivCoreCount()`选择核数。每个核拥有固定、不重叠的x行片段；对角求解按三角顺序推进，尾部更新分核并行。核间使用设备侧`SyncAll`，不是Host stream同步，不分配Device临时内存。

当`n==coreCount*64`，每核驻留64×64对角panel。64列DMA只读取引用三角，批量排入后拆分实/虚；N布局再转为UB行主序。8个独立8×8小块逆以向量lane并行预计算，每个panel内以小块逆乘法及复数点积完成求解，发布64个已解x后其他核并行更新。对齐lda的远端64×64更新只用一次二维DMA；非对齐lda保留分列安全搬运。发布x的交织和接收拆分均由向量指令完成，并保留V→MTE3和V→MTE2等待。

UB分区：输入0–38 KiB，矩阵临时38–76 KiB，小块逆76–80 KiB，常驻矩阵实/虚80–112 KiB，发布索引112–112.5 KiB，x实/虚114–152 KiB，乘积/索引复用152–190 KiB。所有向量起点32字节对齐；无效UB lane初始化或掩码排除，不能引用非使用三角的GM数据。

不满足每核恰有64行时，使用8元素发布的通用多核小块路径，或按容量回退。下述原单核N/T/C路径仍用于非连续步长、小尺寸和未覆盖布局。

#### UNIT：设备侧顺序与融合舍入

UNIT在n<=4096时使用单AIV驻留x，严格按Netlib顺序执行。参考cblas的复数乘积使用融合乘加；为匹配其binary32舍入，设备侧以整数尾数实现最近偶数FMA，再独立减法，未把计算移到Host或放宽容差。对角始终不读。该修复的patch55及加入多核优化的patch86均在A2完整1000条精度通过。

patch90增加NaN传播剪枝：仅当当前未知量已经完成求解且任一分量为NaN时，剩余方程均包含该NaN乘积（零系数乘NaN也为NaN），于是剩余结果两分量均可直接置NaN。当前已解值保持原样；不能仅由Inf推断NaN。432组NaN/Inf/零系数/正负步长与禁用剪枝的原顺序helper对照一致。所有操作仍在AIV执行，不访问隐式对角或非引用三角，不按用例ID硬编码。

#### 1. OP_N：列更新 SIMD 路径

列主序中 A 的列片段连续。每次先求出当前 `x[i]`，再执行：

```text
x[target] += -x[i] * A[target,i]
```

下三角从前向后、上三角从后向前，以 8×8 对角块求解，再更新块外剩余向量。对角 tile 按列紧凑搬运，严格排除非引用三角及 UNIT 对角，UB 列槽保持 32 字节对齐。复数向量拆分为实/虚分量，使用 SIMD
乘加直接更新常驻 UB 的 x 实/虚分量，最终输出时才重新交织；不依赖全局
原子模式。整段 x 在路径入口从 GM 读取一次，全部前代/回代完成后写回一次，从而避免逐列更新时
反复读写 x 的全局内存流量。`incx=1` 使用整段 DataCopy；非连续步长只在入口/出口按逻辑次序
各执行一次 O(n) gather/scatter。

UB 规划：五个 38 KiB 区域，分别为 A 交织输入、A 实/虚拆分、第二输入/输出索引复用、x 实/虚常驻区、对角 tile/输出复用区，总计 190 KiB，低于 arch22 192 KiB UB。列预取的输入缓冲复用必须建立 V→MTE2 依赖；patch45 修复了提前覆盖导致的 LOWER/N 精度失败。padding 由分配的完整向量块容纳，更新指令只写逻辑元素。
最大连续快路径容量为 4864 个复数；更大输入自动转通用路径。

#### 2. OP_T/OP_C：连续列点积 SIMD 路径

转置后当前方程涉及 A 原存储的一段连续列，可复用复数 dot 的拆分、复乘和规约方式：

- T：直接使用 A 实部/虚部；
- C：A 虚部分量乘 -1；
- 对实部和虚部分别做向量乘法与规约，再从当前 b 中减去点积。

整段 x 在入口搬入 UB，求解后写回；步长处理与 OP_N 相同。当前有以下分支：

- UPPER、n≥32：8×8 对角块求解，块外按最多 512 个目标行做 panel 点积更新；lda 对齐时使用二维 DMA，否则逐列拷贝。五个 38 KiB 区域共 190 KiB。
- UPPER、n<32：x 实/虚分量驻留，连续列双缓冲预取，NON_UNIT 对角与列一起搬入；点积完整 repeat 的无效 lane 在规约前置零，避免 NaN/Inf 污染。五个 38 KiB 区域加 512 B 规约区，共 190.5 KiB。
- LOWER：保留驻留交织 x、连续列点积和非对齐短前缀处理，UB 小于 177 KiB。

上述路径均低于192 KiB；快路径最大n=4096，超出后转通用路径。输出交织使用显式V→MTE3 event/wait，保证DMA不提前写回旧UB内容；索引种子先S→V同步再向量扩展。patch52的性能和19个UNIT失败属于已保留的历史实验，不代表当前版本；当前结果见文首状态，不能在三项硬门槛未全部通过时宣称完成验收。

#### 3. 超容量：通用正确性路径

按 BLAS 规则计算 x 的逻辑偏移：

```text
incx > 0: offset(i) = i * incx
incx < 0: offset(i) = (n-1-i) * abs(incx)
```

对非单位步长，驻留路径按上述公式在入口 gather、出口 scatter，逻辑求解与连续步长相同，并保持非逻辑
padding lane 不变。只有 OP_N `n>4864` 或 OP_T/OP_C `n>4096` 时才转入逐元素 GM 的低 UB 占用通用
路径；任务书最大尺寸 4096 不触发该路径。

## 算子约束限制

- `n>=0`；`lda>=max(1,n)`；`incx!=0`；这些标量约束在 `n=0` 时仍校验。
- n>0 时 A/x 不能为空；合法 n=0 空操作允许 A/x 为空。
- 仅访问 uplo 指定三角；UNIT 对角不读取。
- 不检测奇异或近奇异矩阵。
- 不支持超出 lda/incx 语义的任意非连续视图。

| 验收标准 | 描述 | 标准来源 |

测试侧采用 cblas `ctrsv` 作为 golden。未引用三角、UNIT 对角和 `lda` padding 行写入 NaN，可直接发现错误访问；
NON_UNIT 对角按 `boost=max(5,n)` 增强。CSV 覆盖 12 种枚举组合、尺寸扫描、padding、正负步长、
n=0、空指针、非法枚举/lda/incx、Inf/NaN、均匀/正态输入。直测验证 n=0 的空指针/非法标量边界，
并逐位确认非连续 x 的 padding lane 不被改写。性能先 warmup 10 次，再有效采样 60 次。

2026-09-16 真机结果：A2/910B3 完成 1000 条精度、200 条性能及 3 项直接契约测试；三项门槛为 70.700900 / 106.927083 / 179.110733 μs。A3 `ascend910_9362` 完成独立构建、12 条 Smoke、1000 条精度和 200 条性能，三项同参数结果为 69.873 / 109.261 / 186.869 μs。两端均完成 n=4096 内存观测和 msprof 原始数据留存。A3 Profiler 有 71 条正时长 kernel 记录，但细分 PMU 字段为 `N/A`，不宣称获得非零流水利用率。上述均为参赛者侧结果，正式结论以官方验收为准。
