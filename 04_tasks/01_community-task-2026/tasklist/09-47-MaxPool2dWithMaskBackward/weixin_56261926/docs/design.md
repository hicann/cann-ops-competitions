## 1. 需求背景（required）

### 1.1 需求来源

依据社区任务书，参考 `aclnnMaxPool2dWithMaskBackward` 接口，使用 Ascend C 实现二维最大池化的反向传播，完成设计、开发及测试，并按流程向昇腾算子开源仓提交。

### 1.2 背景介绍

最大池化前向计算保留窗口内的最大值及其位置。反向计算根据前向记录的索引，将上游梯度累加到对应输入位置；未被选中的位置梯度为零。当多个窗口选中同一位置时，需要正确合并这些梯度贡献，不能采用覆盖写入。

本任务以现有实现作为功能与性能对照，在保持接口和数据语义一致的前提下，使用 Ascend C 完成设备侧计算，减少不必要的数据搬运与调度开销。

## 2. 需求分析（required）

### 2.1 功能需求

1. 支持四维逻辑 NCHW 输入，以及任务要求的非连续 Tensor 适配。
2. 支持 FLOAT32、FLOAT16；BFLOAT16 按任务书限定于 Atlas 800T A2。
3. 支持合法的窗口、步长、padding 和 `ceilMode` 组合，覆盖重叠窗口、非重叠窗口及边界场景，不限定于附件固定 shape。
4. 消费前向生成的索引，不重新计算最大值；输出形状和类型与正向输入一致。
5. 按接口约束处理参数错误，并验证确定性计算开关下的行为。
6. 核心计算由自研 Ascend C Kernel 完成，不依赖 CPU 或 TBE 回退完成计算。

### 2.2 参数与约束

| 参数 | 方向 | 含义及约束 |
| --- | --- | --- |
| gradOutput | 输入 | 上游梯度，形状为 `[N,C,Hout,Wout]` |
| self | 输入 | 正向输入，提供原输入形状与类型 |
| indices | 输入 | INT8 索引容器，语义按任务附件约定的每通道独立 INT32 argmax 解释 |
| kernelSize | 属性 | 窗口大小，长度为 1 或 2 |
| stride | 属性 | 步长，长度为 0、1 或 2；空数组表示使用 kernelSize |
| padding | 属性 | 填充大小，长度为 1 或 2，范围按任务书校验 |
| dilation | 属性 | 长度为 1 或 2，值仅支持 1 |
| ceilMode | 属性 | 决定正向输出尺寸的取整方式 |
| gradInput | 输出 | 输入梯度，形状、类型与 self 一致 |

`self`、`gradOutput`、`gradInput` 使用一致的数据类型。索引容器与前向输出契约保持一致，不将其与其他历史接口的位掩码编码混用。输入暂不支持 NaN、-Inf；具体边界约束以任务书和接口说明为准。

## 3. 详细设计（required）

### 3.1 算子分析

设 `I(n,c,oh,ow)` 表示索引容器解码后得到的通道内输入位置，则：

$$
\mathrm{gradInput}(n,c,h,w)=
\sum_{oh=0}^{H_{out}-1}\sum_{ow=0}^{W_{out}-1}
\mathbf{1}\!\left[I(n,c,oh,ow)=hW+w\right]
\mathrm{gradOutput}(n,c,oh,ow)
$$

其中，`H`、`W` 为正向输入空间尺寸。不存在有效贡献的位置输出零；同一位置存在多个贡献时执行求和。

形状约束如下：

- `self`、`gradInput`：`[N,C,H,W]`；
- `gradOutput`：与正向池化结果的形状一致；
- `indices`：`[N,C,kH*kW,(ceil(Hout*Wout/16)+1)*32]`，dtype 为 INT8。

正向输出尺寸按窗口、步长、padding 和 `ceilMode` 推导，并处理末端窗口边界修正。索引按任务附件规定的存储契约读取，而非仅根据容器 dtype 推断含义。

### 3.2 总体实现方案

采用接口适配、Host Tiling、Device Kernel 三层结构：

```text
ACLNN 接口
  → 参数与形状校验、必要的 Tensor 规整
  → Host 计算分核与分块信息
  → Ascend C Kernel 批量搬入、梯度计算、结果写回
  → 输出视图适配
```

接口保持两阶段调用方式：`aclnnMaxPool2dWithMaskBackwardGetWorkspaceSize` 完成执行准备，`aclnnMaxPool2dWithMaskBackward` 在调用方指定的 stream 上执行。

### 3.3 Host 侧设计

- 统一解析窗口参数，校验 dtype、维度、输出尺寸及索引容器形状的一致性。
- 根据输入规模、数据类型、池化几何及平台资源生成 Tiling 信息。
- 合理划分多核任务与核内数据块，兼顾小规模调度开销和大规模并行度。
- 对非连续输入输出按接口约定进行规整与视图适配。
- 分块预算包含计算缓冲区和必要的临时空间；对尾块、边界和超大尺寸进行保护。

### 3.4 Kernel 侧设计

Kernel 分为初始化和处理两个阶段，处理过程采用 CopyIn、Compute、CopyOut 结构：

1. 初始化时读取 Tiling 信息，设置本核处理范围与局部缓冲区。
2. 批量读取梯度和索引，完成索引匹配及有效贡献计算。
3. 正确处理窗口重叠带来的累加，保证未命中位置为零，避免并发写入破坏结果。
4. 完成边界和尾块处理后批量写回输出。

优化重点为向量化计算、批量访存、多核负载均衡及减少重复数据处理。具体分块参数由形状和平台资源决定，不依赖用例编号。

低精度输入的重叠累加采用适当的计算精度，输出时统一转换，避免多次低精度舍入扩大误差。索引匹配使用整数语义，结果以任务提供的 golden 和精度标准验证。

## 4. 可维可测分析

### 4.1 精度与功能验证

- 使用任务配套 golden 和原有精度比较工具，遵循生态算子开源精度标准。
- 覆盖三种数据类型、多种 batch/channel、大小 shape、非方形窗口、不同步长、padding、ceilMode 及非对齐尾部。
- 补充窗口重叠、重复索引累加、零梯度、合法泛化参数、非连续 Tensor 和异常参数用例。
- 验证重复执行与确定性开关场景；非当前环境已覆盖的项目单独列入待验收清单。

### 4.2 性能验证

- Atlas 800T A2 以原 TBE 为对照，目标为 `TBE 耗时 / 自研耗时 ≥ 0.95`。
- 开发迭代中固定测试环境、输入及基线版本；自研实现预热 10 次、测量 10 次，统计设备侧 Kernel 耗时均值，不以 Host 提交耗时代替设备耗时。
- 一次调用包含多个 Kernel 时按同一调用范围汇总，保留原始数据与采样口径；基线与自研采样方式有差异时在报告中注明，不将其描述为完全相同的测量。
- 对未达标用例按数据规模、类型和窗口几何分类，结合性能采集定位问题；稳定修改后进行全量回归。
- Atlas 300V Pro 按任务书完成相应性能分析。小 shape 或其他需说明的场景提供分析材料，不以说明替代验收结果。

### 4.3 模型验证与可维护性

按任务书在 Atlas 300V Pro 上完成 yolov11 / DOTAv1 接入验证，目标为相对 Atlas 800T A2 的 mAP50 误差不超过 0.01。模型验证结果独立记录，不以单算子自测替代。

接口、Tiling 和 Kernel 分层维护；测试记录包含软件版本、设备、输入参数、实现版本、精度和性能结果，以便复现及回归。接口兼容性以既有调用契约和前后向索引契约为准。
