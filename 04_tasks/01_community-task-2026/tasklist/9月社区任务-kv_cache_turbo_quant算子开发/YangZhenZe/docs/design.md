# KvCacheTurboQuant 算子设计

## 需求背景（required）

### 需求来源

社区任务《kv_cache_turbo_quant 算子开发》要求基于 TurboQuant 两阶段量化方法，使用 Ascend C 开发键值缓存（KV cache）在线压缩算子，并提供 ACLNN 调用接口。

### 背景介绍

标准多头注意力（MHA）和分组查询注意力（GQA）的键值缓存随 token 数增加而增长。KvCacheTurboQuant 分别压缩键或值向量，减少缓存存储量。

#### KvCacheTurboQuant 算子功能分析

编码包含正交旋转后的标量量化，以及残差的 1-bit QJL（量化 Johnson–Lindenstrauss 投影）。输出由主量化索引、残差投影符号、输入范数和原尺度残差范数组成。

BF16 指 bfloat16，FP16 指 float16，FP32 指 float32。每条 128 维 BF16 向量原占 256 字节。下表取 qjl_dim=128，不计共享矩阵和分配器开销。

| 主量化位宽 | 主编码字节 | QJL 字节 | 两个范数字节 | 合计字节 | 压缩比 |
|---:|---:|---:|---:|---:|---:|
| 2 | 32 | 16 | 4 | 52 | 4.92× |
| 3 | 48 | 16 | 4 | 68 | 3.76× |
| 4 | 64 | 16 | 4 | 84 | 3.05× |

## 需求分析（required）

### 需求描述

编码在设备上完成，保持各 token、各 KV head 之间的数据独立。消费方保存匹配的矩阵、码本和位宽，用于后续向量恢复或内积估计。

## 详细设计（required）

### 算子分析

#### 支持数据类型与形状

设 T 为 token 数，K 为 KV head 数，d 为每条向量的维度，k 为 qjl_dim。任务书规定 4≤K≤32、d=128；属性 `mse_bits` 记为 b，取值为 2、3、4，默认 3。T、k 为正整数。Host 拒绝空张量和未确定的维度。

| 参数 | 方向 | 数据类型 | 形状 | 含义 |
|---|---|---|---|---|
| kv_vectors | 输入 | bfloat16 | [T,K,d] | 待编码向量 |
| rotation_matrix | 输入 | float32 / bfloat16 | [d,d] | 正交旋转矩阵 H 的存储近似 |
| qjl_matrix | 输入 | float32 / bfloat16 | [k,d] | 标准高斯投影矩阵 S 的存储近似 |
| quant_idx | 输出 | uint8 | [T,K,16b] | 主量化索引的位打包结果 |
| quant_qjl | 输出 | uint8 | [T,K,ceil(k/8)] | 残差投影的符号位 |
| quant_norm | 输出 | float16 / bfloat16 | [T,K] | 输入向量范数 |
| quant_gamma | 输出 | float16 / bfloat16 | [T,K] | 原尺度残差范数 |

两矩阵可分别选择存储类型，两范数也可分别选择输出类型。输出类型由输出张量描述指定。H 为归一化 Hadamard 矩阵或预生成的随机正交矩阵；S 的元素独立采自标准正态分布。两矩阵在推理期间固定。

逻辑调用的参数和返回顺序如下，`mse_bits` 是整数属性：

```text
(quant_idx, quant_qjl, quant_norm, quant_gamma) =
    KvCacheTurboQuant(kv_vectors, rotation_matrix, qjl_matrix, mse_bits)
```

#### 数学公式

对每条列向量 x 独立计算。C_b 是含 2^b 个值的升序码本；t 是相邻值的中点。维度下标为 0≤j<d，中点下标为 0≤a<2^b−1，投影下标为 0≤l<k。‖·‖₂ 表示欧氏范数，1{条件} 在条件成立时取 1，否则取 0。

```text
n       = ‖x‖₂
u       = x / max(n, 1e-30)，n=0 时取零向量
y       = H·u
t[a]    = (C_b[a] + C_b[a+1]) / 2
idx[j]  = Σ_a 1{y[j] > t[a]}
y_hat[j]= C_b[idx[j]]
r       = y - y_hat
ρ       = ‖r‖₂
γ       = n·ρ
v       = r / max(ρ, 1e-30)，ρ=0 时取零向量
z       = S·v
qjl[l]  = 1{z[l] ≥ 0}
```

输入提升为 FP32 后计算范数、归一化、旋转、量化和残差投影。码本与中点也在 FP32 中生成。n、γ 在写出时转为各自输出类型，采用最近舍入、中点取偶数；计算 γ 时使用尚未舍入的 n。

后文的 PyTorch eager 参考编码指在 NPU 上按本文编码公式、码本和位布局逐算子执行的实现，不使用图编译或自定义融合内核。它与待测算子接收相同的设备输入，并输出相同顺序的四个张量。

#### 固定码本

码本取自任务附件参考编码 golden.py 中的 CENTROIDS。以下十进制常量先转为 FP32；相邻值在 FP32 中相加，再乘 0.5 得到中点。

```text
C_2 = [-0.1335033178, -0.04002048075, 0.04002048075, 0.1335033178]
C_3 = [-0.19020693, -0.1187859178, -0.06682205945, -0.02166347019,
        0.02166347019, 0.06682205945, 0.1187859178, 0.19020693]
C_4 = [-0.2414890379, -0.1828317791, -0.1429702938, -0.1109927073,
       -0.08325428516, -0.05802082643, -0.03428063914, -0.01134236995,
        0.01134236995, 0.03428063914, 0.05802082643, 0.08325428516,

```

#### 位布局与边界

主编码第 j 维索引的第 p 位写入位偏移 `j·b+p`，其中 `0≤p<b`。字节内低位在前；每 8 个维度形成 b 个字节，3-bit 编码允许跨字节。QJL 第 l 个符号写入字节 `l//8` 的第 `l%8` 位。各向量独立打包。QJL 最后一个字节中超出 k 的高位补零。

#### 编码结果的消费

消费端将主编码解包为索引，再查 C_b 得到 ŷ。将 QJL 位按 `0→−1、1→+1` 解包为 s。令 n_s、γ_s 分别为保存并读取的 quant_norm、quant_gamma，恢复公式如下。

```text
主重构：  x̂ = Hᵀ(n_s·ŷ)
QJL 重构：x̂ = Hᵀ(n_s·ŷ + sqrt(π/2)/k · γ_s · Sᵀs)
内积估计：qᵀx̂，其中 q 为原向量空间中的查询向量
```

QJL 系数来自标准高斯投影的符号估计，k 个投影取平均。γ_s 已包含输入范数，残差修正不再乘 n_s。残差在旋转空间中计算，因此消费端先组合主重构与残差修正，再乘 Hᵀ。QJL 修正不保证向量重构误差下降。

### 算子实现

#### 实现方案

##### ACLNN 调用

ACLNN 是 Ascend C 算子的主机侧调用接口。构建目标为 Ascend910B，CANN 根据算子注册定义生成接口和安装包。调用环境须安装该包、加载包的环境配置，并链接生成的自定义算子 API 库。调用方在同一设备上准备三个输入及四个输出，按以下顺序执行。

1. 调用 `aclnnKvCacheTurboQuantGetWorkspaceSize`，依次传入 kv_vectors、rotation_matrix、qjl_matrix、整数属性 mse_bits、quant_idx、quant_qjl、quant_norm、quant_gamma，并接收工作区字节数和执行器。
2. 分配设备工作区，调用 `aclnnKvCacheTurboQuant`，传入工作区地址、字节数、执行器和设备流。
3. 检查两阶段调用的返回状态。成功提交后，等待设备流执行完成，再读取或消费输出，释放本次调用所用资源。

算子注册的默认位宽为 3；直接调用 ACLNN 时传入整数属性值。输出形状按接口表分配。

##### 3.2.1 host侧设计

Host 指主机侧参数处理与分块计划计算。Host 将输入展平为 N=T·K 条行向量，校验形状、数据类型、位宽、ND 格式及尺寸乘法溢出。张量的原始形状与存储形状须一致。非法描述使形状推导或分块计划生成失败。调用方负责 H、S 的数值性质，Host 不检查正交性和高斯分布。

设备的 AIC 执行矩阵运算，AIV 执行向量运算。一个 AIC 与一个 AIV 组成核对。可用核对数 P 取平台报告的 AIC 数与 AIV 数的较小值。UB 是核内统一缓冲区；GM 是设备全局内存。

###### 分核策略

各核输出区间的起点对齐四个输出的 32 字节搬运边界，避免不同核写同一搬运块。令 B_i=16b 为主编码每行字节数，B_q=ceil(k/8) 为 QJL 每行字节数，行组大小 A 按以下公式计算。gcd 为最大公约数，lcm 为最小公倍数。

```text
A = lcm(16, 32/gcd(B_i,32), 32/gcd(B_q,32))
G = ceil(N/A)
C = min(G, P, max(1, floor(G/8)))
g = floor(G/C)
e = G mod C
```

C 是实际使用的核对数。编号 c 从 0 到 C−1。该核从第 `(c·g+min(c,e))·A` 行开始，负责 `(g+1{c<e})·A` 行，末尾裁剪到 N。每核存在与行数无关的初始化开销，因此按每核至少 8 个行组限制核数；不足 8 个行组时使用一个核对。

###### 数据分块和内存优化策略

所有位宽及矩阵类型共用同一 UB 预算。固定预算为 74624 字节，含 8192 字节基础 API 尾部保留区、128 字节码本和中点、65536 字节矩阵缓冲，以及 768 字节打包表。每行预算按 32 字节对齐后为 2208 字节。每块最多 64 行。

设 U 为平台报告的 UB 字节数，M 为分配行数最多的核的行数。行块大小 R 如下。

```text
R = min(floor(floor((U−74624)/2208)/A)·A, M, floor(64/A)·A)
```

U 不足固定预算或 R 为零时，Host 返回资源不足。192 KiB UB 下，足够大输入在 k=128 时使用 48 行块，在 k=129 时使用 32 行块。

行块主要保存四份 FP32 向量，分别用于单位输入、旋转结果、桶号和临时计算。输入搬运及类型转换复用临时计算空间。查表偏移复用单位输入空间，查表结束后才写残差。范数归约复用旋转结果空间，此时该空间已无待消费的矩阵结果。其余行内预算保存比较掩码、范数及广播结果。

工作区由 CANN 系统区和用户区组成。系统区大小由 `GetLibApiWorkSpaceSize()` 提供。用户区为每个核对分配 `R·128·4` 字节 FP32 矩阵结果区，旋转与投影顺序复用。设备通过 `GetSysWorkSpacePtr()` 和 `GetUserWorkspace()` 分别定位两区。通用计划器对张量和传入的工作区字节数执行 INT64_MAX 上限检查。

###### tilingkey 规划与设备参数

Host 向内核传递 N、k、A、g、e、R、C、b 及 FP32 矩阵乘法分块参数。矩阵乘法将右操作数转置，从而对按行存储的输入计算 `U·Hᵀ` 和 `V·Sᵀ`。内核分派键取 b，类型组合由 CANN 生成的内核变体分派。

##### 3.2.2 kernel侧设计

Kernel 指设备侧编码内核。内核使用 `MIX_AIC_1_1` 一比一混合核调度。AIV 执行归一化、分桶、残差归一化和打包；AIC 通过 Ascend C Matmul 矩阵乘法服务执行旋转与残差投影。每核按行块循环执行以下步骤。

1. 搬入 BF16 输入并提升为 FP32，计算 n 和 u。
2. 计算旋转结果 y，按码本中点求 idx，并输出主编码。
3. 查码本得到 ŷ，计算 r、ρ、γ 和 v，输出两个范数。
4. 按至多 128 个投影行划分 S，计算各块投影，输出 QJL 字节。

两矩阵均为 FP32 时，Matmul 从 GM 读取矩阵。任一矩阵为 BF16 时，内核在每次乘法前将当前矩阵块搬入共用 UB，按需提升为 FP32。`IterateAll<true>` 同步计算并将结果写入该核对的 GM 结果区，随后搬回有效行。`SetOrgShape` 将结果行距固定为 128 个 FP32 元素，尾投影块只消费有效列。

范数计算先将平方值的前后 64 维相加，再执行 `WholeReduceSum` 归约和平方根。`Brcb` 广播每行范数，`Div` 复用每行除数。2-bit 和 3-bit 分桶用 `Compares`、`Select` 累加超过中点的次数。4-bit 分桶按 8、4、2、1 的步长二分查找中点。`Gather` 按桶号查码本。Matmul 配置采用 `MatrixMadType::NORMAL`，设备用 `SetHF32(false, 0)` 关闭 HF32 降精度模式。所有传入 Matmul 的张量均设置容量，限制 API 的搬运范围。

主编码先将桶号乘以位布局对应的二次幂权重。2-bit 和 4-bit 分别将每 4 个和每 2 个桶号归约成一个字节。3-bit 将每 8 个桶号归约为一个不超过 2²⁴−1 的整数，FP32 能精确表示全部中间值。内核复制该整数，再用二次幂缩放、向下取整和整数掩码提取三个字节。字节值经 FP16 转为 uint8，转换无舍入误差。

QJL 尾列填充使用对齐的向量地址和位掩码。k≠128 时，内核把 16 字节行距的比较掩码复制成 32 字节行距，再逐行搬出，以满足设备输出搬运单元 MTE3 的 UB 源地址对齐要求。

内核用 `HardEvent` 同步标量访问、向量运算和直接内存搬运（DMA），用向量流水屏障控制缓冲读写顺序。事件通过 `TPipe::FetchEventID` 获取，避免占用 Matmul 已分配的事件。`DataCopyPad` 只写有效输出字节。

### 算子约束限制

- 张量采用按行优先连续存储的 ND 布局，不支持通用逐元素广播。全部向量共享固定的 H、S，不支持额外的批次矩阵维度。
- 输入及计算中间结果须有限，不定义 NaN、Inf 或溢出的编码语义。
- 输入、输出不得重叠，算子不修改输入。调用方保持所有缓冲存活至设备执行完成。
- 不支持多头潜在注意力（MLA）的低秩缓存、异常通道分组及通道混合位宽。
- 范围仅含编码，不含矩阵生成、反量化、注意力计算或缓存分页管理。

#### 编码比较

测试程序在 NPU 上执行任务附件原始参考编码，与候选算子使用相同的设备输入。类型扩展只适配输入存储与范数输出转换；FP16 范数从未舍入的 FP32 值转换。编码比较先检查四输出的数量、形状、类型、有限值、设备位置及输入未被修改，再进行逐元素比较。

附件容差为 `[单元素允许相对误差, 允许超差比例]`，五个用例均采用以下数值。

| 输出 | 单元素允许相对误差 | 允许超差比例 |
|---|---:|---:|
| quant_idx | 0 | 0.00001 |
| quant_qjl | 0 | 0.000011 |
| quant_norm | 0 | 0 |
| quant_gamma | 0 | 0 |

比较器在 FP64 中计算 `abs(actual−reference)/abs(reference)`。参考与实际均为零时误差为零，仅参考为零时误差为正无穷。误差严格超过第一项的元素计为超差，超差比例不大于第二项时通过。打包输出按字节计数。

#### 质量测量

测试程序采用以下解码分工和统计方法。分工、查询分布与聚合方法是本项目的测试约定，需随设计评审确认。

| 指标 | 解码方法 | 逐向量误差 | 批次统计量 |
|---|---|---|---|
| 重构相对 MSE | 主重构 | ‖x̂−x‖₂²/‖x‖₂² | 算术平均 |
| 内积相对误差 | QJL 重构 | abs(qᵀx̂−qᵀx)/abs(qᵀx) | P95 |

解码和统计使用 FP64。P95 将 N 个误差升序排列，取第 ceil(0.95N) 个值。全部非零分母样本参与统计；出现零分母或非有限误差时，对应整组不能形成有效质量判定，不以删除样本后的统计代替。

所有位宽采用相同任务阈值。编码对照通过不等于质量通过。参考编码也执行相同质量测量，以区分实现差异和算法在该输入及查询集合下的质量问题。QJL 的期望平方绝对内积误差保证不能直接推出相对误差 P95 保证，真实内积接近零时相对误差可能较大。

#### 性能测量

测试使用“支持硬件”表所列环境，记录整机型号和实际依赖版本。

双方使用预先放在 NPU 的相同输入，各预热 10 次、采样 30 次。每次调用前后同步设备，测量完整编码调用至输出就绪的墙钟时间。计时包含调用、内部内存分配及同步等待，不含输入上传、结果下载和精度统计。加速比为参考平均耗时除以候选平均耗时。计时前后均检查正式编码容差和输入未修改。任务表中的固定基线只作对照，加速判定采用同机实测值。

prefill 指模型一次处理输入序列并生成各层 KV 的阶段。本项目用隐藏维 4096、8 个 KV head、head_dim=128、序列长 2048、批大小 1 的 BF16 单层负载测量。KV 生成包含两次 `[2048,4096]×[4096,1024]` 矩阵乘法；编码分别调用一次 K 编码和 V 编码。两侧独立预热并同步计时，吞吐均按 2048 除以单层平均耗时计算，单位为 token/s。该负载是本项目选定的测试方法，其结论限于此负载，不代表所有模型的端到端吞吐。
