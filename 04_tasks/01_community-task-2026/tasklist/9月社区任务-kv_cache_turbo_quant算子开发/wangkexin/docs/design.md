# KvCacheTurboQuant 算子设计

本文说明 Atlas A2 上的编码算子设计、接口与验证方法。补充说明中的开发假设用于开展实现，正式验收以任务书及维护者确认的评价方法为准。

# 需求背景

## 需求来源

依据[社区任务详情](https://www.hiascend.com/activities/task-center/details/6d3df013343845608677c85f3c58d4d6)及其[任务附件](https://www.hiascend.com/p/resource/202609/25e71624009c46969b4db01afca60aa8.zip)，在 Atlas 800T A2、CANN 9.1.0+ 上使用 Ascend C 实现标准 MHA/GQA KV cache 在线编码，通过 aclnn 接口交付至 `cann/ops-transformer/experimental/attention/kv_cache_turbo_quant/`。

## 背景介绍

算子以正交旋转后的标量量化作为主编码，再以 QJL 符号编码保留残差信息。压缩输出供后续计算使用，本算子不实现完整 attention、Value aggregation 或 MLA。默认主编码为 3-bit，配合 D=J=128 的 QJL 和两个 16-bit 范数，每个 head 占 68 字节；相对 BF16 的 256 字节约压缩 3.76 倍。论文中的混合 3.5-bit 模式不属于首版范围。

# 需求分析

## 需求描述

实现输入归一化、正交旋转、2/3/4-bit 固定码本量化、残差归一化及高斯投影、低位优先的位打包，并输出输入范数和原尺度残差范数。功能需对齐附件 golden 的计算语义，性能目标为相对功能等价 PyTorch eager reference 加速至少 10 倍。

## 需求拆解

1. aclnn 接口完成形状与类型校验、输出形状推导、workspace 查询和异步执行。
2. Kernel 完成 FP32 中间计算，并保持量化边界、符号边界与字节布局一致；具体矩阵与累加方案通过四输出比对验证。
3. 自测分别验证四输出一致性、统计重构质量、内积估计质量、性能和输出空间占用。
4. 设计、实现、测试步骤与报告应支持验收方从标准入口复现。

# 详细设计

## 算子分析

对每个输入向量 x，计算：

```text
n = ||x||₂
u = x / max(n, 1e-30)             # n=0 时取全零
y = H u
idx[d] = count(y[d] > boundary)
p[d] = centroid[idx[d]]
r = y - p
rho = ||r||₂
gamma = n * rho
r_unit = r / max(rho, 1e-30)      # rho=0 时取全零
qjl[j] = (S r_unit)[j] >= 0
```

centroid 与 boundary 采用附件 golden 的固定数值。idx 的比较是严格大于，qjl 的比较包含等号。norm 与 gamma 以指定输出类型保存；D=J=128 的官方用例输出类型均为 BF16。

| 参数 | 方向 | 官方 op.json 数据类型 | 形状 |
| --- | --- | --- | --- |
| kv_vectors | 输入 | BF16 | [T,H,128] |
| rotation_matrix | 输入 | FP32 | [128,128] |
| qjl_matrix | 输入 | FP32 | [J,128] |
| quant_idx | 输出 | UINT8 | [T,H,ceil(128*b/8)] |
| quant_qjl | 输出 | UINT8 | [T,H,ceil(J/8)] |
| quant_norm | 输出 | BF16 | [T,H] |
| quant_gamma | 输出 | BF16 | [T,H] |
| mse_bits | 属性 | int | 支持 2/3/4，默认为 3。 |

输入按连续 ND 布局组织；head_dim 固定为 128，num_kv_heads 支持任务书要求的 4～32。表中形状里的 H 表示 head 数，数学公式里的 H 表示旋转矩阵。

任务书还包含 BF16 矩阵和 FP16 范数输出，而 op.json 未声明对应组合。最终支持范围和输出类型选择方式需与验收方确认，不能以本表默默排除任务书范围。官方用例的 J=128；可变 J 及尾部 padding 约定同样待确认。

## Host 侧设计

将 T×H 展平为独立行，校验输入维数、D、矩阵方向、bit-width、输出字节数和整数乘法溢出。按照目标设备可用核数、UB 容量和行数选择每核行数、矩阵分块及缓冲大小。形状较小时研究行内并行以减少空闲，形状较大时优先复用 H/S。

OpDef、InferShape 和 Tiling 按目标仓标准接入。aclnn 使用 workspace 查询与执行两段式接口；具体生成机制与函数声明以仓库构建产物为准，避免与手写 API 重复。合法参数范围之外的输入返回明确错误，异步执行遵守调用方 stream。

## Kernel 侧设计

首个正确性版本采用 FP32 Vector 计算路径。按行或小批量读入 BF16 x 并转 FP32，完成范数和归一化；分块加载 H 执行旋转，按固定边界求索引并重构残差；计算 rho/gamma，再按 golden 顺序执行残差归一化和 S 投影。最后打包 UINT8 输出，并将 norm/gamma 转为输出类型。

索引采用每八维组成一个低位优先字：第 j 维索引左移 j×b 位，再以小端顺序写出 b 个字节；QJL 每八维组成一字节。输出搬运必须处理 48 字节的 3-bit 行宽、16 字节 QJL 行宽及相邻 head 的边界，不能用扩大写入覆盖下一行。

性能优化首先研究多行复用矩阵、FP32 归约方式、矩阵分块和搬运计算流水。若测量表明矩阵计算主导，再评估 Cube 路径；接受候选的前提是四输出与统计质量同时满足要求。不能未经验证把 FP32 矩阵转为 BF16，也不能用 Hadamard 专用变换替代任意正交矩阵。

## 支持硬件与约束

首版以 Atlas 800T A2、CANN 9.1.0+ 为验收目标。具体 910B 子型号及框架版本随正式 baseline 一起确认。输入 H/S 在推理期间固定，但作为接口输入处理；不假设进程中永不改变，不引入未经定义的跨调用缓存。

空输入、非连续输入、NaN/Inf、J 的可变范围及额外 dtype 组合待验收方明确。零向量和投影零点按 golden 处理，不通过改变编码规避边界问题。

# 可维可测分析

## 精度与性能标准

编码测试覆盖全部官方五例，并补充 2/3/4-bit 字节布局、零向量、量化阈值相等及两侧、投影零点、H=4/32 和尾部边界。四项输出分别报告不匹配数与范数差异，不以浮点误差平均值掩盖编码翻转。

质量测试另行计算重构和 QJL 内积估计。任务书要求 `MSE/||x||² <0.05` 和内积相对误差 p95<0.1；MSE 聚合、是否含 QJL 重构、查询分布、投影缩放和零分母处理需与官方评价脚本一致。编码对拍通过不代表统计指标已通过。

测试代码将矩阵生成、四输出比对、重构和误差统计分别组织，使官方补充矩阵或统计定义后可独立替换并复验。开发阶段使用注明生成方法与 seed 的合成矩阵；同时报告主重构、标准 QJL 重构及不同内积分母的诊断结果，明确查询分布，不通过选择较小结果或过滤样本代替验收。合成矩阵的具体数值和结构不构成 kernel 的限制。

性能按以下官方五例与功能等价 eager baseline 比较，head_dim=128、num_kv_heads=8。

| --- | --- | --- | --- | --- |
| gqa_decode_b1 | 1 | 3 | 1491.676 | 149.1676 |
| gqa_decode_b64 | 64 | 3 | 1552.784 | 155.2784 |

## 补充说明：矩阵和质量评价的开发假设

官方附件引用的两份矩阵尚未随包提供，统计质量定义已在[任务讨论帖](https://gitcode.com/cann/ops-transformer/discussions/14)及 [Issue #5627](https://gitcode.com/cann/ops-transformer/issues/5627)集中提问。参考 [TurboQuant 论文](https://arxiv.org/html/2504.19874v1#S3.SS2)与[配套 Attention Score 附件](https://www.hiascend.com/p/resource/202609/1ce0402fb6c6483fb1f359e3405fcc7b.zip)中的公式，开发阶段采用以下可替换的假设，不据此修改任务阈值或声明验收通过。

### 矩阵生成

H 为满足 `H Hᵀ≈I` 的 128×128 正交矩阵。默认用固定 seed 的标准高斯矩阵做 QR，并规范 R 对角符号；同时用 `Hadamard(128)/sqrt(128)` 检查不同旋转结构。S 为 J×128 矩阵，元素独立服从 `N(0,1)`。矩阵按 FP32 连续行主序保存并记录 seed；这些是开发合成数据，官方文件或生成方法明确后替换。

H/S 始终作为调用方输入，kernel 不生成随机矩阵、不写死矩阵值，也不依赖 Hadamard 专有结构。行向量计算分别为 `u @ H.T` 和 `r_unit @ S.T`。

### 重构与内积估计

设解包后的主重构码本向量为 c，QJL 比特映射为 `s=2*bit-1`，保存的范数为 n、gamma。采用以下测试侧重构：

```text
x_main = H.T @ (n * c)
x_qjl  = H.T @ (n * c + gamma * sqrt(pi/2) / J * S.T @ s)
score  = dot(H @ q, n * c)
         + gamma * sqrt(pi/2) / J * dot(S @ (H @ q), s)
```

这里 QJL 系数对应标准高斯 S；若官方定义 S 的标准差为 sigma，须核对相应解码系数，不能仅改变投影尺度却沿用原系数。上述重构和 score 仅用于评价编码输出，不属于本 encode 算子的输出接口。

对 `MSE/||x||²<0.05`，优先研究默认 3-bit 主重构的平均相对平方 L2 误差，即逐向量 `||x_main-x||²/||x||²` 再取样本均值。该解释与 3-bit 标量量化的预期失真量级相符，但 MSE 聚合、是否包含 QJL 及 2/4-bit 适用要求仍由维护者确认；测试会分别保留全部位宽和两种重构的结果，不将开发假设作为其他位宽豁免依据。零向量另外验证编码结果，重构相对误差的零分母按官方规则处理。

对内积误差，同时记录任务书的 `|score-dot(q,x)|/|dot(q,x)|` 和辅助诊断指标 `|score-dot(q,x)|/(||q||*||x||)`。独立查询可能使真实内积接近零，因此暂将“按范数乘积归一化”或“使用相关查询分布”作为两种待确认解释。开发对照包括独立标准高斯查询与 `q=x+0.35*高斯噪声` 的相关查询，分别统计 p95；不混合样本、不删除近零内积样本，也不将辅助指标通过视为原指标通过。零分母样本单独计数并注明未定义，正式处理规则随官方脚本确定。

测试模块保留这些区别，官方答复后更新受影响的数据生成或评价部分；若答复改变编码语义、必需 dtype 或性能计时范围，则同步修订相应接口、实现方案和验证方法。

## 内存与兼容性

每 head 的物理输出字节数为 `ceil(128*b/8)+ceil(J/8)+sizeof(norm)+sizeof(gamma)`。矩阵与 workspace 单独列明。任务书“内存要求不涉及”与统一提交材料中内存报告的关系应在交付前确认。

这是新增算子，不修改其他算子的 ABI 或缓存布局。正式提交包含设计文档、算子说明、可复现自测代码、报告及私有验收代码地址；设计评审与代码验收分别记录。
