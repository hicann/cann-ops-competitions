# 需求背景（required）

## 需求来源

[9月社区任务-kv_cache_turbo_quant算子开发](https://www.hiascend.com/activities/task-center/details/6d3df013343845608677c85f3c58d4d6)。实现Ascend C在线编码算子，通过aclnn工程化交付至ops-transformer，目标目录按任务书为`experimental/attention`，最终结构服从维护者确认。

## 背景介绍

对标准MHA/GQA的K或V向量，采用正交旋转、标量MSE量化与QJL残差符号编码。首版不含MLA、混合3.5-bit模式、attention score计算、softmax或V聚合，也不直接改写分页KV缓存。

默认d=128、qjl_dim=128、mse_bits=3时，每head输出48字节主编码、16字节符号编码、各2字节norm/gamma，合计68字节；相对BF16原向量256字节约3.76倍压缩。此为编码存储比，不是包含输入、H/S矩阵和workspace的进程峰值显存比。网页宣传3.5-bit与附件首版4.25-bit的优先级待Q1确认。

# 需求分析（required）

## 需求描述与接口

令T=num_tokens，H=num_kv_heads，D=128，J=qjl_dim，b=mse_bits；行数N=T×H。

| 参数 | 方向 | 形状 | 附件op.json类型 | 任务书扩展/待确认 |
| --- | --- | --- | --- | --- |
| kv_vectors | 入 | [T,H,128] | BF16 | H为4–32，T上限/空输入待确认 |
| rotation_matrix | 入 | [128,128] | FP32 | 任务书也列BF16 |
| qjl_matrix | 入 | [J,128] | FP32 | 任务书也列BF16，J是否固定128待确认 |
| quant_idx | 出 | [T,H,ceil(128b/8)] | UINT8 | b=2/3/4 |
| quant_qjl | 出 | [T,H,ceil(J/8)] | UINT8 | 非8倍数J尾位语义待确认 |
| quant_norm | 出 | [T,H] | BF16 | 任务书也列FP16 |
| quant_gamma | 出 | [T,H] | BF16 | 任务书也列FP16 |

格式按op.json为ND，无广播。暂以连续输入设计；非连续输入是否拒绝或适配需按目标仓约定确认。首轮基线按附件FP32矩阵/BF16输出复现，不意味着删除任务书其他dtype要求。

属性`mse_bits`为整数，默认3，允许2/3/4；其他值返回参数错误。接口候选名称为`aclnnKvCacheTurboQuantGetWorkspaceSize`和`aclnnKvCacheTurboQuant`，按aclnn两段式接口先校验输入及输出tensor、计算workspace，再在调用者stream上执行。不读取设备输入值来选择实现路径。

# 详细设计（required）

## 算子分析

### 数学与数值语义

下面按附件golden.py的行向量约定记录，不以实数等价替代浮点实现一致性：

```text
n = ||x||2
u = n > 0 ? x / max(n, 1e-30) : 0
y = u @ H.T
boundary[k] = (centroid[k] + centroid[k+1]) / 2
idx[j] = count(y[j] > boundary[k])
yhat[j] = centroid[idx[j]]
r = y - yhat
rn = ||r||2
gamma = n * rn
ru = rn > 0 ? r / max(rn, 1e-30) : 0
p = ru @ S.T
qjl_bit[j] = (p[j] >= 0)
```

- 使用附件2/3/4-bit各自centroid常量，不自行重新拟合。阈值恰好相等时归较低桶；QJL投影为零时编码1。
- golden对H/S与输入转FP32计算，最终norm/gamma转BF16；实际NPU matmul内部精度模式、归约顺序需锁定版本并验证，不能仅凭FP32张量类型推定逐位结果。
- 任务书写`sign(S @ r)`，golden实际对`r/||r||`投影：非零有限实数下符号相同，浮点零附近未必相同。初版保留golden的归一化步骤，Q5确认前不省略。
- 零输入不等于所有编码字节为零：继续按centroid、比较和sign规则计算，norm/gamma为零时的输出依golden验证。
- NaN/Inf、极小值、负零和零残差覆盖政策待确认；不得静默吞错或随意钳制到正常结果。

### 位布局

每8个索引为一组，构成逻辑整数`w = sum(idx[lane] << (lane*b))`；按低字节先出输出b个字节。b=3时每组24bit/3bytes，避免错用每值独立字节布局。QJL每8个符号位输出1字节，lane0为最低位。按每行独立打包，不能跨head拼接。

D固定128，主编码无尾部。若J允许非8倍数，golden会补零至8的倍数；任务接口尾位规则仍需Q7确认。计算shift及转换时使用宽度明确的无符号整数，不能依赖溢出行为。

## 算子实现

### Host侧设计（拟）

- 校验rank、D、H范围、H/S矩阵维度、b合法值和dtype组合；避免N、输出长度和workspace大小乘法溢出。
- 从目标平台获取可用核数及内存资源，不硬编码未经核实的A2/A3参数。
- tiling元信息拟包含N、J、b、行块大小、矩阵列块大小、尾行数、路径标记与workspace段偏移。
- 路径选择仅依shape/dtype/硬件，不依输入具体数值；H/S是运行时输入，即使推理期间固定，也不按测试矩阵硬编码结果。
- 不在host读取全量NPU输入做计算，不把拷贝/初始化成本藏到计时区间外。

**TilingKey规划。** 初始`key=100+b`，即102/103/104分别表示路径A的2/3/4-bit，限定BF16输入、FP32矩阵、BF16范数输出与D=J=128；尾行数量放在tiling数据中，不另外增加key。预留`key=200+b`给路径B，只有精度和性能验证通过并冻结shape阈值后才启用分发；当前不得仅因N较大就进入未验证路径。其他dtype或J扩展需增加明确的类型/形状校验及独立分支，不与上述key隐式共用。非法b、未支持组合和大小溢出在host返回错误；实现阶段补齐任务书要求的组合，不能把阶段性拒绝作为最终功能豁免。

### Kernel侧设计（拟）

**路径A：精度优先、小N向量化。** 将head行分配给核；按资源约束对H/S输出维度分块搬入，计算范数、旋转、阈值、残差、投影与打包。尽量融合阶段减少启动开销；先处理N=8的小case，核间不并发写同一编码字节。

候选分核以16行作为所有权分组（首轮J=128）：组号g覆盖`[16g,min(16g+16,N))`，核c处理`g=c,c+C,...`，其中`C=min(可用Vector核数,ceil(N/16))`。每核逐行完成数学计算，将本组的4项输出汇集后写回。每行主编码为`16b`字节、QJL为16字节、两个范数各2字节；完整16行组的各输出起点和长度均为32字节对齐。末组仅写有效字节，不向相邻组或tensor分配边界外填充；若目标搬运接口不支持精确短写，则使用受控的尾部搬运方案并先作越界测试。任何J扩展须重算分组对齐条件，不能直接沿用该结论。

初始核内矩阵块取`B=16`行、D=128：旋转和QJL投影顺序执行，复用同一`B×D` FP32矩阵缓冲，不同时常驻H/S。内存规划如下，均为候选上界，不是已测硬件容量：

| UB用途 | 预算字节 |
| --- | ---: |
| 矩阵块 | `4BD=8192` |
| 逐元素乘积块 | `4BD=8192` |
| 单行unit、rotated、residual、辅助向量 | `4×4D=2048` |
| BF16输入行 | `2D=256` |
| 16行组打包输出、norm/gamma | `16×(16b+16+4)`，b=4时1344 |
| 归约/转换暂存、对齐和标量保留区 | 暂留8192，最终按所选API要求校核 |
| 合计最大值 | 28224（约27.6KiB） |

Host必须用目标平台资源信息及各API实际暂存需求重新核算；预算不足时缩小B或返回不支持，不能超额分配。初版单缓冲，阶段间显式同步；逐行复用中间量，不引入跨核同步。路径A没有自定义全局中间tensor，框架自身workspace另按构建链申报。N=8仅用一个所有权组，启动/串行计算代价需实测；若不达性能门槛，再设计更细并行及独立归并阶段，不能忽略短范数输出的核间写入风险。

**路径B：大N分阶段矩阵候选。** 候选顺序：归一化→旋转矩阵乘→量化/残差归一化→QJL矩阵乘→符号打包。各阶段可分kernel并以workspace交接；阶段间使用明确的执行顺序，禁止假设跨核隐式屏障。

路径B先保守分配unit `[N,D]`、rotated/residual `[N,D]`、projected `[N,J]`三个FP32区及两个`[N]` FP32标量区；各区按平台要求向上对齐，张量部分上界为`4N(2D+J+2)`字节加对齐余量。N=16384、D=J=128时为25296896字节（约24.125MiB），另加矩阵库按接口查询的workspace；不能把库workspace算作零。量化阶段按行独占地复用rotated区存residual_unit，下一阶段只在前序kernel完成后读取。生命周期复用优化必须先用事件/stream顺序证实无覆盖再启用。

H/S为FP32且编码含不连续阈值，不能为使用Cube自行降为BF16。矩阵硬件路径、累加精度及是否保持统计/逐元素验收均为待真机验证项；若精度不满足，改精度保持路径并重新测性能。Vector-only也不预先承诺10倍加速。

**Workspace与搬运。** 先按中间量生命周期规划并复用区段；报告N/J相关上界、缓冲数量和峰值，不声称零workspace。单个128×128 FP32矩阵为64KiB，不能假设H、S与所有临时量可同时常驻片上。只有单缓冲验证后才比较双缓冲；tail使用合法的非对齐搬运方案，具体API待核实。

**工程布局。** 任务要求aclnn，而目标仓贡献指南同时列生态最简kernel与标准op_host/op_kernel两种形式。拟提供def/shape推导、tiling、kernel、aclnn测试和README，Q8确认实际目录和构建链后冻结文件清单；不把最简直调demo冒充aclnn交付。

## 支持硬件

附件要求Atlas800T A2、CANN9.1.0+；网页说明A3。已取得开发环境的运行时SoC为`Ascend910_9382`，CANN为9.1.0，驱动26.1.1、固件9.0.0.9.220；这些是环境识别结果，不是算子支持或精度性能通过证明。A2/A3最终验收范围仍请Q1确认，不以已有A3环境取消A2要求。编译器、框架及参考脚本版本随实际基线证据冻结。

## 算子约束限制

不包含MLA、3.5-bit混合模式、分页更新、attention下游或在线更新H/S；不能从5个样例推定全量shape只有H=8/J=128。类型、J范围及异常输入政策仍按Q7收敛。

# 可维可测分析

## 特性交叉分析

本算子为单设备在线编码，不引入分布式通信、随机数生成或跨调用持久状态；不改变调用者stream，不隐式执行设备级同步。H/S由调用方提供，重复调用之间不假定矩阵内容不变。aclnn workspace由调用方按查询结果持有至本次stream执行完成；图模式支持须用目标框架验证，当前不作兼容承诺。异常输入、dtype扩展与矩阵加速路径分别验证，避免优化路径绕过原型校验；现有算子不修改，不引入全局配置副作用。

### 验证顺序与停止条件

1. 先获取官方矩阵及统计评价脚本，复跑参考自身：如果参考不达标，保留完整失败证据，澄清算法/评价契约，不靠调kernel掩盖。
2. 先写会因错误矩阵方向、阈值比较、位序或gamma定义失败的focused测试；再实现最小计算路径。
3. 首探小T启动开销、大T矩阵吞吐、2-bit统计质量及阈值附近编码稳定性；不只挑最好看的case。
4. 同设备/版本、相同计时边界复跑reference和候选，记录预热、重复次数、统计量、频率状态和同步点。全部必须kernel纳入计时，不拿CPU墙钟对比单kernel事件时间。
5. focused通过后在冻结commit运行一次全量；环境或相关候选未变化不反复全量。测试日志、矩阵/脚本哈希与commit绑定，截图来自同次测试。
6. 任何必需case精度或性能未达标，或Q1–Q8影响的验收口径尚不确定，不标注“最终代码/验收材料可提交”。设计评审PR用于收敛这些问题，不等同最终验收申请。
