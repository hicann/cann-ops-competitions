aclblasCaxpy算子设计文档
1. 需求背景
1.1 需求来源
本需求为昇腾CANN社区2026年度算子开发任务，针对Ascend 950PR芯片，开发BLAS标准复数向量运算算子aclblasCaxpy，对标业界主流cuBLAS cublasCaxpy算子与Netlib标准caxpy实现，补齐昇腾ops-blas开源仓复数向量基础运算能力。
1.2 背景介绍
BLAS（基础线性代数子程序库）是深度学习、科学计算领域的核心基础库，复数向量线性组合运算是矩阵运算、傅里叶变换、信号处理等场景的高频基础算子。目前昇腾ops-blas开源仓缺少适配Ascend 950PR芯片的单精度复数向量axpy算子，无法满足复数场景的线性计算需求。
本次基于Ascend C编程语言开发aclblasCaxpy算子，实现单精度复数（complex64）向量线性组合更新计算，完全对齐cuBLAS、Netlib标准算子语义与参数规范，采用Kernel直调架构开发，适配昇腾NPU硬件特性，保障算子精度与性能达标，开发完成后合入昇腾开源ops-blas仓库，完善昇腾生态复数线性运算能力。
2. 需求分析
2.1 需求描述
基于Ascend 950PR芯片、CANN 9.1.0版本，使用Ascend C语言开发aclblasCaxpy句柄式BLAS算子，实现单精度复数向量线性组合原地更新计算，计算公式为y[j] = alpha * x[k] + y[j]。算子需完整兼容标准BLAS参数语义、正负步长、空参数、非法参数校验等特性，支持异步Stream执行，精度符合昇腾开源算子精度标准，性能达到指定标杆阈值，接口统一纳入公共头文件，支持全产品线复用，最终完成开源合入。
2.2 功能需求拆解
1.	核心计算功能：严格遵循标准复数运算语义，单精度复数乘法遵循(a+bi)(c+di) = (ac-bd) + (ad+bc)i，复数加法实现实部、虚部分别独立相加，完成向量线性组合计算。
2.	参数语义兼容：完全对齐cuBLAS cublasCaxpy与Netlib caxpy参数规范，支持1-based Fortran索引规则，兼容正负向量步长（incx、incy），支持任意合法向量长度n。
3.	参数合法性校验：实现全量参数异常校验逻辑，句柄为空、向量指针为空、n为负数、步长为0等非法场景返回对应标准状态码；n=0为空操作场景，直接返回成功且不修改输出数据。
4.	硬件与架构适配：基于Ascend C Kernel直调方式开发，依托ops-blas开源工程框架，通过handle绑定Stream实现NPU异步执行，适配Ascend 950PR芯片算力特性。
5.	接口规范约束：算子接口声明统一写入include/cann_ops_blas.h，禁止定义950PR私有接口，保证多产品线通用。
6.	精度性能达标：实部、虚部分别按FLOAT32精度标准校验，满足生态开源精度要求；大规模向量计算场景性能不低于官方标杆耗时。
2.3 非功能需求
1.	精度需求：采用Netlib BLAS caxpy作为精度Golden基准，COMPLEX64数据实部、虚部分别校验，满足rtol=2^-10、atol=2^-16、匹配率≥99%、最大绝对误差≤1e-2的精度标准。
2.	性能需求：经过warmup预热后，有效采样50次取平均耗时，n=1048576、2097152、4194304标准场景耗时分别不超过14.53us、28.36us、89.76us。
3.	兼容性需求：仅适配Ascend 950PR芯片、CANN9.1.0版本，接口完全兼容标准BLAS语义，无硬件私有特性依赖。
4.	稳定性需求：支持极端值（0值、极大值、Inf、NaN）、边界值、正负步长、非对齐访存等全场景稳定运行，无计算异常、内存溢出问题。
3. 详细设计
3.1 算子基础信息
属性	内容
算子名称	aclblasCaxpy
计算公式	y[j] = alpha * x[k] + y[j]（1-based索引，k=1+(i-1)*incx，j=1+(i-1)*incy，i∈[1,n]）
支持数据类型	COMPLEX64（实部、虚部均为FLOAT32）
支持硬件	Ascend 950PR
算子类型	向量基础线性运算、原地更新算子
执行方式	NPU异步执行，依赖Stream绑定，需主动同步结果
3.2 接口设计
3.2.1 接口声明
接口统一声明在include/cann_ops_blas.h，与标准BLAS、cuBLAS参数顺序完全对齐，接口定义如下：
aclblasStatus_t aclblasCaxpy(
    aclblasHandle_t handle,
    int n,
    const aclblasComplex* alpha,
    const aclblasComplex* x,
    int incx,
    aclblasComplex* y,
    int incy);
3.2.2 参数详细说明
参数名	输入输出	数据类型	参数说明与约束
handle	输入	aclblasHandle_t	库上下文句柄，携带执行Stream；为空返回ACLBLAS_STATUS_HANDLE_IS_NULLPTR
n	输入	int	向量计算元素个数，n≥0；n<0返回非法参数；n=0为空操作，直接返回成功
alpha	输入	aclblasComplex*	复数缩放系数，n>0时不能为空指针，实虚部支持全量FLOAT32取值
x	输入	aclblasComplex*	输入复数向量，Device端内存，只读；n>0时不能为空指针
incx	输入	int	向量x元素步长，非0；incx=0返回非法参数，支持正负步长
y	输出	aclblasComplex*	输入输出复数向量，Device端内存，原地更新；n>0时不能为空指针
incy	输入	int	向量y元素步长，非0；incy=0返回非法参数，支持正负步长
3.2.3 返回值
返回aclblasStatus_t状态码，包含三类核心状态：ACLBLAS_STATUS_SUCCESS（执行成功）、ACLBLAS_STATUS_INVALID_VALUE（参数非法）、ACLBLAS_STATUS_HANDLE_IS_NULLPTR（句柄为空）。
3.3 整体架构设计
算子采用Host侧接口逻辑 + Device侧Kernel直调的分层架构，完全适配ops-blas工程规范，代码存放于blas/axpy/arch35/目录。整体执行流程分为参数校验、Tiling分块、Stream绑定、Kernel执行四大阶段，实现异步高效计算。
3.3.1 Host侧设计
1.	参数合法性校验：优先校验句柄有效性，依次校验n、incx、incy、alpha、x、y参数合法性，非法参数直接返回对应状态码，无Kernel调用开销。
2.	空操作处理：当n=0时，直接返回成功，不执行任何设备计算逻辑。
3.	Tiling分块策略：基于Ascend 950PR AI Core算力与UB内存大小，自动计算核数、单核处理块数、尾块数据量。采用均匀分块+余数补全策略，将余数数据分配至前序核，最大化硬件利用率；根据incx、incy是否为1区分连续/非连续访存场景，配置差异化Tiling参数。
4.	Stream绑定与下发：从handle中获取绑定的Stream，将Tiling参数、输入输出地址、缩放系数打包下发至Device侧Kernel，实现异步执行。
3.3.2 Device侧Kernel设计
Kernel采用三段式流水线设计（CopyIn - Compute - CopyOut），基于Ascend C流水线并行能力，最大化提升访存与计算效率，整体无数据依赖阻塞。
1.	Init初始化阶段：解析Host下发的TilingData参数，获取当前核索引、总计算元素数、分块偏移、步长参数，计算当前核需要处理的向量数据首地址与数据范围，区分正负步长的地址偏移逻辑。
2.	CopyIn数据搬运阶段：根据incx、incy正负步长规则，完成GM全局内存至UB统一缓冲区的数据搬运，适配非连续访存场景，处理1-based索引的地址映射，保证数据读取准确性。
3.	Compute计算阶段：解析复数缩放系数alpha的实部、虚部，对x、y向量元素逐一对齐，执行复数乘法+加法运算，严格遵循标准复数运算公式，分离实虚部分别计算，保证计算精度。
4.	CopyOut写回阶段：将UB中计算完成的y向量结果，按指定步长写回GM全局内存，实现原地数据更新。
3.4 核心计算逻辑设计
设缩放系数alpha = a + bi，向量x单个元素x = c + di，原向量y单个元素y = e + fi，核心计算推导如下：
复数乘法：alpha * x = (ac - bd) + (ad + bc)i
复数加法：y_out = (ac - bd + e) + (ad + bc + f)i
算子遍历n个元素，根据步长参数索引对应x、y向量元素，逐元素完成上述计算，最终覆盖写入y向量内存。
3.5 算子约束与边界处理
1.	空维度处理：n=0为合法空操作，不修改任何设备数据，直接返回成功。
2.	步长约束处理：拦截incx=0、incy=0非法场景；支持正负步长，通过索引偏移适配反向向量遍历逻辑。
3.	访存适配：支持向量非对齐偏移、非连续访存场景，完全通过步长参数实现，无需额外Padding。
4.	极端值处理：兼容0值、极大值、Inf、NaN等特殊输入，计算逻辑稳定，无崩溃、异常输出问题。
