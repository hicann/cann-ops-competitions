# 一、需求描述

## 1.1 需求来源

本设计对应 [Ascend C Basic API 指针化扩展（VECTOR 分册）社区任务](https://www.hiascend.com/activities/task-center/details/7dda608eaee54623b53a0eb72f366c53)，依据[任务书](https://www.hiascend.com/p/resource/202609/7820d2b199124c0aa127372534bd4a20.zip)与 [VECTOR 接口清单](https://docs.qq.com/sheet/DYVNBU3BUUVdVRFRu?tab=000001)，扩展 asc-devkit Basic API 的数据操作数表达方式。

接口同时接受原有 LocalTensor 与等价硬件地址空间的裸指针，并允许同一调用中的各操作数独立选择两种形式。接口名称、计算功能、非 Tensor 参数语义、返回值及原有 Tensor 调用行为保持一致。文档结构参考任务指定的 [API 设计评审案例](https://gitcode.com/cann/asc-devkit/issues/1222)。

## 1.2 需求分析

### 1.2.1 接口范围

设计范围为[官方 VECTOR 接口清单](https://docs.qq.com/sheet/DYVNBU3BUUVdVRFRu?tab=000001)（2026-09-16 版本）所列的 **85 个接口名、256 条重载签名、20 个头文件**，包括矢量算术、标量运算、转换、归约、比较选择、Gather/Scatter、填充广播、排序、转置及清单内辅助接口。任务书的汇总数为 79 个接口名、245 条签名；本设计采用在线清单的逐项范围，不以较小汇总数裁剪接口。清单外的搬运、矩阵及 Proposal 专用接口不因同目录或同头文件而扩展。

适配硬件为 Ascend 950。软件环境满足任务书 CANN 9.0.0～9.1.0，并满足对应官方样例对版本的要求；样例要求 CANN 9.1.0 时采用该版本。各接口保留原架构条件、数据类型限制及可用编译模式，清单中的条件接口不等价于所有接口均支持 950 设备执行。

### 1.2.2 功能与约束

| 需求 | 设计约束 |
| --- | --- |
| Pointer / Tensor 双调用 | 清单内 Local 数据操作数支持原 Tensor 或等价地址空间指针；各操作数独立推导类型 |
| 原调用兼容 | 保留原名称、参数顺序、默认参数、显式模板参数顺序及原 Tensor 重载 |
| 数值一致 | 复用原底层算法，保持计算精度、舍入、饱和、融合、掩码及归约顺序 |
| 内存一致 | 不复制操作数数据，不新增随输入规模增长的 Device 缓冲区，不隐式扩容或补齐 |
| 地址有效 | 调用方保证地址、生命周期、对齐、容量和别名关系满足对应原接口要求 |
| 同步一致 | 保留原流水属性和同步责任，不因指针适配添加隐式全流水屏障 |
| 范围完整 | 以“接口名＋清单重载序号＋条件编译分支”区分覆盖项，不按同名函数合并覆盖 |

指针只表达元素类型和地址，不提供 Tensor 的容量、位置及调试元数据。扩展不能通过构造虚假 Tensor 恢复这些信息，也不能把其他地址空间强制转换为 UB 来绕过类型约束。

# 二、方案设计

## 2.1 接口内部实现

### 2.1.1 分层与调用路径

对外声明位于 `include/basic_api/`，类型适配与接口实现位于 `impl/basic_api/`，按既有头文件组织。公共内部工具放在 `AscendC::Internal` 命名空间，使用仓库已有的类型工具，不增加外部运行库依赖。

```text
原 Tensor 调用 ── 原 Tensor 重载 ── 原检查与元数据处理 ──┐
                                                        ├─ 原 *Impl ─ 原硬件实现
Pointer / 混用 ── 受约束的新重载 ── 类型检查与地址提取 ───┘
```

全 Tensor 调用只由原重载承接。新重载要求至少一个可扩展的数据操作数为指针或数组，避免与原重载竞争；每个数据操作数使用独立模板参数，避免以一个共同模板类型限制 Pointer / Tensor 混用。

### 2.1.2 类型识别与底层地址提取

内部操作数 traits 提供有效性、原始元素类型、地址空间和是否为 Tensor 等编译期信息。仅接受明确支持的 Tensor、硬件指针及数组类别，不以任意对象存在 `GetPhyAddr()` 成员作为适配依据。

| 操作数形式 | 底层地址提取 | 类型约束 |
| --- | --- | --- |
| `LocalTensor<T>` | 取得 `GetPhyAddr()`，沿用对应原包装层的地址转换 | 元素类型使用 `PrimT<T>`；保留 Tensor 位置检查 |
| 硬件空间 `T*` | 原样返回指针 | 保留 pointee 类型、地址空间与 const 属性 |
| 硬件空间 `T[N]` | 在明确的数组适配分支中退化为首元素指针 | 不把数组作为 Tensor；不因形参引用而新增元素 const |
| 其他类型 | 不进入新重载或触发定向编译诊断 | 不接受整数地址、GlobalTensor 或错误地址空间替代 Local 操作数 |

`GetUnderlyingPtr` 只进行地址提取，不分配、不搬运、不更改指针偏移。输出操作数要求可写；输入 const 指针仅在原底层接口和编译器支持对应只读语义时接受，不通过移除 const 获得兼容。

同类型算术接口验证各操作数的原始元素类型一致。转换、索引、掩码、工作区等接口按参数角色验证，不能统一要求全部操作数类型相同。例如 Cast 的源和目的类型允许不同，Sort 的索引仍为原接口规定的类型，Transpose 的临时区仍保持原字节类型。

### 2.1.3 底层实现复用

对于底层 `*Impl` 已接受指针的接口，新包装层完成类型校验后直接调用原实现，原有 mask、repeat、stride、count 和其他控制参数逐项透传。

对于底层实现仍接受 Tensor 的接口，将其地址访问与元数据依赖分离：数值计算主体抽取为内部指针入口；原 Tensor 入口保留元数据检查并调用同一主体。指针入口只能使用可由原参数明确确定的信息；依赖 Tensor 容量或位置的信息不得猜测。原接口通过 count、repeat 或参数结构能够确定的工作区大小继续使用原计算方式。

新重载保持原有 `__aicore__`、流水属性、架构宏和保留 UB 限制。`isSetMask=false` 时不得新增掩码设置；调用方原有的掩码配置责任保持不变。扩展层不改变核数、数据切分、访存顺序和尾部处理规则。

### 2.1.4 检查与可观测性

原 Tensor 重载保留 `ASCENDC_DEBUG`、`ASCENDC_CPU_DEBUG`、MSTX 等分支中的原检查和信息上报。

新混用重载分别检查仍为 Tensor 的操作数，并执行不依赖 Tensor 容量的 count、mask、repeat 等公共检查。指针的地址空间和可写性由类型约束检查；容量与实际分配范围由调用方保证。Tensor 专用的多操作数边界检查不能直接套在混用参数上。

CPU Debug 路径保留其原编译条件及掩码状态语义。MSTX 仅上报真实可取得的 Tensor 信息，不为裸指针伪造 Tensor 描述。接口可用性与调试信息完整度分别定义，不能因缺少 Tensor 元数据而取消旧 Tensor 路径的诊断。

### 2.1.5 接口族与特殊结构

| 接口族 | 适配规则 |
| --- | --- |
| 一元、二元与标量运算 | 逐个适配数据操作数；标量保持原类型；原融合、原位更新和广播语义不变 |
| Cast、量化及反量化 | 分别推导源、目的和比例因子类型；保留转换模式与各参数的原角色 |
| 比较、选择和掩码 | 区分数据、比较结果 Tensor 与控制 mask 数组；控制参数不因数组形式被误判为数据操作数 |
| 归约 | 保持输出布局、索引输出、临时区大小与归约顺序；结果计数等标量引用保持原形式 |
| Gather / Scatter | 数据与索引独立适配，保持索引单位、合法范围、重复索引和越界约束 |
| Copy、Duplicate、交织与广播 | 只扩展清单中的签名；保留数据布局、重复参数及源数据类型 |
| Sort / MrgSort | 数据、索引和临时区独立适配；原 `MrgSortSrcList<T>` 保持布局，指针源列表使用单独的内部适配结构与相应受约束重载，不修改原结构 ABI；列表元素顺序及有效位含义保持一致 |
| Transpose / TransDataTo5HD | Tensor 数组与指针数组分别适配；固定列表长度保持不变；既有 `uint64_t` 地址列表重载保留，不由泛型重载抢占；地址列表 Tensor 与被转置数据的类型参数分开处理 |
| Fill | 沿用 L0A/L0B/L1 初始化语义及原架构能力；按对应存储空间适配，禁止归入通用 UB 矢量包装；没有原实现的架构不通过本任务新增硬件能力 |
| GetAbsAddr | 保留 CPU Debug 条件和弃用属性；Tensor 地址查询按原管道/位置映射，指针形式只接受该调试后端可解释的地址；不作为 950 NPU 计算用例 |
| DeNormMin 等常量填充接口 | 保持由原模板确定的数值类型与特殊值语义，适配目的操作数；不把 NaN 等特殊值按普通容差判断 |

## 2.2 接口设计

### 2.2.1 调用形式

以下以 Add 表示调用约定，其中 `dstTensor`、`src0Tensor`、`src1Tensor` 为同元素类型的 LocalTensor，`dstPtr`、`src0Ptr`、`src1Ptr` 为对应 UB 指针，`count` 满足原接口约束。

```cpp
AscendC::Add(dstTensor, src0Tensor, src1Tensor, count);
AscendC::Add<float>(dstTensor, src0Tensor, src1Tensor, count);
AscendC::Add(dstPtr, src0Ptr, src1Ptr, count);
AscendC::Add<float>(dstPtr, src0Tensor, src1Ptr, count);
AscendC::Add(dstTensor, src0Ptr, src1Tensor, count);

AscendC::Add<float, true>(dstPtr, src0Tensor, src1Ptr,
    mask, repeatTime, repeatParams);
```

显式模板参数保留原有元素类型及布尔、枚举等参数位置；新增操作数类型参数放在其后并由函数实参推导。未显式指定元素类型时，由角色对应的操作数推导；显式指定时校验其与实际元素类型一致，不据此执行隐式数据转换。

不能从参数推导的原模板参数继续要求显式提供。例如表示被转置数据类型的模板参数不能从 `LocalTensor<uint64_t>` 地址列表推断。已有具有两种元素类型或非类型模板参数的接口分别维持原参数顺序，不套用 Add 的单类型签名。

### 2.2.2 重载边界

Add 保持 count、连续 mask、位 mask 三种形式，各形式的非数据参数原样保留。其他接口按清单逐签名扩展，不用可变参数转发覆盖不同语义的重载。

| 情况 | 规定行为 |
| --- | --- |
| 全部为原 Tensor | 选择原重载，原检查与计算路径不变 |
| 至少一个合法 Pointer，其余为合法 Tensor / Pointer | 选择新增受约束重载 |
| 直接传入 UB 数组 | 作为对应数据指针参与类型推导 |
| 同类型算术传入不同元素类型 | 编译拒绝，不隐式转换 |
| 向 UB 操作数位置传入 GM 指针 | 编译拒绝，不强制转换地址空间 |
| 输出指向 const 元素 | 编译拒绝 |
| 原接口不支持的 dtype / 架构 / 编译选项 | 保持原限制，不由新重载绕过 |
| 原接口允许的原位重叠 | 沿用原行为；不新增对任意部分重叠的支持 |

## 2.3 测试用例设计

### 2.3.1 覆盖模型

覆盖键为“清单重载＋架构/编译条件＋dtype＋参数模式＋操作数形式”。具有 n 个可独立扩展操作数的普通接口覆盖全部 `2^n` 种 Tensor / Pointer 组合，包括全 Tensor、全 Pointer 和混用。固定长度列表另覆盖全 Tensor、全 Pointer、合法列表元素组合与长度约束。不同参数角色的合法 dtype 组合独立列举。

测试调用公开 API，并使用待测仓库头文件及实现。基线 Tensor、扩展后 Tensor、Pointer、混用使用相同输入、参数、布局和同步。每条清单签名分别对应编译用例和适用的运行用例；仅在 CPU Debug 或其他架构可用的签名由对应条件编译测试覆盖，不计入 950 运行通过数。

### 2.3.2 用例矩阵

| 测试维度 | 用例设计 | 判定 |
| --- | --- | --- |
| 官方回归 | 原样保留任务附件及仓库相关官方样例，再增加调用形式变体 | 原 Tensor 样例和变体均通过原判定脚本 |
| 模板兼容 | 隐式类型、显式元素类型、全部原模板参数、默认布尔/枚举参数 | 合法用法无歧义编译；原调用不变 |
| 指针推导 | 指针变量、直接 UB 数组、合法偏移指针、各位置混用 | 正确选中重载，输出与基线一致 |
| 数据规模 | 1、32、1024、2048，并保留官方脚本原规模；增加合法向量块边界及尾部 | 有效区正确，保护区不被覆盖 |
| 数据取值 | 合法定义域内覆盖 [-100,100]、零值、正负及相消输入 | 同时满足官方脚本和适用精度标准 |
| 数学定义域 | Ln 使用正输入，除法避开常规零分母；异常值另设用例 | 不用非法输入替代正常精度覆盖 |
| mask / repeat / stride | 连续与位 mask、部分有效位、合法重复边界、支持的非连续步长和广播 | 仅指定元素被处理，输出布局一致 |
| isSetMask | true 与 false；false 由调用方设置合法掩码 | 原掩码责任和状态语义一致 |
| 特殊接口 | 转换模式、索引类型、排序顺序、源列表、有效位、地址列表与临时区 | 按接口业务语义比对 |
| 特殊值 | 支持的 NaN、Inf、负零、极值和非正规数，覆盖常量填充接口 | 特殊值类别、符号或位模式符合原语义 |
| 编译拒绝 | 非法元素类型、错误地址空间、只读输出、错误列表长度、模板类型冲突 | 定向失败，无误接收或歧义 |
| Debug / MSTX | 原 Tensor 检查回归、混用真实元数据处理、无元数据指针路径 | 条件编译成功，原诊断能力保留 |

对于排序、转置等具有固定布局或最小块限制的接口，仅使用符合其约束的规模；shape=1 不适用时标明对应约束并覆盖最小合法布局。短输入测试区分有效长度与对齐分配容量，保留保护区，避免搬运要求导致越界。零长度是否可调用沿用各接口原定义，不统一增加空输入支持。

### 2.3.3 官方样例与测试组织

以任务附件及 `examples/01_simd_cpp_api/03_basic_api/` 中对应样例为运行入口，复用原 Host、数据生成与精度脚本。样例参数化补充任务书规模和调用形式，不更改原脚本阈值。低层编译、类型与参数边界用例置于 `tests/api/basic_api/` 对应目录。

每个运行 case 记录接口签名、dtype、有效长度、实际容量、操作数形式、mask/repeat/stride 或其他属性、基线与待测结果及判定指标。报告区分编译通过、NPU 运行通过、条件不适用和未覆盖项；不能用一个样例代表整个同名接口的全部重载。

# 三、可维可测

## 3.1 精度标准/性能标准

浮点计算同时满足对应官方 `verify_result.py` 与[生态算子开源精度标准](https://gitcode.com/cann/opbase/blob/master/docs/zh/ops_precision_standard/experimental_standard.md)的适用要求。标准采用逐元素混合容差：

`abs(actual - golden) <= atol + rtol * abs(golden)`

并同时满足对应 dtype 的通过比例和最大绝对误差上限。官方脚本的容差、失败比例及标准的最大误差约束分别保留，不以单一 rtol 大小替代完整判定；任一适用判定失败即不通过。

原 Tensor 与扩展后的各调用形式还需进行同输入差分。仅改变参数表达形式时，有效输出应与原路径一致；原接口允许的非确定性行为按其原业务标准判断。整数、位运算、索引、搬运、排序布局及地址查询采用相应精确或结构化比对，不套用浮点容差。NaN 等特殊值单独按原接口语义比较。

本任务无额外性能指标。类型识别和重载选择在编译期完成，地址提取不引入按元素循环和额外 Device 数据拷贝；扩展层 Device 数据缓冲区增量为零，原实现已有的内部资源保持不变。性能对照使用相同输入、编译选项、同步与计时范围，不改变原算法以换取表面加速。

## 3.2 兼容性分析

| 兼容维度 | 保持方式 |
| --- | --- |
| 源码调用 | 原 Tensor 重载、模板顺序、默认值、返回值和参数顺序保留 |
| 重载选择 | 新重载要求至少一个指针类数据操作数，全部 Tensor 不进入新增候选 |
| 数据类型 | 保留 PrimT 映射及每个操作数角色的原类型关系 |
| 数值行为 | 共享原计算主体，不增加升精度、舍入、饱和或数学近似策略 |
| 内存与结构布局 | 原 Tensor、参数结构和源列表结构不变；地址提取无额外数据分配 |
| 地址空间 | 逐接口保持原存储空间，不把 Fill 等非 UB 接口纳入通用 UB 转换 |
| Debug 与可观测性 | 原 Tensor 检查完整保留，指针路径只使用真实信息 |
| 架构与工具链 | 保留原条件编译；950 指针扩展不扩大其他架构的硬件承诺 |
| 编译选项 | 原保留 UB、流水和模式限制在新增声明与实现中一致生效 |

公共适配工具集中维护，接口族仅提供角色约束与原实现转发，避免各接口自行识别指针产生行为差异。测试结果关联源码版本、CANN/编译器版本、设备及实际头文件来源，确保运行结果能够对应到具体实现。
