# 需求背景（required）

## 需求来源

9 月 CANN 社区 aclblasStbsv（A2/A3）算子开发任务。拟在 cann/ops-blas 工程中新增 arch22 实现，通过 Ascend C kernel 直调提供单精度实数三角带状方程求解能力。设计文档拟提交到 cann/cann-ops-competitions 的对应任务目录。

## 背景介绍

三角带状求解用于具有局部耦合关系的线性系统。矩阵按带状列主序存储，无需展开为稠密矩阵。拟对齐 cuBLAS cublasStbsv 的接口语义，以 Netlib CBLAS stbsv 生成精度参考，使用任务附件 GPU baseline 做性能对比。已有其他架构实现可用于理解工程集成方式；arch22 计算将使用适用于 A2/A3 的 Ascend C 指令与内存模型。

# 需求分析（required）

## 需求描述

求解 `op(A) * x = b`，调用前 x 保存 b，调用后在同一缓冲区保存解。输入、输出均为 float32；不包含 alpha、beta、复数共轭运算或广播。OP_C 在实数场景下与 OP_T 等价。

```cpp
aclblasStatus_t aclblasStbsv(
    aclblasHandle_t handle, aclblasFillMode_t uplo,
    aclblasOperation_t trans, aclblasDiagType_t diag,
    int n, int k, const float* A, int lda, float* x, int incx);
```

## 需求拆解

| 项目 | 拟支持的行为 |
| --- | --- |
| 三角方向 | UPPER、LOWER |
| 转置 | N、T、C；实数 C 等价于 T |
| 对角 | NON_UNIT 使用矩阵对角，UNIT 将对角视为 1 且不读取其存储值 |
| 维度 | n≥0、k≥0、lda≥max(1,k+1)；带宽访问按矩阵边界裁剪 |
| 向量步长 | 正、负 incx；只写逻辑向量元素，保留物理间隙 |
| 空操作 | 合法 n=0 直接成功；合法 k=0 且 UNIT 可直接成功 |
| 异常 | 空 handle 返回 HANDLE_IS_NULLPTR；非法枚举、尺寸、lda、零/INT_MIN 步长，以及 n>0 时空 A/x 返回 INVALID_VALUE |
| 执行 | 使用 handle 绑定 stream 异步提交，接口正常路径不内部同步 |
| 存储 | A 只读；x 原地更新；不支持 A 与 x 重叠 |
| 泛化 | 分派仅依赖接口参数与硬件容量，不依赖 CSV 序号、用例名、随机种子或预置结果 |

# 详细设计（required）

## 算子分析

### 数学公式与地址映射

令 B=op(A)。B 为下三角时按 i=0 到 n−1 前代，为上三角时按 i=n−1 到 0 回代：

`x[i] = (b[i] − Σ B[i,j] * x[j]) / B[i,i]`。

求和仅覆盖已求解且位于带内的 j。UNIT 时省略除法与对角读取。零基下，UPPER 的 A(i,j) 位于 `A[j*lda+k+i-j]`；LOWER 位于 `A[j*lda+i-j]`。转置时交换逻辑行列后映射。负步长的逻辑起点为 `(n−1)*abs(incx)`，第 i 个元素地址为 `start+i*incx`，索引及字节数计算拟使用 64 位整数。

### 数据类型与形状

float32；A 为 lda×n 的带状存储，x 物理长度为 `1+(n−1)*abs(incx)`。n、k、lda、incx 为运行时参数，不为任务 CSV 固定尺寸生成专用答案。通用路径拟覆盖超出官方尺寸扫描范围的合法参数，受设备可用内存限制。

## 算子实现

### Host 侧设计

1. 按公共接口契约依次检查 handle、枚举、维度、lda、incx 和必要指针，避免 k+1、abs(INT_MIN) 等整型溢出。
2. 对合法空操作直接返回成功。
3. 从硬件能力和 UB 容量确定向量缓存、矩阵面板大小及尾部长度；生成包含地址、维度、方向、对角类型与缓存策略的 tiling 参数。
4. 使用 handle 绑定的 stream 直调自定义 kernel。拟优先采用单 AIV 顺序推进解向量，避免跨核求解依赖；只有互不依赖的退化对角计算才考虑分核。
5. 支持基于带宽、转置与存储连续性的通用分派。阈值拟来自资源容量及实际剖析，不为五个硬性能点单独写分支。

### Kernel 侧设计

拟结合带状列主序与前代/回代依赖采用以下通用方案：

- **非转置**：求出当前 x[j] 后更新依赖该元素的后续带内向量区间。连续矩阵列搬入 UB 后进行乘法及减法，复用尚未求解的右端项。上三角反向推进，下三角正向推进。
- **转置**：原矩阵的一列对应 B 的一行；连续加载有效列段，与已求解 x 做乘积和归约，随后求当前元素。OP_C 共用转置路径。
- **小规模/窄带**：拟使用 UB 标量顺序计算或短向量计算，减少搬运与同步启动成本。
- **大规模/宽带**：拟采用容量约束的分块面板和向量操作；面板尾部按有效长度处理。无法整向量驻留 UB 时采用分段缓存或直接存储访问回退，不能因 n 超过官方最大用例而越界。
- **k=0**：NON_UNIT 为独立逐元素除法；UNIT 保持输入不变。

矩阵只加载合法带内数据；UNIT 对角不参与数据读取或运算。数据搬运、向量计算和标量读取之间显式保证依赖同步。写回遵守 incx，避免覆盖间隙和未使用区域。计算顺序拟优先对齐 Netlib 的列更新/行点积顺序；向量归约产生的舍入差异需通过任务精度标准验证。

# 可维可测分析

## 精度标准与方法

拟使用 ops-blas C++ GTest 全量加载附件 1200 条 CSV，包括 200 条性能用例的精度检查；逐条记录 case 名、完整参数、期望/实际状态及数值指标，检查名称集合与数量完全一致。另补充空 handle、流语义、非单位步长间隙保护、UNIT 对角 NaN/Inf 不读取、尺寸与参数泛化用例，补充用例与官方计数分开。

黄金结果拟通过外部 Netlib CBLAS stbsv 生成，参考实现与 NPU 使用完全相同的 A 和 b。NON_UNIT 按任务说明对随机矩阵被引用对角按符号加减 5，双方共享处理后的输入。原始 CSV 的填充标签与随机种子将原样解析；随机类输入另覆盖均匀 [-5,5] 与正态 μ∈[-5,5]、σ∈[0.1,2] 的 50%/50% 分布。特殊值用例单独判断 NaN/Inf 位置及符号，不把非有限误差掩盖为零。

| 精度指标 | 要求 |
| --- | --- |
| atol、rtol | 均为 2^-13 |
| 逐元素匹配 | abs(actual−golden) ≤ atol + rtol*abs(golden) |
| matched_ratio | ≥0.99 |
| 最大误差 | 满足任务规定的 1e-2 或 32 ULP 上限；同时记录绝对误差与 ULP，不静默放宽阈值 |
| 负向/空操作 | 核对状态和不写入行为；无数值比对时指标记 N/A |

遇到标杆异常或溢出时将保留原始结果和原因，检查矩阵条件与特殊值语义，不能删去失败 case 后报告“全量通过”。

## 性能标准与方法

拟对全部 200 个 TC_PF 用例使用同一正式构建进行 msprof 测量。每个用例预热 5 次、有效采样 64 次，报告全部有效采样算术平均值，满足任务不同段落的 10 次及 >10 次要求。每次调用前在同一 stream 恢复原始 b；恢复数据的 DMA 不计入求解 kernel 时长，最后实际输出仍需通过精度检查。

一次接口调用若包含多个 kernel，计时将求和全部相关 kernel 的 Task Duration。保留逐次原始时长、均值、原始 profiler 日志和解析对应关系，禁止用 Host 计时替代、选择最快样本或混合不同版本的最优结果。

GPU 基线取原始 gpu_baseline.csv，按完整参数与对应条目关联，单位由 ms 转换为 us。定义 `ratio=GPU_us/NPU_us`，200 点均要求 ratio≥0.8，即 `NPU_us≤GPU_us/0.8`。另外同时核对五个任务书硬上限：

| n | k | uplo | trans | diag | 上限 us |
| ---: | ---: | --- | --- | --- | ---: |
| 256 | 8 | UPPER | N | NON_UNIT | 198.0 |
| 512 | 32 | LOWER | N | NON_UNIT | 379.8 |
| 1024 | 16 | UPPER | T | UNIT | 659.5 |
| 2048 | 64 | LOWER | T | NON_UNIT | 1725 |
| 4096 | 128 | UPPER | N | UNIT | 2365 |

平均加速比仅作汇总，不替代逐点通过条件。任务未提供 TBE 性能标杆，报告相应模板项拟写 N/A 并明确使用附件 cuBLAS GPU 基线。
