# aclblasCdotc 算子设计文档

# 需求背景

## 需求来源

本算子来自 2026 年 8 月社区任务“aclblasCdotc 算子开发（950）”。任务要求基于 `ops-blas` 工程，使用 Ascend C 为 Ascend 950PR 实现句柄式复数共轭点积接口，并完成接口适配、功能验证和性能优化。

## 背景介绍

### aclblasCdotc 算子功能

`aclblasCdotc` 计算两个单精度复数向量的共轭点积：

`result = sum(conj(x[i]) * y[i])`

设 `x[i] = xr + xi * i`，`y[i] = yr + yi * i`，则每个元素对最终结果的贡献为：

- 实部：`xr * yr + xi * yi`
- 虚部：`xr * yi - xi * yr`

输入和输出的数据类型均为 `COMPLEX64`，实部和虚部各使用一个 `FLOAT32`。`incx` 和 `incy` 表示相邻逻辑元素在物理内存中的步长，支持任意非零正、负整数。

### 设计目标

本设计在不改变 `ops-blas` 公共接口的前提下，为 `arch35` 增加 Ascend 950PR 实现。连续输入采用多核向量化归约以满足大规模性能要求，非单位步长输入按照 BLAS 逻辑顺序访问，覆盖正步长、负步长和混合步长场景。

# 需求分析

## 需求描述

使用 Ascend C 实现 `aclblasCdotc`，支持 `COMPLEX64` 输入和输出、运行时长度 `n`、任意非零 `incx` 和 `incy`，并通过句柄绑定的流异步执行。功能语义与 `cublasCdotc`、Netlib `cdotc` 保持一致，精度和性能按任务书规定的方法验收。

## 需求拆解

功能与语义。算子对 x 取共轭后与 y 逐元素相乘并归约，输出一个复数标量。负步长按照 Netlib BLAS 的逻辑起点和访问方向处理。

参数与边界。`n` 支持零和正整数；`n == 0` 时输出 `(0, 0)`。句柄、输入输出指针、长度和步长均需在 Host 侧完成合法性检查。

执行方式。接口使用句柄中绑定的流异步下发。连续输入走多核向量路径，非单位步长输入走通用步长路径。

精度要求。输入输出保持 `COMPLEX64`，实部和虚部分别按照任务书的 `FLOAT32` 标准判定。归约结果与累加顺序有关，验证时必须固定参考实现及版本。

性能要求。重点优化 `incx == 1` 且 `incy == 1` 的百万级连续输入，减少全局内存访问、归约依赖和核间汇总开销。

# 详细设计

## 算子分析

### 数学公式

算子定义为：

`result = sum(conj(x[k]) * y[j])`

其中逻辑元素编号为 `i = 0 ... n - 1`。正步长时，物理下标为 `i * inc`；负步长时，物理下标为 `(n - 1 - i) * abs(inc)`。

展开复数乘法后：

`result.real = sum(x.real * y.real + x.imag * y.imag)`

`result.imag = sum(x.real * y.imag - x.imag * y.real)`

### 支持数据类型

| 对象 | 数据类型 | 内存位置 | 说明 |
| --- | --- | --- | --- |
| x | `COMPLEX64` | Device | 参与计算时取共轭 |
| y | `COMPLEX64` | Device | 第二个输入向量 |
| result | `COMPLEX64` | Device | 单个复数标量 |
| n、incx、incy | `int` | Host | 运行时参数 |

### 支持形状

x 和 y 均为逻辑一维向量，逻辑长度为 `n`。当 `n > 0` 时，输入需要提供的物理元素数为：

`1 + (n - 1) * abs(inc)`

result 的形状为标量 `[1]`。本算子不涉及广播和额外的 leading dimension。

### 接口定义

```cpp
aclblasStatus_t aclblasCdotc(
    aclblasHandle_t handle,
    int n,
    const aclblasComplex* x,
    int incx,
    const aclblasComplex* y,
    int incy,
    aclblasComplex* result);
```

| 参数 | 含义 | 约束 |
| --- | --- | --- |
| handle | 携带执行流和工作区的句柄 | 不能为空 |
| n | 参与点积的逻辑元素数 | `n >= 0` |
| x、y | 输入复数向量 | `n > 0` 时不能为空 |
| incx、incy | 输入向量的逻辑步长 | 必须非零，可正可负 |
| result | 输出复数标量 | 不能为空 |

## 算子实现

### 整体方案

实现由 Host 侧参数处理和 Kernel 侧归约计算两部分组成。Host 侧完成参数检查、快速返回、分核分块和工作区检查；Kernel 侧根据步长选择连续输入路径或通用步长路径。

连续输入路径把数据分配给多个 Vector Core。每个核心完成局部复数点积并把局部结果写入工作区，全部核心同步后，由第 0 核按核心编号汇总并写出最终结果。

非单位步长路径使用一个核心按照逻辑元素顺序访问输入，分别处理 x、y 的正负步长并直接写出结果。

### Host 侧设计

#### 参数检查与快速返回

参数按照句柄、长度、输出指针、步长和输入指针的顺序检查。`n < 0`、步长为零或者必要指针为空时返回对应错误。

`n == 0` 是合法输入。Host 侧通过句柄绑定的流异步将 result 清零，不启动计算 Kernel。

#### 分核策略

参与计算的核心数为 `min(n, 可用 Vector Core 数)`，避免启动空核。

连续路径在数据量足够时，以 64 个复数为一个对齐组。完整对齐组均匀分配到各核心，多余组依次分配给编号靠前的核心，不足 64 个复数的尾部由最后一个核心处理。小规模连续输入按元素数均匀分配。

非单位步长路径只启动一个核心，使逻辑访问顺序与 BLAS 定义一致。

#### 分块策略

单核分块候选为 13,824、14,848 和 15,488 个复数。Host 侧先以 15,488 估算处理轮数；如果较小分块不会增加处理轮数，则优先选用更适合完整向量循环的较小分块，否则使用 15,488。

分块只决定单次搬入和局部计算的数据量，不改变各核心负责的输入范围。

#### 工作区与下发

每个参与核心在工作区写出两个 `FLOAT32`，分别保存局部实部和虚部。工作区以 64 个 `FLOAT32` 对齐；56 个核心参与时，工作区大小为 512 字节。工作区不足时返回执行失败。

Host 侧使用句柄绑定的流下发 Kernel，接口返回成功仅表示任务已成功提交；Host 读取 result 前需要同步该流。

### Kernel 侧设计

#### 连续输入路径

每个核心循环处理自己的连续输入区间：

1. 将 x、y 的交错复数数据搬入片上缓冲区。
2. 在寄存器中拆分实部和虚部，按共轭点积公式完成乘加。
3. 使用八组独立累加链处理完整向量，缩短连续乘加的依赖等待。
4. 使用有效掩码处理不足完整向量宽度的尾部。
5. 将当前分块归约成一个复数，并累加到本核局部结果。

非对齐尾块使用带补齐的数据搬运，补齐值为零，避免越界访问且不改变结果。每个核心完成全部分块后，将局部结果写入工作区。所有核心同步完成后，第 0 核顺序汇总各核结果并写出 result。

#### 通用步长路径

通用步长路径按照 `logical = 0 ... n - 1` 顺序处理。正步长的物理下标为 `logical * inc`；负步长的物理下标为 `(n - 1 - logical) * abs(inc)`。x 和 y 分别计算下标，因此支持正负混合步长。

该路径在 `FLOAT32` 下逐项计算实部、虚部并顺序累加，避免先整理输入所需的额外设备内存。

### 精度设计

算子输入、内部乘加结果和输出均采用单精度。连续路径采用多核并行归约，通用步长路径采用单核顺序归约，因此两条路径的累加顺序不同。任务书明确本算子不要求确定性计算，本实现不承诺不同并行度或不同参考库之间最后若干位完全一致。

任务书指定使用 cblas 的 Netlib `cdotc` 生成参考结果。单精度点积对累加顺序敏感，因此自验和正式验收需要固定参考库名称、版本和实际加载来源。双精度累加后转为单精度的结果可用于补充分析数学误差，但只有在任务方明确认可时才能替代任务书指定的参考结果。

### 性能设计

性能优化集中在连续输入路径：

- 多核并行读取并计算局部结果，降低单核处理长度。
- 以交错复数形式连续搬运，减少不规则访存。
- 使用八组累加链覆盖连续乘加依赖。
- 根据单核数据量选择分块大小，避免不必要的处理轮次。
- 每个核心只写出一个复数局部结果，核间工作区数据量固定且很小。
- 第 0 核直接汇总局部结果，不启动第二个 Kernel。

### 内存设计

| 项目 | 占用 |
| --- | ---: |
| result | 8 字节 |
| 工作区 | 每核 8 字节，整体按 256 字节对齐；56 核时为 512 字节 |
| 连续路径片上输入缓冲 | x、y 合计最多 247,808 字节 |
| 额外临时设备内存 | 不申请，复用句柄工作区 |

## 支持硬件

| 芯片版本 | 支持情况 |
| --- | --- |
| Ascend 950PR | 支持 |
| Ascend 950DT | 支持 |
| Atlas A2/A3 系列 | 本次 `arch35` 实现不适用，沿用对应架构已有实现 |

## 算子约束限制

- `n`、`incx`、`incy` 使用 `int` 表示，`n >= 0`，`incx != 0`，`incy != 0`。
- `n > 0` 时，x、y、result 必须指向有效的 Device 内存。
- result 为独立输出，不支持与输入向量重叠。
- 输入只支持一维 BLAS 步长语义，不支持广播和额外 padding 描述。
- 接口异步执行，Host 读取结果前必须同步句柄绑定的流。
- 归约累加顺序不作跨实现、跨并行度的逐位一致性保证。

## 兼容性分析

本实现沿用 `include/cann_ops_blas.h` 中已有的 `aclblasCdotc` 公共接口，不新增 Ascend 950PR 私有接口。新增内容位于 `arch35` 实现路径，不改变其他架构已有实现的接口和行为。

Host 侧参数检查、句柄、流和工作区使用方式与 `ops-blas` 现有句柄式接口保持一致，便于后续维护和统一测试。
