# aclblasCtbmv 算子设计文档

作者：dyuan311。任务：aclblasCtbmv（A2/A3）。

## 需求背景（required）

### 需求来源

昇腾社区“8月社区任务-aclblasCtbmv算子开发（A2/A3）”。接口进入 `cann/ops-blas`，A2/A3 实现目录为 `blas/tbmv/arch22/`。

### 背景介绍

单精度复数三角带状矩阵向量乘法将一个 n 阶三角带状矩阵与向量相乘。矩阵采用列主序带状存储，结果原地写回向量。半带宽为 k，有效矩阵元素数为 O(n(k+1))。原地更新需要协调各核心读取输入向量与写回输出的顺序。

公共接口与 cuBLAS `cublasCtbmv` 参数序列对齐，语义参考 Netlib `ctbmv`。复数包含 float32 实部和虚部。

## 需求分析（required）

### 需求描述

$$
x_{out}=\operatorname{op}(A)x_{in},\qquad\operatorname{op}(A)\in\{A,A^T,A^H\}.
$$

```cpp
aclblasStatus_t aclblasCtbmv(
    aclblasHandle_t handle, aclblasFillMode_t uplo,
    aclblasOperation_t trans, aclblasDiagType_t diag, int n, int k,
    const aclblasComplex* A, int lda, aclblasComplex* x, int incx);
```

| 参数 | 类型与约束 |
| --- | --- |
| handle | 已创建的库句柄，提供 stream 和工作区 |
| uplo | ACLBLAS_UPPER 或 ACLBLAS_LOWER |
| trans | ACLBLAS_OP_N、ACLBLAS_OP_T、ACLBLAS_OP_C |
| diag | ACLBLAS_NON_UNIT 或 ACLBLAS_UNIT |
| n、k | int；n≥0，k≥0 |
| A | const aclblasComplex*；Device 上 lda×n 个复数 |
| lda | int；lda≥k+1 |
| x | aclblasComplex*；Device 输入输出，n>0 时跨度为 (n−1)×abs(incx)+1 |
| incx | int；非零，支持正负方向 |

### 需求拆解

1. 支持上三角、下三角，N、T、C，以及单位、非单位对角，共 12 种组合。
2. 引用有效带内矩阵元素；单位对角按 (1,0) 计算。
3. 支持 n=0 快速返回、k=0 对角矩阵、满带、带宽填充、正负步长和非法参数返回码。
4. 使用句柄绑定的 stream 执行异步设备计算。读回输出前同步 stream。
5. 使用 C++ GoogleTest、CSV、Netlib CBLAS 自验；在 CANN 9.1.0、Ascend910B3 上满足三项指定平均耗时要求。

## 详细设计（required）

### 算子分析

以下索引从 0 开始。上三角 A(i,j) 的存储偏移为 k+i−j+j×lda，有效行满足 max(0,j−k)≤i≤j。下三角偏移为 i−j+j×lda，有效行满足 j≤i≤min(n−1,j+k)。

向量逻辑元素 i 在正步长下偏移为 i×incx；负步长下偏移为 (n−1−i)×abs(incx)。T 使用转置后的索引；C 在转置时对矩阵虚部取反。单位对角直接贡献原向量对应元素。

### 主机端设计

`ctbmv_host.cpp` 依次检查句柄、枚举、维度、lda 和 incx。句柄为空返回 9，非法枚举返回 10，非法数值返回 3。参数有效且 n=0 时返回成功。n>0 时检查 A、x；k=0、diag=UNIT 时返回成功。

读取设备可用向量核心数，生成 `CtbmvTilingData`：n、k、effectiveK、lda、numBlocks、smallTileRows、incx、uplo、trans、diag。incx 使用 64 位整数传递。

#### 分块规则与适用条件

设设备可用向量核心数为 C，以下计算适用于 n>0、C>0。有效半带宽、目标块数 P、每块输出行数 R 和候选块数 B 定义为：

$$
k_{eff}=\min(k,n-1),\qquad P=\min(C,32),\qquad
R=\begin{cases}
32,&\lceil n/P\rceil\le32,\\
64,&\lceil n/P\rceil>32,
\end{cases}\qquad B=\lceil n/R\rceil.
$$

P 用于选择 R；B 表示小带宽路径实际启动的块数。B 可以大于 P，入口继续检查 B≤C。32、64 行分别对应单个实部分量数组的 128、256 字节，均满足 32 字节数据块对齐；64 行与内核 `SMALL_TILE_ROWS` 及索引缓冲区布局对应。目标值 32 是当前实现的调度参数，其最优性需要进一步实测评估。

小带宽路径同时要求：

1. incx=1，输入向量形成连续区间。
2. diag=NON_UNIT，批量矩阵读取包含实际对角元素。
3. 布局为 UPPER/N、LOWER/T 或 LOWER/C。这三种布局对输出区间 [s,e) 的输入依赖均落在 [s,min(n,e+k_eff))，便于一次缓存完整依赖。
4. k_eff≤256−R，使每核所需输入复数数量满足 R+k_eff≤256。
5. lda≥4，与当前每列四个复数的分组搬运入口约束一致。
6. B≤C，使启动的计算块数量处于设备可用向量核心数量范围内。

主机函数 `UseCtbmvSmallBandFastPath` 检查上述条件。设备函数 `UseSmallBandFastPath` 复查布局、步长、对角类型和容量，并检查 B 等于 `tiling.numBlocks`。设备侧的核心数量约束由主机传入的合法分块数据保证。

通用路径使用 min(C,n) 个块，按块编号交错分配输出行。调度函数输入来自设备核心数量和公开接口参数。主机为两条路径统一检查句柄工作区容量，并启动一个包含最终写回的设备内核。

### 设备端设计

#### 计算流程与有效读取范围

小带宽路径每个核心处理连续输出行。输入复数从全局内存搬入统一缓冲区（Unified Buffer，UB），实部、虚部分拆存储，使用 `Gather` 按带状索引取得各条对角线的贡献。矩阵按每组至多四个复数带状行搬运，四个复数占 32 字节；同组内的对角线复用该次搬运结果。

`LoadSmallBandA` 对每列执行有效区间交集。设列号为 j，带状存储的行号为 b，当前分组起点为 g、长度为 q。实际搬运区间为：

$$
I_U=[g,g+q)\cap[0,k+1)\cap[\max(0,k-j),k+1),
$$

$$
I_L=[g,g+q)\cap[0,k+1)\cap[0,n-j).
$$

`DataCopyPad` 的源地址和搬运长度由交集确定，左侧和右侧填充在 UB 中完成。交集为空时，当前列组的本地空间填零。计算阶段再用 `DiagonalOutputRange` 与当前输出块取交集，得到有效计算元素数。

需要设备计算的单位对角调用进入通用路径；`LoadAValue` 在行列号相等时直接返回 (1,0)，并在该位置结束函数。矩阵访问范围由行贡献区间限定在有效带内。负步长使用 64 位逻辑索引计算实际向量位置。

通用路径 `ProcessScalar` 按核心编号交错处理输出行，从主对角开始沿带内方向累加，将结果写入工作区。`Process` 在所有行计算结束后执行全核心同步，再调用 `CopyBack`。

#### 原地写回与同步条件

小带宽路径的第 c 个块处理 [cR,min(n,(c+1)R))。B=ceil(n/R) 保证每个已启动块的起点小于 n，因此每个块都会进入 `ProcessSmallBandTile`。该区间划分覆盖全部输出行，各块拥有独立的输出位置。

同步顺序为：

1. `LoadSmallBandX` 将本块完整输入依赖搬入 `xQueue_`。输入复数个数至多 R+k_eff≤256。
2. `SyncMte2ToV` 使用搬入流水线到向量流水线的事件等待，队列出队后调用 `SyncAllAiv`。
3. `SyncAllAiv` 先执行向量流水线到搬出流水线的事件等待，再调用 `FftsCrossCoreSync<PIPE_MTE3,0>(0)` 和 `WaitFlagDev(0)`。
4. 跨核等待完成时，每个参与块均已完成自身输入读取。后续向量计算持续使用本块的 `xLocal`，其生命周期覆盖最终输出搬运。
5. 各块把结果写回各自输出区间，并等待搬出流水线完成，再释放 `xLocal`。

因此，任意块开始覆盖全局 x 时，其他块所需的原始输入均已存入各自 UB。B≤C 是该全核同步设计的启动约束。该论证依赖主机与内核的路径选择条件一致，以及每个启动块执行相同次数的跨核同步。

通用路径设实际块数为 B_g=min(C,n)，行分配为 row=c+tB_g，其中 t 为非负整数。每行结果由所属块写入工作区，`StoreOneWorkspace` 在每次搬出后等待完成。各块完成所有行的原始 x 读取后进入同一次 `SyncAllAiv`。随后，incx=1 使用每段至多 256 个复数的并行搬运；incx≠1 由第 0 个块按逻辑索引逐元素写回。跨步路径中其他块的返回发生在跨核同步之后。

上述原地更新分析以 A、x 和句柄工作区分别占用独立存储区域为调用前提。调用方通过句柄绑定的 stream 管理执行顺序，并在读取设备结果前完成 stream 同步。

#### 复数计算与舍入顺序

设矩阵元素为 a_r+i a_i，输入元素为 x_r+i x_i。C 模式先对 a_i 取反。单项贡献为：

$$
p_r=a_rx_r-a_ix_i,\qquad p_i=a_rx_i+a_ix_r.
$$

向量函数 `ComplexMulAcc` 依次调用四次 `MulAddDst`：先向虚部累加 a_r x_i 和 a_i x_r，再向实部累加 a_r x_r 和 −a_i x_i。每条对角线按主对角向外的顺序处理。这里的计算顺序与 `ComplexMulAccFused` 分别描述，最终结果按任务书规定的分量容差判定。

软件辅助函数 `FusedMultiplyAdd` 的设计语义采用电气与电子工程师协会（IEEE）754 浮点运算标准的二进制单精度融合乘加：在乘积与加数求和后，执行最近偶数舍入。令 R32 表示该舍入，F 表示一次融合乘加：

$$
F(a,b,c)=R32(ab+c).
$$

`ComplexMulFused` 采用以下计算顺序：

$$
p_r=F(a_r,x_r,-R32(a_ix_i)),
$$

$$
p_i=\begin{cases}
F(x_r,a_i,R32(x_i a_r)),&trans=N,\\
F(a_r,x_i,R32(a_i x_r)),&trans=T\ \text{或}\ C.
\end{cases}
$$

随后实部、虚部分别通过 F(1,p,acc) 累加。通用路径和小带宽路径中的数值风险分组共用该辅助函数。单位对角的贡献直接取对应输入元素。

软件融合乘加的主要实现步骤为：

1. 拆解符号、指数和有效数；次正规数通过左移规格化。
2. 两个 24 位有效数形成精确的 48 位乘积，放入 64 位整数中进行指数对齐。右移丢失位通过粘滞位记录，即记录被移出的位中是否存在 1。
3. 根据符号执行有效数相加或相减，结果重新规格化，然后根据余数与中点的关系进行最近偶数舍入。
4. 极小结果在次正规数精度下舍入；最终指数超过范围时生成带符号无穷。
5. 非数（NaN）输入、零乘无穷和相反符号无穷相加生成规范静默 NaN；无穷、带符号零和精确抵消分别由对应分支处理。

N 模式下，软件计算路径将实部和虚部均为零的输入元素贡献按零处理，对应 [Netlib CTBMV 的非转置遍历](https://www.netlib.org/blas/ctbmv.f)。N 与 T/C 的虚部融合顺序是当前辅助函数采用的浮点求值顺序；参考 BLAS 的具体指令顺序受其实现和编译选项影响。复测材料需记录实际链接库的发行版本及编译环境。本轮记录了 `libblas.so.3` 的加载路径，发行来源及版本列为补充项。

#### 浮点指数条件的推导与检查范围

`MaxRawExponent` 分别求本块输入向量和当前矩阵分组全部实、虚分量的最大原始指数，记为 E_x、E_A。原始指数是 float32 的 8 位指数字段，有限数范围为 0 至 254，255 对应无穷或 NaN。令每个输出分量的实数乘积项数上界为 M：

$$
M=2(k_{eff}+1),\qquad L=\lceil\log_2 M\rceil.
$$

当 E_x=255、E_A=255 或 E_x+E_A+L≥380 时，整个矩阵分组调用软件融合乘加。指数来自当前调用的实际输入，M 来自有效半带宽。

阈值可由有限数幅值上界解释。原始指数为 E 的有限分量满足绝对值小于 2^(E−126)，该上界也覆盖零和次正规数。对于当前矩阵分组，把一行任一分量的实数乘积贡献补零至 M 项，其绝对值之和满足：

$$
\sum_{t=1}^{M}|u_tv_t|
<2^{E_A+E_x+\lceil\log_2 M\rceil-252}.
$$

进入向量计算的有限分组满足指数和至多 379，上式上界相应小于 2^127。该条件为乘积与累加量级提供保守的溢出风险判断。舍入误差、相消和次正规数精度另按输出分量标准验证。

软件融合乘加在一次融合操作内部延后乘积舍入；上述复数公式中的 `RoundedMultiply` 仍会产生独立舍入结果。整个复数表达式的精度与特殊值结果，通过公开接口和参考 BLAS 比对验证。现有证据为所列 GTest 与性能调用的输出检查；辅助函数的专项数值边界验证列为后续验证项。

### 存储与计算量

对于 n>0，有效带内复数位置数为 n(k_eff+1)−k_eff(k_eff+1)/2，算术工作量为 O(n(k_eff+1))。输入存储和主机检查的工作区需求为：

$$
B_A=8\,lda\,n,\quad B_x=8((n-1)|incx|+1),\quad W=32\left\lceil\frac{8n}{32}\right\rceil.
$$

单位为字节，向量公式适用于 n>0。工作区属于库句柄持有的分配；默认句柄容量为 32 MiB。此处 W 表示算子检查的容量需求。小带宽路径的结果直接写回 x；通用路径在该工作区中暂存 n 个复数。

每个向量核心在 `Init` 中通过 `TPipe::InitBuffer` 声明的 UB 空间如下，队列深度均为 1：

| 缓冲区 | 元素组成 | 容量（字节/核） |
| --- | --- | ---: |
| `aQueue_` | 至多 256 列，每列 4 个复数，每复数 2 个 float32 | 8192 |
| `xQueue_` | 256 个复数 | 2048 |
| `calcBuf_`：实虚分量与中间量 | 10 段，每段 256 个 float32 | 10240 |
| `calcBuf_`：交错输出 | 512 个 float32 | 2048 |
| `calcBuf_`：归约临时量与累加预留 | 256+8 个 float32 | 1056 |
| `calcBuf_`：索引 | 512 个 32 位索引 | 2048 |
| `calcBuf_`：指数提取及转换 | 2 段，每段 2048 个 32 位元素 | 16384 |
| 合计 | 三次 `InitBuffer` 声明值之和 | 42016 |

其中 `calcBuf_` 合计 31776 字节。表中数值由当前源码的偏移和长度计算，口径为每核显式声明容量；编译器额外占用、运行时内存和设备峰值内存另行测量。保存的 Ascend910B3 平台配置列出 `ub_size=196608` 字节，显式声明容量处于该范围内。当前两条路径共用此固定缓冲区布局。

256 个复数的输入容量决定 R+k_eff≤256 的分块条件。矩阵缓冲区容量按 256 列的四复数组分配。计算区为当前函数中的分量、临时量、索引和指数提取提供固定位置。调整分块大小时，应联合检查输入覆盖范围、索引跨度和每核容量。

## 可维可测分析

### 精度标准与覆盖

标准结果通过 CBLAS `cblas_ctbmv(CblasColMajor, ...)` 生成。逐元素条件为：

$$
|actual-golden|\le2^{-16}+2^{-10}|golden|.
$$

实部、虚部分别要求匹配率≥0.99且最大绝对误差≤0.01。NaN 按两侧类别匹配，Inf 按类别和符号匹配。全部 n 个输出复数参与比对。

CSV 包含 1000 项功能、精度、边界用例和 200 项性能用例；另有空句柄、非法 lda 存储、未映射区域填充值三项 GTest。未映射区域专项包含 48 组设备比较。

常规随机输入的均匀分布与正态分布各占 50%。矩阵配置为 596/596/8（均匀/正态/特殊），向量为 597/597/6。正态分布采用 5 个均值与 5 个标准差，实部、虚部使用独立随机种子。

### 性能标准

在同一 stream 上，每项预热 20 次、有效调用 100 次，每次调用前恢复原始 x，每次有效调用后进行精度检查。CANN `ACL_PROF_TASK_TIME_L0` 导出的设备计算任务 `task_time(us)` 用于计时。所列性能采样调用均执行一个完整设备计算任务，其范围包含核内计算、同步和最终写回。100 个有效样本的算术平均值与任务书上限比较，最大值作为附加统计记录。

参数有效的 n=0，以及 k=0、diag=UNIT，在主机端返回成功，设备任务数量为零。这两类调用按快速返回功能验证。

### 通用路径性能与后续验证

通用路径按输出行执行标量循环。非单位对角、非零向量元素的常规贡献包含矩阵分量读取、8 字节输入向量搬运、相应等待以及软件复数乘加；每行结果还包含一次 8 字节工作区写入。带宽和阶数增大时，这些操作的执行次数随有效带内位置数增长。incx≠1 的最终写回由第 0 个块逐元素执行，还包含串行写回成本。小带宽路径中的数值风险分组也会执行逐元素软件计算。

现有扩展测量包含：n=4096、k=512、LOWER/N/NON_UNIT、lda=513、incx=1，在同一 Ascend910B3 环境下平均设备耗时为 30073.186400 μs，最大值为 30084.020 μs，每项统计采用预热后的 100 次有效调用。该布局与带宽进入通用路径。任务书三项性能上限的参数范围见前表；扩展参数的耗时按测量值单独记录。

当前源码结构表明，小粒度搬运及等待、软件浮点运算、跨步串行写回均可能影响通用路径耗时。现有设备任务总耗时支持上述性能记录；各部分的耗时占比需要进一步设备性能分析。后续优化可研究输入分段复用、通用布局向量化和跨步结果的分块写回，并复核有效读取范围与原地更新同步条件。

现有测试已覆盖正负步长、12 种枚举组合以及带外填充值。后续评审验证应重点补充：32/64 行分块切换附近和 B=C 附近的参数、R+k_eff=256 附近的容量边界、指数和 379/380 附近的有限输入、次正规数及强相消输入。所用数据及参数通过现有 C++ GoogleTest、CSV、CBLAS 测试链路执行；新增验证结果单独记录。
