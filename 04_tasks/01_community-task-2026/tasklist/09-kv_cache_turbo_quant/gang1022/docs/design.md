# KvCacheTurboQuant 算子设计文档

> 提交人：gang1022；设计版本：v0.1；日期：2026-09-23。本文是设计方案，性能和精度结果须在 Atlas 800T A2 真机自验后填写，文中没有测试通过结论。

# 需求背景（required）

## 需求来源

本设计依据[9月社区任务 kv_cache_turbo_quant 算子开发任务书](https://www.hiascend.com/activities/task-center/details/6d3df013343845608677c85f3c58d4d6)及其附件 `op.json`、`case.json`、`golden.py`，采用本仓库 `04_tasks/01_community-task-2026/resources/design_template.md` 的章节结构。任务书规定：面向标准 MHA/GQA KV cache，开发 Ascend C 的 aclnn 在线编码算子；验证硬件为 Atlas 800T A2，CANN 版本为 9.1.0 及以上。任务书正文高于任务页简介和模板中的其他算子示例。

本题标杆是随附 `golden.py:calc_expect_func` 的 PyTorch eager Encode 参考实现。任务未提供同名 TBE 算子或 TBE 源码，因此本设计不填写虚构的 TBE 路径。目标工程为 `cann/ops-transformer/experimental/attention`；设计文档先在竞赛仓评审，代码在任务要求的验收通过后另向代码仓提交 PR。

## 背景介绍

标准 MHA/GQA 在推理时保存每个 token、每个 KV head 的向量。BF16、`head_dim=128` 时，一个向量占 `128×16=2048 bit=256 B`。任务书要求用统一的 MSE 主量化和 QJL 残差编码降低存储开销。默认 `mse_bits=3`、`qjl_dim=128` 时，主编码 48 B、QJL 编码 16 B、范数与残差尺度各 2 B，合计 **68 B/head，即 4.25 bit/channel，理论压缩比 256/68≈3.76×**。这些是格式计算值，不能代替设备性能结果。

首版不实现论文中按异常通道划分的混合 3.5 bit/channel 模式，也不覆盖 MLA latent KV cache。旋转矩阵和高斯投影矩阵由调用方预生成、推理期间固定，但仍以张量输入传入，不固化到 Kernel 常量中。

### 参考流程

```text
BF16 向量 x → FP32 范数 n → 单位向量 u → y=H·u
                                            ├→ 质心量化 idx → 位打包 quant_idx
                                            └→ 残差 r=y-c[idx] → 范数 ρ
                                                → S·(r/ρ) → 符号位打包 quant_qjl
n → 输出量化 quant_norm；n×ρ → 输出量化 quant_gamma
```

# 需求分析（required）

## 需求描述与范围

输入 `kv_vectors` 为 `[T,H,128]` 的 BF16 K 或 V 向量；`rotation_matrix` 为 `[128,128]` 的 FP32/BF16 正交旋转矩阵；`qjl_matrix` 为 `[Q,128]` 的 FP32/BF16 高斯投影矩阵。`H` 是 KV heads 数，支持任务书规定的 4 至 32；`Q=qjl_dim` 通常为 128，但按矩阵首维决定输出长度，不把“通常等维”误写成固定等维。`mse_bits` 支持 2、3、4，默认 3。所有张量使用 ND 格式。任务附件 `op.json` 与五个 `case.json` 用例只覆盖上述范围的子集，其中矩阵为 FP32、范数输出为 BF16、`H=8`、`Q=128`。

| 参数 | 方向 | 类型 | 形状/约束 |
|---|---|---|---|
| `kv_vectors` | 输入 | BF16 | `[T,H,128]`；K、V 均可调用 |
| `rotation_matrix` | 输入 | FP32/BF16 | `[128,128]`；调用方保证正交 |
| `qjl_matrix` | 输入 | FP32/BF16 | `[Q,128]`；调用方保证固定的高斯投影分布，`Q>0` |
| `mse_bits` | 属性 | int | 2/3/4，默认 3 |
| `quant_idx` | 输出 | UINT8 | `[T,H,ceil(128×mse_bits/8)]` |
| `quant_qjl` | 输出 | UINT8 | `[T,H,ceil(Q/8)]` |
| `quant_norm` | 输出 | FP16/BF16 | `[T,H]`；官方五例使用 BF16 |
| `quant_gamma` | 输出 | FP16/BF16 | `[T,H]`；官方五例使用 BF16 |

接口采用 aclnn 两阶段调用模式：第一阶段校验输入与输出、计算 tiling 和 workspace，第二阶段发起异步计算。实际 C++ 函数签名、算子注册和 `op_host/op_api` 文件名以 `ops-transformer` 同类算子工程规范实现；接口语义包含三个输入张量、`mse_bits` 属性和四个输出张量。输出类型须按接口声明校验，不能为迁就附件子集删掉任务书中的 BF16 矩阵或 FP16 范数范围。

## 需求拆解

1. 一个向量独立完成归一化、旋转、主量化、残差投影和四输出写回；不同 `(token,head)` 间没有数据依赖。
2. 主量化的质心、相邻质心中点阈值、严格 `>` 比较及 2/3/4 bit 位布局与附件 Golden 对齐。
3. QJL 符号采用 `projected >= 0`；投影基于**单位残差**，`gamma` 使用原尺度 `n×ρ`。
4. BF16 输入和矩阵先升为 FP32 参与计算，输出范数和 gamma 在末端转为声明的 FP16/BF16；矩阵乘加、归约和舍入差异需用 A2 实测判定。
5. 默认三位格式满足 68 B/head；其他位宽与 Q 值按公式计算，不能沿用 4.25 bit/channel。
6. 在线 Encode 要满足重构、内积和性能标准；报告分别给出数值程序、输入身份、硬件环境和原始计时证据。

# 详细设计（required）

## 算子分析

### 数学语义与边界

对每个 `x∈R^128`，令 `n=||x||₂`，`u=x/n`（`n=0` 时 `u=0`），`y=H·u`。`C_b` 为附件 Golden 的 `CENTROIDS[b]`，按升序排列；相邻中点 `t_j=(C_b[j]+C_b[j+1])/2`。每维编码 `idx_i=Σ_j [y_i>t_j]`，主重构 `c_i=C_b[idx_i]`，残差 `r=y-c`，`ρ=||r||₂`。输出尺度为 `quant_norm=cast(n)`、`quant_gamma=cast(n×ρ)`。残差单位向量在 `ρ=0` 时取零，否则 `v=r/ρ`；QJL 投影 `p=S·v`，符号位 `q_j=[p_j>=0]`。

当 `n=0` 时仍按 Golden 计算 `y=0`、质心索引、残差和 QJL，不得直接把全部编码输出清零；此时 `quant_norm=quant_gamma=0`。当 `ρ=0` 时，`v=0`，投影为 0，按 `>=0` 规则 QJL 各有效位为 1。除零保护采用与 Golden 对齐的条件选择；非零分支的 FP32 计算需逐步比对。

主编码以每 8 个维度为一组：`word=Σ_{lane=0}^7 idx_lane << (lane×b)`，再按低字节在前写出 `b` 个 UINT8。`D=128` 时共有 16 组，输出长度分别为 32、48、64 B。QJL 每 8 个投影符号组成一个低位在前的字节；`Q` 不足 8 的末组高位填零，输出 `ceil(Q/8)` B。尾位不能读取矩阵越界，也不能把填充位参与统计。

主量化质心须使用附件 Golden 的以下常量，顺序由负到正；阈值均由相邻两项中点计算，不能换成等间隔量化：

| bits | 质心 `C_b` |
|---:|---|
| 2 | `[-0.1335033178, -0.04002048075, 0.04002048075, 0.1335033178]` |
| 3 | `[-0.19020693, -0.1187859178, -0.06682205945, -0.02166347019, 0.02166347019, 0.06682205945, 0.1187859178, 0.19020693]` |
| 4 | `[-0.2414890379, -0.1828317791, -0.1429702938, -0.1109927073, -0.08325428516, -0.05802082643, -0.03428063914, -0.01134236995, 0.01134236995, 0.03428063914, 0.05802082643, 0.08325428516, 0.1109927073, 0.1429702938, 0.1828317791, 0.2414890379]` |

### 格式与存储

| `mse_bits` | 默认 `Q=128` 时主码 | QJL | 两个 16 bit 标量 | 总计 | 相对 BF16 理论压缩比 |
|---:|---:|---:|---:|---:|---:|
| 2 | 32 B | 16 B | 4 B | 52 B | 256/52≈4.92× |
| 3 | 48 B | 16 B | 4 B | **68 B** | **256/68≈3.76×** |
| 4 | 64 B | 16 B | 4 B | 84 B | 256/84≈3.05× |

一般情形每 head 字节数为 `ceil(128×b/8)+ceil(Q/8)+2+2`（两个标量均为 16 bit）。矩阵由调用方共享，以上只计算 KV cache 编码本体，不把常驻矩阵摊入单 head 大小。

## 算子实现

### Host 侧设计

Host 校验张量数量、ND 格式、dtype、shape、`mse_bits` 范围、stride/连续性和输出形状；从矩阵首维读取 `Q`，用 64 位整数计算 `N=T×H`、输出字节数及总地址，防止溢出。非连续输入按目标仓的 aclnn 规范通过 stride 寻址或必要的连续化步骤处理，不能静默按连续内存读取；所需 workspace 同步计入。`T=0` 时仅保留空输出，不启动 Kernel；`T>0` 时由平台信息取得可用核数与 UB 大小。矩阵的正交性和高斯分布由调用方/测试数据提供，不在热路径逐元素验证。

**核间切分**：以一个 `(token,head)` 向量为最小任务单位，`blockDim=min(可用核数,N)`。每核处理一段连续向量，前若干核多分配一个向量；核间无归约和写重叠。`N` 很小时优先低启动开销；`N` 很大时让一个核循环处理多向量，复用矩阵块。Host 向 tiling data 写入 `N、Q、mse_bits、输入/输出步长、每核起点与个数、每批向量数 B、矩阵行块 R、缓冲数及尾块信息`。输出偏移按 `vector_id×对应每 head 字节数` 计算。

**核内切分与 UB 预算**：按 32 B 对齐分配缓冲，矩阵沿输出行分块搬入，设计初值 `R=32`、`B=1`（decode）或试探 `B=4/8`（prefill）。两种矩阵均为 FP32 后，每个 `R×128` 行块占 `4R×128=16 KiB`；双缓冲两个矩阵行块合计 `2×2×16=64 KiB`。每批的 x/u/y/c/r/v、归约临时值和打包输出另计 `M_vec(B,Q)`，总预算：

`M_UB = align32(2×4R×128) + align32(2×4R×128) + M_vec(B,Q) + M_pack(B,Q) + M_api_tmp ≤ 实际可用 UB`。

其中两个首项分别是 H 与 S 的双缓冲，`M_vec`、`M_pack` 要按真实 Ascend C API 临时缓冲、Q 的分块和流水占用在编码时逐项核算；若容量不足，先减小 `B/R` 或改为单缓冲。不能把示例 64 KiB 当作完整 UB 占用或把模板示例的 UB 大小当作 A2 实测值。QJL 矩阵对任意正 `Q` 分块流式处理，避免 `Q` 大时常驻完整矩阵。

**tilingKey**：按 `mse_bits∈{2,3,4}` 与矩阵 dtype 路径选计算分支；小 N 与大 N 通过 tiling data 的 B 值调整，不为每个 shape 创建独立 Kernel。矩阵 dtype 的两种输入组合均保持 FP32 计算语义。准确的 `R/B`、缓冲重用和 tilingKey 编码随 A2 编译、精度、性能实测固定，变更时同步更新本文。

**Workspace**：首版融合四输出计算，设计上不申请存放完整 y/r 的额外全局中间张量；若目标仓 aclnn 框架要求系统 workspace，应按其接口返回并与用户数据 workspace 分开记录。任何因实现调整而新增的临时 GM 缓冲须补容量公式和生命周期。

### Kernel 侧设计

```text
Init: 根据 tiling data 绑定 GM 输入/输出，分配对齐的 LocalTensor/队列。
For 每核的向量批：
  CopyIn: 读取 BF16 x，转换 FP32；按行块读取 H/S，BF16 矩阵转换 FP32。
  Compute 1: FP32 平方和归约、sqrt 得 n；条件化归一化得到 u。
  Compute 2: 分行块求 H·u 得 y；与 C_b 中点作严格 > 比较，生成 idx。
  Compute 3: 质心回查、r=y-c、FP32 残差归约得 ρ；条件化归一化得 v。
  Compute 4: 分行块求 S·v，比较 >=0 得符号位；按 Golden 分组/字节序位打包。
  CopyOut: 写 quant_idx、quant_qjl；n 与 n×ρ 末端转 FP16/BF16 并写回。
```

```text
GM: x/H/S ──CopyIn+Cast──→ FP32 LocalTensor
                                 │
                        norm → unit → H 行块点积
                                 │
                      质心比较/idx ──→ 主码打包
                                 │
                        残差/残差范数
                                 │
                        单位残差 → S 行块点积
                                 │
                           >=0 → QJL 打包
                                 │
                  CopyOut: idx/QJL/norm/gamma
```

阶段 1、3 的归约结果只在所属向量内使用；归约临时缓冲和同步以实际 Ascend C API 约束实现。阶段 2、4 对矩阵行做点积，可按数据类型及 A2 能力比较 Vector FP32 与可行的矩阵计算路径；任何低精度加速路径须先验证是否满足输出编码与标量精度判据，不能靠降低比较标准换性能。对 `Q` 尾块使用有效长度掩码；压缩字节只写当前向量的独立输出区间。先保证融合单 Kernel 的正确性，再通过矩阵块复用、搬算重叠、批向量处理和合适的 B/R 调优。

### Golden 与 Kernel 流程差异

| 环节 | 附件 PyTorch Golden | 计划中的 Ascend C Kernel | 一致性要求 |
|---|---|---|---|
| FP32 计算 | BF16/FP32 输入转 FP32，张量算子逐阶段执行 | LocalTensor 中归约、旋转、投影；部分步骤融合 | 数值比较须覆盖四输出与边界值 |
| 质心量化 | 向量化生成中点并统计严格 `>` | 按位宽分支使用固定质心表、逐维比较 | 阈值及等号方向一致 |
| 打包 | 每组 8 lane，低字节先写 | 每向量本地打包并搬出 | 分组、尾位及字节序一致 |
| 矩阵复用 | PyTorch 每次调用由框架调度矩阵乘 | 同核多向量复用矩阵行块、减少启动与中间 GM 写 | 不改变 H/S 输入语义 |

## 支持硬件与特性交叉

| 场景/特性 | 影响和处理 |
|---|---|
| Atlas 800T A2，CANN≥9.1.0 | 本题唯一要求的验证平台；记录实际设备身份、驱动/固件、CANN 和构建参数 |
| MHA/GQA，4≤H≤32 | 相同 per-head 编码，各 head 独立；N=T×H 用于均分，不以测试附件 H=8 限死接口 |

# 可维可测分析

## 精度与性能验证方案

在 Atlas 800T A2、CANN 9.1.0+ 上完成官方五个用例，逐例记录完整输入 dtype/shape、矩阵身份、四输出 shape/dtype、Golden 比对、重构/内积统计、原始日志。附件 `case.json` 引用了 `data/rotation_matrix.bin` 和 `data/qjl_matrix.bin`，但原附件 ZIP 未包含这两个二进制文件；自建测试矩阵须固定生成脚本、随机种子及 SHA256，并与官方原件明确区分。旋转矩阵需验证正交条件，高斯矩阵分布及归一化尺度需写入测试元数据。

| 官方 case | `T,H,D` | bits | idx / QJL 长度（Q=128） | 任务书 eager 基线（µs） | 达到 10× 时的 A2 耗时上界（µs） |
|---|---|---:|---:|---:|---:|
| `gqa_decode_b1` | 1,8,128 | 3 | 48 / 16 | 1491.676 | 149.1676 |
| `gqa_decode_b64` | 64,8,128 | 3 | 48 / 16 | 1552.784 | 155.2784 |
| `gqa_prefill_t2048` | 2048,8,128 | 3 | 48 / 16 | 3855.422 | 385.5422 |
| `gqa_mse2_t2048` | 2048,8,128 | 2 | 32 / 16 | 3607.963 | 360.7963 |
| `gqa_mse4_t2048` | 2048,8,128 | 4 | 64 / 16 | 5286.502 | 528.6502 |

验收指标分别为：`MSE/||x||²<0.05`；`|<q,x_hat>-<q,x>|/|<q,x>|` 的 **95th percentile `<0.1`**；功能等价 PyTorch eager Encode 加速 **≥10×**，且在线编码不成为 prefill KV 生成瓶颈。任务书未随附件提供 q、反量化/内积估计程序、完整统计轴和零分母口径；这些须在自验脚本中依据正式口径锁定并与设计评审对齐，不能把四输出比对直接当作两项统计指标已通过，也不能自加 epsilon、删样本或只选择有利 case。重构至少要明确从 `idx` 解码质心、逆旋转与范数的关系；QJL 内积修正需依据实际 S 分布和 q 输入定义，不能凭空把符号字节当作普通向量重构。

性能分别保留任务书给出的五个 eager 基线和**同一台 A2、相同输入/依赖/计时边界**实测的 eager 参考耗时；报告中写明用哪个基线形成判定。计时应预热、同步设备、重复采样并报告统计量，Golden 生成期望结果的 CPU 搬运不混入功能等价 Encode 的计时。不得用跨设备或跨输入耗时拼成加速比。五个用例均需记录通过/失败/跳过、退出码、代码 commit、测试脚本版本及日志位置；未执行时状态为未执行。

补充验证覆盖 H=4 与 32、范围内其他 H、BF16 矩阵、FP16 标量输出、Q 非 128 与 QJL 尾位、零/近零向量、非法形状和位宽。补充用例与五个官方 case 分表记录，不虚称官方给出更多 case。

## 可维护性与兼容性

Host 侧集中校验与 tiling，Kernel 保持“归约—旋转—量化—残差—投影—打包”可追踪阶段；质心表与打包规则放在单一实现位置并附针对 2/3/4 bit 的诊断测试。仅在证据显示收益时增加 dtype/规模分支，避免为五个 case 复制五份 Kernel。源码、测试、README、API 文档和构建文件遵循 `ops-transformer` 贡献规范，最终算子目录为 `experimental/attention` 下的本题实现。

这是新增算子，不涉及替换既有同名算子的向后兼容；接口仍需遵守 aclnn 调用约定、ND 连续布局、输出 dtype/shape 和错误处理。设计 PR 的评审、CLA/构建检查与代码 PR 的 CI、真机自验、验收为独立状态；本设计提交不代表后者已经完成。

## 设计待验证点

- A2 上矩阵行块/批向量参数、实际 UB 容量及系统 workspace 数值，需要编译和 Profiling 后回填。
- 输出比较器、重构与内积的可执行统计协议，以及缺失矩阵二进制的替代输入身份，需要在真机自验前锁定。
- 任何为达到 10× 而引入的低精度矩阵路径或流水并行，都须重新验证官方五例及两项统计精度要求。
