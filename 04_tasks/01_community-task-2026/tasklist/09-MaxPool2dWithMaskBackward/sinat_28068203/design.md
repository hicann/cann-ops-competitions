# MaxPool2dWithMaskBackward 算子设计

## 1. 需求背景

### 1.1 需求来源

[9月社区任务-MaxPool2dWithMaskBackward算子开发](https://www.hiascend.com/activities/task-center/details/41ecbfa3d3cd4306adaf8236460aed08?menu=tasks)。贡献者：hlyruby（GitCode 命名空间：sinat_28068203）。开发代码目标为 `cann/ops-nn/experimental/pooling/max_pool2d_with_mask_backward`。

### 1.2 背景介绍

最大池化反向传播利用正向保存的最大值位置，将输出梯度累加到输入平面。重叠窗口可能指向同一输入位置，需要处理累加冲突和低精度舍入。采用 Ascend C 实现 Host 参数校验、Tiling 和设备侧计算，面向 Atlas 800T A2 与 Atlas 300V Pro。

## 2. 需求分析

### 2.1 接口与数据约定

任务附件的 prototype 与 golden 共同定义输入接口。`self` 只用于确定输出形状，不参与数值计算。

| 参数 | 类型 | 逻辑形状/含义 |
| --- | --- | --- |
| gradOutput | FLOAT16/FLOAT32/BFLOAT16 | `[N,C,Ho,Wo]`，输出梯度 |
| self | 与 gradOutput 相同 | `[N,C,Hi,Wi]`，正向输入形状 |
| indices | INT8 | `[N,C,Kh*Kw,M]`，argmax 的字节容器 |
| kernelSize | INT64 列表 | 长度 1 或 2，正整数 |
| stride | INT64 列表 | 长度 0、1 或 2；空列表取 kernelSize |
| padding | INT64 列表 | 长度 1 或 2，`0 <= P <= K` |
| dilation | INT64 列表 | 长度 1 或 2，元素均为 1 |
| ceilMode | BOOL | 默认 false，控制输出尺寸取整 |
| gradInput | 与 gradOutput 相同 | `[N,C,Hi,Wi]` |

逻辑布局为 NCHW，注册存储格式为 ND，与任务 prototype 保持一致。非连续输入由 ACLNN 连续化处理，输出通过框架回写适配非连续视图。BFLOAT16 仅在 A2 启用，310P 限定 FLOAT16/FLOAT32。

令 `L=Ho*Wo`，`M=(ceil(L/16)+1)*32`。附件 golden 规定整个 indices 容器的**连续前 `4*N*C*L` 字节**为小端 INT32 索引：

`argmax[n,c,q] = reinterpret_int32(indices_bytes)[(n*C+c)*L+q]`。

索引值是通道内的 `hi*Wi+wi`。容器尾部不参与计算；不能使用 `[Kh*Kw,M]` 的字节跨度定位各通道 argmax，也不能按逐窗口位图解码。此接口与内置 bitmask 编码不可混用，调用方须按附件约定生成索引。窗口面积须满足附件 golden 的 `Kh*Kw >= 2`；若扩展到面积 1，须另行定义容器容量不足的接口处理，不将其静默解释为当前编码。

### 2.2 功能拆解

1. 校验形状、属性、dtype 和索引容器容量。
2. 按输出所有权分核，避免重叠窗口的跨核写竞争。
3. 以 FP32 按固定顺序累加，结束后一次转换到输出 dtype。
4. 覆盖小通道大平面、非对齐宽度、重叠窗口、非方形窗口及 ceilMode。
5. 提供可复现的精度、性能及泛化测试流程。

## 3. 详细设计

### 3.1 数学定义

对通道 `b=n*C+c` 和输入平面位置 `p`：

`gradInput[b,p] = cast_T(sum_q (argmax[b,q]==p ? float32(gradOutput[b,q]) : 0))`。

求和按 `q=oh*Wo+ow` 的升序进行。没有命中索引的位置写零。算法不依赖 self 的数值。合法索引须在输入平面内，且属于对应输出的池化窗口。

单维输出长度使用 `a=I+2P-K`：floor 模式为 `floor(a/S)+1`，ceil 模式为 `ceil(a/S)+1`，随后当 `(O-1)*S >= I+P` 时将 ceil 模式的 O 减一。Host 中使用数学意义的整除，避免负数 C++ 截断导致边界形状错误。

### 3.2 Host 与 Tiling

Host 核对三个输入和一个输出的维度、N/C 一致性、dtype 配对、Ho/Wo 公式、indices 形状及字节容量。尺寸乘法使用宽整数并在乘法前检查溢出；异常参数返回失败，不截断进入 Kernel。非连续 Tensor 在进入 Kernel 前转为连续逻辑布局。

Tiling 下发输入/输出平面尺寸、窗口与步长、padding、通道数、输出块尺寸、块数和核心数。根据平台 UB 容量与可用计算核心数分配块，块内保存输出累加区与梯度/索引缓存。以通道和平面片共同构成任务，不仅按 N*C 分核，避免小通道大图退化到少数核心。

块边界按输出 DMA 对齐粒度设计。尾块搬运需显式处理有效长度；不同核心不能通过对齐扩写覆盖相邻输出。310P 与 A2 使用各自支持的搬运接口，BF16 模板由架构条件隔离。310P 的 FP32 转 FP16 使用受支持的 CAST_NONE；该架构不支持 CAST_RINT，A2 仍使用 CAST_RINT。

### 3.3 Kernel

每个任务独占连续的 gradInput 平面片。先将 FP32 累加区置零，再读取覆盖该片的 gradOutput 与 INT32 argmax。仅将命中当前片且在输入平面内的索引累加到本地输出，按输出窗口的行优先顺序处理，以保证固定累加顺序。每个输入位置最终只由一个任务写回，不需要全局浮点原子加或核间清零同步。

合法索引来自对应池化窗口，因此可利用窗口几何缩小需要扫描的 gradOutput 区域；不能对每个输出片扫描完整梯度平面。梯度与索引采用分块 DMA 进入 UB，降低逐元素 GM 访问。回退路径将候选输出行合为连续 q 区间，每批最多处理 2048 个梯度，保持 q 升序。310P 非对齐输入向前取 32 字节对齐起点，在 UB 保留前缀并在访问时加相应偏移，仅对不足一个对齐块的尾部做标量读取，不越过请求区间末端。FP16/BF16 数据转为 FP32 后累加，再一次舍入写回；FLOAT32 保持 FP32 累加。

当相邻块覆盖相同的池化窗口时，允许重复读取该窗口，但通过输出所有权筛选避免重复写入。优化方向包括缓存复用、向量索引比较、非重叠窗口快路径及双缓冲；任何优化均须保持索引编码与确定性顺序。

### 3.4 软件结构

| 目录 | 职责 |

| op_host | OpDef、InferShape/InferDataType、属性检查、Tiling |
| op_kernel | Tiling 数据结构、Ascend C 分块搬运与累加 |

| examples | ACLNN 调用入口与运行说明 |

采用 experimental 自定义算子包构建链，ACLNN 接口显式调用 Contiguous 和 ViewCopy，处理输入连续化与输出视图回写，并将空 stride 规范化为 kernelSize。通过独立 vendor 包加载，保留系统算子用于基线比较，避免以自定义实现覆盖基线后形成自我对比。

### 3.5 A2 向量化路径

输入平面按行分为 512 元素的片段，每个向量 lane 独占一个输入位置。根据输入位置与步长计算可覆盖该位置的输出窗口，按 oh 升序、ow 升序逐组 Gather 梯度和索引；仅当 argmax 等于当前输入平面位置时累加。越界候选映射到显式的零梯度/无效索引哨兵，避免越界读取和重复贡献。

当完整候选输出行可装入 8192 元素的源缓存时，优先将通道内连续最多 1024 个输入位置作为一个片段，允许一个向量批次跨越输入行。各 lane 独立计算行列坐标；候选输出列先作边界检查，再转换为源缓存偏移，防止越界列绕到相邻行。尾块按实际元素数上取整到向量粒度执行，写回仅使用有效长度。二次幂除数采用精确二进制缩放，其他除数通过余数修正取整。

候选窗口不超过 4 个、完整候选输出行可装入 4096 元素缓存时，将输入分片扩展到 2048 元素，使用 4 组候选偏移缓存，减少任务数和同步次数。FP16/BFLOAT16 路径 UB 占用为 169984 字节，FLOAT32 为 157760 字节；否则在候选窗口不超过 9 个、源区域可装入 6144 元素缓存时使用 1536 元素分片，其 FP16/BFLOAT16 与 FLOAT32 UB 占用分别为 188928 / 173632 字节；其余形状保持 1024 元素分片。

Host 枚举不超过 min(N*C, 核心数) 的通道组数，以任务轮数乘以每组通道工作量和映射准备开销估算最慢核心耗时，选择组数。各组通道数最多相差 1，同一空间片段的坐标映射在组内复用。候选窗口数不超过 9 时缓存各窗口的 Gather 偏移，超出时实时计算；余数通道和尾片段按实际长度执行。INT32 argmax 直接 DMA 至源缓存，以整数比较判定命中，省去转浮点和索引中转区。FLOAT32 梯度直接 DMA 至源缓存，去掉 UB 内中转；FLOAT16/BFLOAT16 保留 FP32 转换。左边界哨兵每个空间任务初始化一次并跨通道复用；右边界在每次 DMA 后恢复。FLOAT32 累加区直接写回 GM，省去输出中转。其余源缓存有效区域由 DMA 覆盖。缓存容量上界同时考虑窗口、步长和宽度，不依赖用例编号。

窗口映射使用浮点向量与整数转换生成，对倒数乘法的取整结果通过余数进行修正。仅当平面索引小于 2^24、窗口参数满足精确整数表示及 UB 容量约束时启用该路径；其他形状和 310P 使用分块回退路径。两条路径均保持同一输入位置的累加次序。平台核心信息在 TilingParse 阶段保存，在运行期平台信息缺失时使用编译信息，兼容 ACLNN 与动态图调用。

## 4. 可维可测分析

### 4.1 精度验证方案

A2 覆盖附件全部 140 个用例，310P 筛选支持的 FLOAT32/FLOAT16 共 103 例，以未经修改的 golden 为参考。测试脚本通过 dtype 参数筛选，另验证 310P 对 BF16 的拒绝行为。索引从量化到目标 dtype 后的 self 生成；梯度使用固定随机种子。对 FLOAT16、FLOAT32、BFLOAT16 分别记录参数、绝对/相对误差及官方阈值判定，按[生态算子精度标准](https://gitcode.com/cann/opbase/blob/master/docs/zh/ops_precision_standard/experimental_standard.md)计算精度指标。

新增测试包括单值属性、空 stride、ceil 尾窗口、非连续输入与输出、多个窗口命中同一位置、零梯度、非对齐形状、很小 N*C 与大平面、重复运行的确定性，以及非法 dtype/shape/属性拒绝。官方原件保持只读，数据生成在测试工作目录进行。输入不包含 NaN 或负无穷。

### 4.2 性能验证方案

目标环境为 CANN 9.0.0 或 9.1.0。对相同 shape、dtype 和属性，分别运行原 TBE 与 Ascend C 实现，预热后采集设备 Kernel 耗时，数据生成、H2D/D2H 与首次编译不计入。检查 profiler 中实际执行路径，防止误测 AICPU 回退。

A2 整体性能不低于 TBE 的 95%，同口径速度比为 `T_TBE/T_AscendC`。100 us 以下的小 shape 若耗时超过 TBE 30%，补充性能仿真图和分析。310P 验证功能精度，以 A2(910B3) 耗时的 5 倍作为参考，超过该参考 30% 的场景补充性能仿真图。基线的索引编码必须转换为其真实接口约定，禁止将 argmax 前缀直接作为内置 bitmask 使用。

### 4.3 模型接入方案

在 Atlas 300V Pro 上接入 YOLOv11，使用 DOTAv1 数据集；与 Atlas 800T A2 使用相同模型权重、数据划分、预处理及评估参数。确保模型实际调用目标反向算子，记录调用路径，比较 mAP50，绝对差不超过 0.01。模型验证代码按任务要求贡献至 modelzoo-GPL 指定目录。

## 5. 兼容性与限制

算子独立放置于 experimental/pooling，不修改已有池化算子或 A5 路径。确定性输出同时满足默认非确定性模式的允许行为。官方参数表中未单列 self，附件 prototype 和 golden 均要求 self，因此采用三输入接口。indices 使用任务附件的 INT32 前缀协议，调用方须与之配套。BF16 不在 310P 声明支持。设计文档仅描述方案与验证方法，验证结果由独立测试报告承载。
