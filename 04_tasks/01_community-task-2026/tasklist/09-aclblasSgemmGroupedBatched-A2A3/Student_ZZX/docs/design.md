# 需求背景（required）

## 需求来源

2026 年 CANN 社区任务 `aclblasSgemmGroupedBatched_A2A3`，目标是在 ops-blas 已有公共 BLAS 接口下新增 `arch22` 实现，支持 Atlas A2/A3。任务书、原始测试数据和生成器保留在本项目 `original_task/`。最终代码目标目录为 `blas/gemm_grouped_batched/arch22/`，测试目标目录为 `test/gemm_grouped_batched/sgemm_grouped_batched/arch22/`。

## 背景介绍

分组批量矩阵乘允许每组独立指定形状、转置、前导维、`alpha`、`beta` 和 batch 数。矩阵均为列主序，数学定义是 `C[g,j] = alpha[g] × op(A[g,j]) × op(B[g,j]) + beta[g] × C[g,j]`。公共入口 `aclblasSgemmGroupedBatched` 已在 `include/cann_ops_blas.h` 声明；本任务复用该签名及 handle 所绑定的 stream，不新增同名 API。

主仓现有 `arch35` 实现不覆盖本任务的 A2/A3 `arch22`。通用实现必须覆盖所有合法输入；规则矩阵通过 Cube 路径加速，以满足原始性能用例。

# 需求分析（required）

## 需求描述

输入为按组排列的 Host 参数数组、Host 指针数组和位于 Device 的 FP32 矩阵。支持 `OP_N`/`OP_T` 的四种组合、非方阵、任意合法列主序前导维、空组、零维、`k=0`、`alpha=0`、`beta=0`，并保持异步 stream 语义。`OP_C` 按任务要求返回非法参数。`A/B` 不可修改，`C` 的列 padding 不可改写。

## 需求拆解

1. 在入队前完成全组参数校验，避免后续组无效导致前组已写入；对维度、步长、总 batch 和地址偏移使用足够宽的整数并检测溢出。
2. 将 Host 参数及 Device 地址按值快照到固定容量 packet；函数返回后调用者可以销毁参数数组，但 Device 矩阵须保持到 stream 完成。
3. 用 AIV 路径覆盖全部合法输入，用 AIC Matmul 路径处理满足精确 dispatch 条件的紧凑矩阵。两条路径共用同一 Host 校验。
4. 分别验证数值、异步生命周期、内存边界和性能。精度比较使用任务指定的 Netlib CBLAS；性能使用独立样本的逐 kernel 耗时之和，不能把 event 区间或单个 kernel 当作整次 API。

# 详细设计（required）

## 算子分析

### 数学公式与存储

组 `g` 的矩阵索引从之前各组 batch 数的前缀和开始。令 `p[g] = Σ(t<g) groupSize[t]`，第 `j` 个 batch 使用 `Aarray[p[g]+j]`、`Barray[p[g]+j]`、`Carray[p[g]+j]`。逻辑 `C(i,j)` 的列主序偏移为 `i+j×ldc`。

| 转置 | A 元素偏移 | B 元素偏移 |
| --- | --- | --- |
| N | `i+l×lda` | `l+j×ldb` |
| T | `l+i×lda` | `j+l×ldb` |

`A_N`、`A_T`、`B_N`、`B_T`、`C` 的最小前导维分别为 `max(1,m)`、`max(1,k)`、`max(1,k)`、`max(1,n)`、`max(1,m)`。即使当前组 batch 数为零，前缀仍必须正确推进。按任务的显式指针规则，已声明的矩阵元素指针须非空。

### 数据类型与支持形状

输入、输出与累加均为 FP32。通用路径支持所有满足公共接口及任务约束的合法维度和步长，包括非紧凑、尾块与四种转置。Cube 快路径仅在 `alpha=1`、`beta=0`、`m,n,k≥16`、三维均为 16 的倍数且 `lda/ldb/ldc` 为紧凑形式时启用。形状不满足快路径条件时执行通用路径，不降低数值或校验要求。紧凑 8³ NN、`alpha=1,beta=0` 使用独立 AIV 小矩阵路径。

## 算子实现

### Host 侧设计

校验顺序为 handle、组数、全部必需数组、逐组枚举/尺寸/步长/范围、所有实际矩阵指针。无效输入返回现有 ACLBLAS 状态码，且在首个 kernel 入队前结束校验。入队后设备错误由调用方同步 stream 时观察；不在 API 内强制同步。

普通 packet 至多包含同组 74 个 batch 的尺寸、转置、标量及 A/B/C Device 地址。CANN 9.1 `TCubeTiling` 使用 200 字节按值载荷；完整 Cube packet 为 2032 字节，编译期断言它不超过 2048 字节参数预算。Host 在入队前构建全部 packet，避免参数数组生命周期依赖。Cube 的 tiling 在入队前准备，失败返回执行失败，不能静默退回 AIV 并把慢速结果当作 Cube 性能。

相邻的同组 packet 若形状和 tiling 一致，且 A/B/C 各自全部地址与对应最小地址的差可用 32 位无符号整数表示，则合为最多 147 矩阵的 2048 字节偏移 packet；基址保留 64 位，不假定矩阵之间存在 stride。小组融合至多容纳 4 组、32 个矩阵，各组独立保留形状和 tiling，单组 batch 不超过 8、三维不超过 256。融合前用防溢出的区间差检测 C/C、C/A、C/B 重叠，存在依赖即保留原启动次序，不融合。

8³ 小矩阵按每包 80 个指针组处理，输入输出通过 UB 成块搬运。仅在整次调用的 A/B/C 各指针序列均严格等差且增量、终点检查通过时使用 96 字节 stride packet；否则保留独立指针数组路径。设备地址和元数据始终按值传入，不保留调用者 Host 数组地址。

通用路径在 `arch22` 下按输出列及 **512 行**划分 AIV 任务。每核循环处理多个任务，用局部 UB 缓冲累加 FP32。非转置 A 沿列连续搬运；转置 A 用 `DataCopyPad` 按 `lda` 跨步读取，每个 4 字节元素写入一个 32 字节 UB 槽，再按 `offset[r]=r×32` 用 `Gather` 紧凑排列。转置路径额外使用 16 KiB 跨步缓冲和 2 KiB 偏移表；有效行数控制 DMA 块数及 Gather 长度，处理 512 行尾块。字节步长用 64 位计算，超出 DMA 的 32 位步长字段时退回逐元素采集。搬运与计算之间保留管线同步，K 累加顺序与原 `MulAddDst` 语义不变。只写 C 的逻辑 `m×n` 区域。`alpha=0` 或 `k=0` 时不读取 A/B；`beta=0` 时不读取旧 C；B 元素为零时不能跳过乘法，以保留 `Inf×0` 的 NaN 语义。

Cube 路径利用列主序/行主序对偶：`C_col^T = op(B_col)^T × op(A_col)^T`。原始 B 作为行主序左输入、A 作为右输入，转置标志交换但不取反。Host 根据可整除维度、矩形长宽比、batch 数和 AIC 核数选择逻辑 tile，支持 16 倍数的边界，包含 96/192 等非二次幂块。当独立矩阵足以占满核心时，适用的形状由单个 AIC 负责完整矩阵，减少重复设置与输入搬运。Matmul 内部 split 独立于逻辑 tile，并检查 SDK 的规划结果；小块与特殊矩形使用自动 baseK。一个普通 AIC 任务负责一个输出 tile，任务序列跨 batch 分配，kernel 内按核号循环。融合小组则按矩阵分配任务，并使用编译期单矩阵路径，避免给普通 Cube 路径引入动态任务步长。

Cube kernel 用 CANN 9.1.0 的 `Matmul` API、GM ND FP32 输入输出和同步 `IterateAll`，每个 tile 完成后调用 `End`，随后才能复用对象。调用 `AscendC::SetHF32Mode(AscendC::HF32Mode::DISABLE)` 禁止默认 HF32；不通过降精度换取性能。tiling 数据和地址随 packet 按值传入，不创建临时 GM 矩阵。

当 `k≥2048` 且可被 1024 整除时，SDK 路径以 1024 为一段计算 K 维。一个输出块的所有分段仍由同一核心按顺序处理：首段覆盖 C，后续段以 SDK 的 FP32 原子加模式写回，并在段间显式同步。首段不读取旧 C，保持 `beta=0` 对 NaN 初值的语义。该策略不放宽精度标准；长 K 与 Netlib 不同求和次序产生的误差必须继续按原始门限记录和验证。

短 K 的窄矩阵对写回和调度开销更敏感。Host 对符合条件的紧凑矩形使用整矩阵逻辑任务和矩形内部块；相邻且形状、转置、标量一致的小组可以合成普通矩阵 packet，合并前仍检查输出与输入、输出之间的重叠，不能改变存在依赖的执行次序。

在普通非融合单矩阵模板之外，增加一个范围明确的 FP32 TN 专用路径：公共 A 转置、B 不转置，`n=96`、`k∈{16,32}`、`m≥512` 且 `m` 可被 512 整除；仍继承 Cube 入口的紧凑布局与 `alpha=1,beta=0` 限制。每个逻辑任务处理公共 M 维的 512 列片段。一次将 `512×K` 的右输入搬入 L1，复用于三个 32 行输出片段；右操作数按 K 的 8 元素块和 N 的 128 元素块搬入 L0B，四次 `32×128` FP32 MMAD 合成一次 `32×512` Fixpipe 写回。保持关闭 HF32，不转换真实输入的精度。

该专用路径使用 4 KiB L0A、两份 16 KiB L0B 和两份 64 KiB L0C；L1 左、右输入分别为 4 KiB 和 64 KiB 的最大容量。每个 L0B 槽独立跟踪搬运完成与计算释放事件，复用左操作数前等待两个计算槽；写回完成事件保护对应 L0C 槽。这样可让搬运与计算重叠，同时防止覆盖仍在使用的输入或输出。任务按连续矩阵片段分配到核心，保留访问局部性；不满足条件的情况仍走既有 SDK 或 AIV 路径。

### 精度与异常值

测试缓冲区在 ACL 分配地址后保留 512 字节前保护区和原有后保护区，确保默认 `offset_floats=0` 不被测试框架人为改为 32 字节错位；显式 offset 仍逐元素生效，整个前后保护区都参与检查。此前 32 字节保护区的失败原始记录与隔离诊断保留，修正后重新运行完整测试，不拼接不同布局或不同库的通过结果。原始 CSV、采样次数、批量规模和所有数值、性能门限保持不变。

逐组逐矩阵以 Netlib `cblas_sgemm` 作为 golden。有限元素须满足任务的混合容差 `|actual−golden| ≤ 2^-13(1+|golden|)`；逐矩阵及整例 matched ratio 至少 99%。任务书的绝对误差上限写为 **0.01 或 32×ULP**：测试同时保留固定 0.01 诊断和显式 32×ULP 模式，极值输入按任务允许的 ULP 上限判定，并在报告中标明口径；绝不改变混合容差。NaN 分类与 Inf 符号分别比较，不能通过 `isfinite` 排除特殊值。`k=0`、`alpha=0`、`beta=0` 的不读取约束使用毒化缓冲验证。

## 算子约束限制

矩阵指针须指向有效、互不发生非法写入重叠的 Device 存储；Host 指针数组由调用者提供，不能用 Device 指针表冒充。任意非法 Host 地址无法由本接口安全探测。不同 stream 可并发，但共享同一 C 的无序写入由调用者避免。通用 AIV 路径保证功能覆盖，不能假定任意形状均能达到 Cube 性能。

# 可维可测分析

## 精度标准/性能标准

原始 1200 条和补充 306 条逐例运行，无漏测或把资源不足记为 PASS。性能用例由上游 ops-blas GTest 工程运行，先 5 次 warmup，再取 20 次有效样本；用 msprof 原始逐 kernel 数据计算每次 API 的全部 kernel 耗时之和，再比较均值。五个显式硬门限分别为 PF1001 351.3 µs、PF1002 3714 µs、PF1003 37652 µs、PF1004 298380 µs、PF1005 1188440 µs；全部 200 项按 `gpu_ms/0.8` 换算到相同单位比较。ACL event 仅作诊断，不替代任务的逐核计时口径。GTest 的成功测量状态也不代表性能达标：必须另外校验非空 XML、原始逐核数量、预热/有效样本数及逐项门限。

## 验证方法

先跑小尺寸和非方阵四转置，再做原始与补充全量精度、原始性能、GTest、异步参数数组销毁/同一 C 连续调用/双 stream、guard/padding 和 NPU 内存检查。报告应保留 CANN/驱动/硬件、最终 Git HEAD、动态库 SHA-256 与加载路径、原始 profiler CSV、逐例 JSONL、样本均值及截图。最终代码与测试二进制须对应同一提交；任何未运行、超时或失败项目在报告中如实标注。
