# 1. 需求背景（required）

## 1.1 需求来源

本需求来源于“aclblasCsyr2 950 算子开发”社区任务，要求在 Ascend 950PR 上完成单精度复数对称秩 2 更新算子的设计、开发、测试和交付，并按社区流程提交至 ops-blas 开源仓。

算子使用公共 handle 获取执行 stream，以 kernel 直调方式异步执行。接口声明加入统一头文件，禁止定义 950PR 私有平行公共接口。

## 1.2 背景介绍

### 1.2.1 算子功能

aclblasCsyr2 执行：

\[
A\leftarrow A+\alpha xy^T+\alpha yx^T
\]

其中：

- \(\alpha\) 为单精度复数标量；
- \(x\)、\(y\) 为逻辑长度为 n 的复数向量；
- A 为逻辑形状为 \(n\times n\) 的复数对称矩阵；
- \(T\) 表示普通转置，不进行共轭。

接口仅读取并更新 `uplo` 指定的三角区域。另一三角由逻辑对称性隐含，不读取、不补写。

本算子属于 symmetric 更新，不属于 Hermitian 更新，对角元素虚部无需为零。

### 1.2.2 工程现状与接入要求

根据任务书，需在 `include/cann_ops_blas.h` 中新增 `aclblasCsyr2` 声明，并复用 `include/cann_ops_blas_common.h` 中的：

- `aclblasComplex`；
- `aclblasHandle_t`；
- `aclblasFillMode_t`；
- `aclblasStatus_t` 及相关状态码。

实现与同族实数算子归档于 `blas/syr2/arch35/`，测试代码归档于 `test/syr2/csyr2/arch35/`。

本任务采用 kernel 直调，不引入图模式算子注册、广播推导或高维动态 shape 机制。

### 1.2.3 设计重点

本算子的难点主要是以下要求的同时满足：

1. 复数乘加保持普通对称语义。
2. 负步长与列主序地址换算正确。
3. 指定三角之外的矩阵数据不被访问。
4. A 原地更新时不存在重复写入和缓冲覆盖。
5. 三角区域的非均匀列长度能够合理分配到多个核。
6. 小规模启动开销与大规模计算、搬运开销均受控制。
7. 快速返回、异常参数及特殊值符合任务要求。

# 2. 需求分析（required）

## 2.1 需求描述

使用 Ascend C 实现 COMPLEX64 对称秩 2 更新接口，支持：

- 上三角和下三角；
- 任意合法非零正负 `incx`、`incy`；
- `lda≥max(1,n)` 的列主序矩阵；
- A 原地更新；
- `n=0`、`alpha=(0,0)` 快速返回；
- 参数错误检查；
- handle 绑定 stream 的异步执行。

实现须满足任务书规定的精度标准和四组性能指标。

本算子不涉及广播、批处理、三维以上 ND 运算、共轭更新或其他数据类型。

n 是运行时参数，Host 根据本次 n 生成执行参数；不要求实现图模式动态 shape 能力。

x、y 为只读输入，只有 A 原地覆写。

# 3. 详细设计（required）

## 3.1 算子分析

### 3.1.1 数学定义与三角语义

使用 0 基下标：

\[
A'_{ij}=A_{ij}+\alpha x_i y_j+\alpha y_i x_j
\]

上三角有效区域：

\[
\Omega_U=\{(i,j)\mid 0\le i\le j<n\}
\]

下三角有效区域：

\[
\Omega_L=\{(i,j)\mid 0\le j\le i<n\}
\]

有效复数元素总数：

\[
M=\frac{n(n+1)}{2}
\]

由复数乘法交换律：

\[
\alpha x_i y_j+\alpha y_i x_j
=
\alpha x_j y_i+\alpha y_j x_i
\]

更新项在数学上对称。因此指定三角足以表示逻辑结果，无需计算和写回另一三角。

这里的“对称”指逻辑矩阵，不要求调用结束后 A 的两个物理三角互为镜像。

### 3.1.2 复数计算展开

对于：

\[
a=a_r+\mathrm{i}a_i,\qquad b=b_r+\mathrm{i}b_i
\]

普通复数乘法为：

\[
(ab)_r=a_rb_r-a_ib_i
\]

\[
(ab)_i=a_rb_i+a_ib_r
\]

采用按列复用的计算形式。对第 j 列：

\[
t_1=\alpha y_j,\qquad t_2=\alpha x_j
\]

然后计算：

\[
A'_{ij}=A_{ij}+x_it_1+y_it_2
\]

实部：

\[
A'_{ij,r}=A_{ij,r}
+x_{i,r}t_{1,r}-x_{i,i}t_{1,i}
+y_{i,r}t_{2,r}-y_{i,i}t_{2,i}
\]

虚部：

\[
A'_{ij,i}=A_{ij,i}
+x_{i,r}t_{1,i}+x_{i,i}t_{1,r}
+y_{i,r}t_{2,i}+y_{i,i}t_{2,r}
\]

对角元素使用同样的更新过程，不执行共轭或虚部清零。

以上推导说明数学等价关系。实际浮点求值顺序、融合乘加和零值分支须通过 golden 及特殊值用例验证，不假定不同表达式逐位一致。

### 3.1.3 数据类型与布局

| 对象 | 位置 | 类型及属性 |
|---|---|---|
| alpha | Host | 单个 `aclblasComplex`，只读 |
| x、y | Device | `aclblasComplex` 向量，只读 |
| A | Device | `aclblasComplex` 矩阵，原地输入输出 |
| n、incx、incy、lda | Host | int |
| 内部地址及元素计数 | Host/Device | 64 位整数 |

实部、虚部均使用 FLOAT32 计算，不降低到 FLOAT16 或 BFLOAT16。

复数类型的字段、布局和对齐以公共头文件为准。实现时检查实际布局，禁止自行定义不兼容类型或未经确认直接转换指针布局。

### 3.1.4 统一寻址规则

矩阵按列主序存储：

\[
offset_A(i,j)=i+j\cdot lda
\]

逻辑有效行数始终为 n。每列 `[n,lda)` 是 padding，不参与计算。

当 \(n>0\) 时，向量物理长度要求为：

\[
L_x=1+(n-1)|incx|,\qquad
L_y=1+(n-1)|incy|
\]

负步长起点：

\[
s_x=
\begin{cases}
0,&incx>0\\
-(n-1)incx,&incx<0
\end{cases}
\]

\[
s_y=
\begin{cases}
0,&incy>0\\
-(n-1)incy,&incy<0
\end{cases}
\]

逻辑地址：

\[
offset_x(i)=s_x+i\cdot incx
\]

\[
offset_y(i)=s_y+i\cdot incy
\]

例如 `n=4、incx=-2` 时，逻辑 x 的访问偏移为：

```text
6 → 4 → 2 → 0
```

调用方传入分配区域起始指针，由实现完成反向起点换算。

以上偏移单位均为复数元素。地址乘法先提升到 64 位，再计算字节跨度；避免对 32 位 `INT_MIN` 直接求绝对值。

n=0 时不计算向量有效访问范围，不访问 Device 操作数。

## 3.2 算子实现

### 3.2.1 总体方案

采用“Host 参数校验及任务规划 + Device 按列有效行段更新”。

```text
公共接口
  ├─ 参数校验
  ├─ 快速返回判断
  ├─ Device 指针检查
  ├─ 64 位地址跨度计算
  ├─ 分核分块规划
  └─ 使用 handle 中的 stream 异步启动 kernel
       ├─ Init：任务定位和缓冲初始化
       └─ Process
            ├─ CopyIn：搬入合法行段
            ├─ Compute：复数向量乘加
            └─ CopyOut：写回同一合法行段
```

基础实现使用 Ascend C 向量计算。若 CATLASS 中存在适合的调度或搬运组件，可在不改变公共接口和数学语义的前提下复用。

不构造 `xy^T` 或 `yx^T` 完整中间矩阵，不创建完整 A 副本。

### 3.2.2 公共接口

在 `include/cann_ops_blas.h` 中新增：

```cpp
aclblasStatus_t aclblasCsyr2(
    aclblasHandle_t handle,
    aclblasFillMode_t uplo,
    int n,
    const aclblasComplex* alpha,
    const aclblasComplex* x, int incx,
    const aclblasComplex* y, int incy,
    aclblasComplex* A, int lda);
```

| 参数 | 合法条件 | 错误状态 |
|---|---|---|
| handle | 有效句柄 | 空指针返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR` |
| uplo | UPPER 或 LOWER | `ACLBLAS_STATUS_INVALID_ENUM` |
| n | n≥0 | `ACLBLAS_STATUS_INVALID_VALUE` |
| alpha | 非空 Host 指针 | `ACLBLAS_STATUS_INVALID_VALUE` |
| incx、incy | 非零 | `ACLBLAS_STATUS_INVALID_VALUE` |
| lda | ≥max(1,n) | `ACLBLAS_STATUS_INVALID_VALUE` |
| x、y、A | 实际计算时非空 | `ACLBLAS_STATUS_INVALID_VALUE` |

公共接口使用库内枚举名称，不通过硬编码枚举数值实现判断。

### 3.2.3 Host 侧设计

#### 1. 校验与快速返回顺序

拟采用：

```text
1. 检查 handle
2. 检查 uplo
3. 检查 n、incx、incy、lda
4. 检查 alpha 指针
5. n == 0：返回 SUCCESS
6. 读取 Host alpha
7. alpha 实部、虚部均为零：返回 SUCCESS
8. 检查 x、y、A
9. 检查内部索引与字节跨度是否可表示
10. 生成参数并启动 kernel
```

由此保证：

- n=0 时仍检查零步长、非法 lda、非法枚举和空 alpha。
- alpha=0 时允许 x、y、A 为空，因为不会访问它们。
- quick return 不启动 kernel，不更新 A。
- 零值采用精确比较，不能把接近零的 alpha 当作零。
- 含 NaN 的 alpha 不满足零值条件。

对于 alpha=0，直接返回是任务书规定的接口行为，不通过实际计算 `0×Inf` 等表达式实现。

任务书未完全规定多个参数同时非法时的错误优先级。上述顺序作为设计约定，开发时与主仓惯例、配套验收用例核对。

#### 2. 地址与生命周期检查

内部使用 64 位计算：

- 三角元素数量；
- 正负步长起点；
- 向量跨度；
- 矩阵元素及字节偏移；
- 核任务边界。

对转换和乘法进行范围检查，避免整数回绕。

非空检查不能证明 Device 指针有效或分配容量足够，调用方负责提供合法内存。

alpha 由 Host 读取后按值传给 kernel，不将 Host alpha 指针交给 Device 解引用。执行参数采用仓库已有的安全传递机制，不能让异步 kernel 依赖已失效的 Host 栈内存。

#### 3. 基础分核策略

三角矩阵不同列的有效长度不同，不能直接按相同列数均分。

将指定三角按列展开为 M 个有效元素组成的逻辑序列。

上三角前缀：

\[
P_U(j)=\frac{j(j+1)}{2}
\]

下三角前缀：

\[
P_L(j)=jn-\frac{j(j-1)}{2}
\]

对于逻辑编号 q，先找到满足：

\[
P(j)\le q<P(j+1)
\]

的列 j。

行号为：

\[
i=
\begin{cases}
q-P_U(j),&UPPER\\
j+q-P_L(j),&LOWER
\end{cases}
\]

设启用核数为 C，第 c 个核负责：

\[
q_b=\left\lfloor\frac{Mc}{C}\right\rfloor,\qquad
q_e=\left\lfloor\frac{M(c+1)}{C}\right\rfloor
\]

区间 `[q_b,q_e)` 互不重叠并覆盖全部有效元素，核间元素数差异不超过 1。

kernel 仅在首任务定位时执行前缀查找，之后按列顺序推进，避免逐元素求逆。首列定位采用整数二分等可验证方法。

该方案允许一列由不同核处理互不相交的行段，不需要原子操作。

#### 4. 核数与分块选择

核数由平台可用核数和最小单核有效工作量共同决定，不机械追求满核。

- 小 n：减少核数，控制启动和调度开销。
- 大 n：利用足够核数，提高并行度。
- 通用步长：单元素搬运成本较高，单独评估最优配置。

tile 长度 T 由实际 UB 预算决定。所有参数以目标平台查询和实测为依据，不写死未经验证的 UB 容量或核数。

#### 5. UB 预算与缓冲生命周期

基础版本按单缓冲实现，建议缓冲规划如下：

| 缓冲 | 内容 | 生命周期 |
|---|---|---|
| x 行段 | 当前 tile 的 x | 搬入至计算结束 |
| y 行段 | 当前 tile 的 y | 搬入至计算结束 |
| A 行段 | 旧 A，计算后可复用为输出 | 搬入至搬出结束 |
| 列标量 | x_j、y_j、t1、t2 | 当前列处理期间 |
| 临时空间 | 实虚部整理和乘加中间结果 | 对应计算阶段 |

基础 x、y、A 三组复数行段约占 `24T` 字节，但这不是最终 UB 用量，仍需计入布局整理、计算临时空间、队列和对齐开销。

设固定开销为 \(S_f\)，实际每元素预算为 \(S_e\)，则：

\[
T=
alignDown\left(
\left\lfloor\frac{UB_{\mathrm{available}}-S_f}{S_e}\right\rfloor,
L
\right)
\]

L 为已验证的计算或搬运粒度。

在双缓冲版本中，重新计算实际峰值占用，不简单沿用单缓冲 T。缓冲复用须根据生命周期确定，不能同时占用同一空间保存仍然需要的数据。

#### 6. 执行参数与分支

执行参数至少包括：

| 字段 | 作用 |
|---|---|
| n、lda | 矩阵尺寸与前导维 |
| incx、incy | 有符号步长 |
| startX、startY | 向量起点 |
| alphaReal、alphaImag | 标量值 |
| totalElements | 三角元素数 |
| blockDim、tileLength | 核数与 tile 长度 |
| uplo | 三角模式 |
| variant | 连续或通用路径 |

逻辑路径划分为：

- UPPER，incx=incy=1；
- LOWER，incx=incy=1；
- UPPER，其他合法步长；
- LOWER，其他合法步长。

具体使用模板实例化、分支参数或工程已有 tiling key 方式，由仓库构建机制决定，不额外引入图模式流程。

### 3.2.4 Kernel 侧设计

#### 1. Init

每个核：

1. 读取参数并计算自身任务区间。
2. 定位首列和首行。
3. 初始化 GM 视图、UB 缓冲及队列。
4. 准备 alpha。
5. 根据三角模式和步长选择处理路径。

#### 2. 有效区间确定

第 j 列合法行区间：

\[
I_j=
\begin{cases}
[0,j+1),&UPPER\\
[j,n),&LOWER
\end{cases}
\]

将当前核在该列中的任务范围记为 \(K_j\)，候选 tile 为 `[r,r+T)`，则：

\[
V_j=I_j\cap K_j\cap[r,r+T)
\]

交集为空时不搬运、不计算；非空时只处理该区间。

先确定合法地址，再执行搬运。不能先读取完整矩形块，再通过计算掩码屏蔽未指定三角。

#### 3. CopyIn

搬入：

- 有效行段对应的 x、y；
- 当前列的 x_j、y_j；
- A 的有效行段。

对于 inc=1，使用目标平台支持的连续搬运。

对于一般步长，先保证按逻辑地址正确读取，可采用已验证的 gather 或逐元素读取。之后再评估小固定步长、负连续步长的优化路径。

若采用“连续搬入后在 UB 内反序”优化负步长，必须证明所读区间完整位于合法向量存储范围。

#### 4. Compute

1. 按公共复数布局获取实部、虚部。
2. 计算当前列 t1、t2。
3. 执行 FLOAT32 复数乘加。
4. 将结果整理为公共复数布局。

同一列分为多个 tile 时，复用 t1、t2。

UB 内可以对尾块补齐，但无效 lane 不得影响有效输出。

#### 5. CopyOut

结果写回原位置：

\[
A+i_{\mathrm{begin}}+j\cdot lda
\]

写回长度严格等于当前有效元素数量。

不得写入另一三角、padding、其他核区间或尾块补齐区域。

对于非对齐搬运，除检查逻辑长度外，还应确认底层实际访问及写事务范围。计算掩码不能代替 GM 访存边界控制。

#### 6. 流水

基础版本完成正确性验证后，再引入搬入、计算、搬出重叠。

同步关系必须满足：

```text
搬入完成 → 计算开始
计算完成 → 搬出开始
搬出完成 → 输出缓冲可复用
```

双缓冲不改变每个输出元素的归属，不引入多个核对同一 A 元素的累加。

### 3.2.5 原地更新与并行安全

每个输出只依赖：

\[
A_{ij}^{old},x_i,x_j,y_i,y_j,\alpha
\]

不依赖其他 A 元素。因此，在 A 与 x/y 不重叠的条件下，可直接原地更新，无需完整矩阵副本。

必须保持：

1. **唯一写入者**：每个有效 A 元素仅属于一个核。
2. **先读后写**：写回前已读取该元素旧值。
3. **输入只读**：x、y 不被修改。
4. **缓冲完整**：异步搬出结束前不复用相应缓冲。

x 与 y 指向同一只读向量不会产生写入冲突。

任务书未明确 A 与 x/y 的重叠别名行为。基础方案不承诺支持该重叠，最终约束需与库规范核对并在 README 中说明。不能在未备份输入的情况下宣称任意别名均安全。

### 3.2.6 特殊值与优化边界

有限值数学等价不保证 NaN/Inf 下行为相同。

重点验证：

- alpha 含 NaN/Inf；
- x、y 实部或虚部含 NaN/Inf；
- `0×Inf`；
- x_j、y_j 同时为零；
- 正负零；
- 大值溢出及极小值。

golden 中是否保留参考实现的零列跳过逻辑，应与配套测试工程一致。

`alpha=(1,0)` 专用化、重新结合乘法或融合乘加都属于待验证优化。尤其不能仅因数学上乘 1 不变，就认定省略复数乘法不会改变特殊值结果。

本任务不要求 bit-exact，但任何优化都必须通过普通精度及特殊值回归。

### 3.2.7 性能优化规划

| 优化项 | 目标 | 启用条件 |
|---|---|---|
| 连续步长路径 | 减少地址计算和离散搬运 | 与通用路径功能一致 |
| 三角元素均分 | 降低核间负载差异 | 任务覆盖及边界验证通过 |
| 列标量复用 | 减少重复复数乘法 | 精度和特殊值通过 |
| UB 缓冲复用 | 增大有效 tile | 生命周期无冲突 |
| 双缓冲 | 重叠搬运和计算 | UB 足够且实测有收益 |
| 小规模核数调优 | 降低固定开销 | 小 n 与基准 case 实测 |
| 列组处理 | 跨列复用 x/y 行段 | 在基础方案上单独验证 |

列组处理属于后续优化候选。首版优先实现可证明正确的按列行段方案，不同时引入复杂的二维调度和多套未验证路径。

矩阵 A 的必要逻辑读写量约为：

\[
B_A=2\times8\times M=8n(n+1)\text{ bytes}
\]

该值仅包含 A 的一次读取和一次写回，不包含向量重复读取、参数传输和事务放大。是否受带宽限制需以 profiling 为依据。

## 3.4 算子约束限制

1. 仅支持 COMPLEX64。
2. alpha 为 Host 标量指针，x/y/A 为 Device 指针。
3. A 采用列主序，仅引用指定三角。
4. 支持非零正负步长和合法 lda。
5. 不广播、不返回视图、不支持高维批处理。
6. 仅 A 原地更新，x/y 只读。
7. 接口内部不执行 stream 同步。
8. 调用方负责 Device 内存容量和生命周期。
9. 不保证 bit-exact。
10. 实际最大可处理规格受地址表示范围、可用内存和平台执行能力限制，不额外虚构固定 n 上限。

# 4. 可维可测分析

## 4.1 精度标准/性能标准

### 4.1.1 精度标准

golden 使用测试工程按任务书指定语义实现的复数参考版本，不依赖 cblas 复数 syr2 接口。

只对有效三角比较，实部、虚部分别统计。

| 指标 | 要求 |
|---|---|
| rtol | \(2^{-10}\) |
| atol | \(2^{-16}\) |
| required_matched_ratio | 0.99 |
| max_abs_error_limit | 按任务书规定的 `1e-2 或 32×ULP` 执行 |

有限值逐元素条件：

\[
|actual-golden|
\le atol+rtol|golden|
\]

实部、虚部分别满足匹配率和最大误差要求后，用例才通过。

`1e-2 或 32×ULP` 的选择规则、ULP 定义和适用范围以配套检查器及验收解释为准，不自行取更宽阈值。

NaN/Inf 先进行类别匹配，再按测试工程规则检查符号等属性。不得将 NaN 差值直接计入普通误差统计，也不得静默忽略类别不匹配。

### 4.1.2 性能标准

| case | uplo | n | alpha | incx | incy | lda | 平均耗时上限 |
|---|---|---:|---|---:|---:|---:|---:|
| 1 | UPPER | 512 | (1,0) | 1 | 1 | 512 | 11 μs |
| 2 | LOWER | 1024 | (1,0) | 1 | 1 | 1024 | 12.17 μs |
| 3 | UPPER | 2048 | (1,0) | 1 | 1 | 2048 | 24.89 μs |
| 4 | LOWER | 4096 | (1,0) | 1 | 1 | 4096 | 131.97 μs |

测试应先 warmup，再有效采样超过 50 次，建议固定 100 次。

计时必须覆盖实际 Device 执行，不能只测 Host 异步入队时间。是否包含 Host 接口开销须与标杆口径一致。

A 每次调用都会累加更新。精度测试应恢复初始 A；性能测试的数据复用和恢复方式按配套指导固定，避免溢出，也避免将不属于标杆范围的数据恢复操作计入耗时。

报告记录环境、warmup 次数、采样次数、平均耗时和计时边界。以上数值为验收目标，不是已完成的性能结果。

## 4.2 Golden 与基础测试

golden 使用独立标量实现，不复制 NPU 的分核和 tile 代码，以减少同源错误。

基本流程：

```text
保留 A_initial
按负步长规则解释 x、y

对每一列 j：
    确定 uplo 合法行范围
    按参考求值规则计算复数更新
    仅修改 A_golden 的有效三角
```

普通有限值以配套 golden 为唯一验收标杆。高精度辅助计算仅用于误差定位，不替代规定标杆。

增加可手算用例：

- n=1，验证对角虚部；
- n=2，验证上下三角；
- 纯实输入，验证虚部不被无故引入；
- 纯虚输入，验证普通乘法的符号；
- x=y，验证两项更新均存在；
- 负步长与 padding 同时出现。

## 4.3 用例覆盖

| 类别 | 覆盖内容 | 目的 |
|---|---|---|
| 空与最小规模 | n=0、1、2、3 | no-op、对角和基本公式 |
| 小质数 | 5、7、17、31 | 不规则分核 |
| 幂及邻域 | 63/64/65、127/128/129 等 | 对齐与尾块 |
| tile 边界 | T−1、T、T+1 附近的任务长度 | 缓冲边界 |
| 大规模 | 512、1024、2048、4096 | 精度与性能 |
| 三角 | UPPER、LOWER | 三角语义 |
| 步长 | ±1、±2、±3 的组合 | 反向和跨步 |
| lda | n、n+1、n+7 等 | padding |
| alpha | 零、一、纯实、纯虚、一般复数、大值 | 标量边界 |
| 特殊值 | NaN、±Inf、±0、极小值 | 数值行为 |
| 合法地址偏移 | 满足类型要求的不同元素偏移 | 非对齐搬运 |

随机输入按任务书要求使用均匀分布和正态分布各 50%，实部、虚部独立生成，并记录随机种子。

### 4.3.1 参数与快速返回

| 条件 | 预期 |
|---|---|
| handle 为空 | HANDLE_IS_NULLPTR |
| uplo 非法 | INVALID_ENUM |
| n<0 | INVALID_VALUE |
| incx=0 或 incy=0 | INVALID_VALUE |
| lda<max(1,n) | INVALID_VALUE |
| alpha 为空 | INVALID_VALUE |
| 实际计算时 x/y/A 为空 | INVALID_VALUE |
| n=0，必检参数合法 | SUCCESS，无 Device 访问 |

### 4.3.2 内存访问与原地安全

在以下区域设置哨兵并保留初始副本：

- 未指定三角；
- lda padding；
- 向量步长间隙；
- 分配范围内的前后保护区。

验证：

1. 有效三角满足 golden。
2. 未指定三角和 padding 逐字节不变。
3. x、y 全部保持不变。
4. 保护区未被修改。
5. no-op 时整个 A 不变。

哨兵只能发现错误写入，不能证明未发生多余读取。还须进行搬运范围审查，并在工具可用时开展 Device 内存访问检查。

## 4.4 异步和资源测试

- 同一 stream 中安排输入准备、算子和结果回传，同步后验证。
- 检查接口内没有显式 stream 同步。
- 使用独立 handle、stream 和缓冲验证并发隔离。
- 重复调用后检查资源释放及内存增长。
- Device 运行错误沿用库内机制处理，不通过强制同步改变接口语义。

## 4.5 内存分析

任务书未设独立内存上限，但自测报告需包含内存数据。

基础设计：

- 无完整输出矩阵副本；
- 无两个外积中间矩阵；
- 无 \(O(n^2)\) 辅助 Device 空间；
- UB 用量由 tile 和缓冲规划确定；
- 原则上不新增用户级 Device workspace。

分别报告算子临时空间和测试框架的 golden、备份矩阵占用，避免混淆。

## 4.6 关键风险与闭环

| 风险 | 控制措施 | 验证证据 |

# 5. 工程价值与实施计划

## 5.1 工程价值

本方案不提出新的数学算法，其价值在于将标准复数秩 2 更新实现为可验证、可优化的 Ascend C 算子。

主要特点：

1. 仅处理有效三角，避免完整矩阵中间结果。
2. 将步长、列主序和三角边界统一到明确的地址模型。
3. 通过有效元素分核缓解三角列长度不均。
4. 利用每个 A 元素独立更新的性质实现无原子原地写回。
5. 以正确性基线承接连续搬运、列标量复用和流水优化。

性能收益以实测证明，不将标准 BLAS 语义本身包装为算法创新。
